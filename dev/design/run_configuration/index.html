Run configuration

Every Aeolus run is described by one self-contained TOML file (schema version 2, ONE-b #451; the target is the single model of One model). The file is checked against the model's schema, resolved into a typed RunConfig, and written back in canonical form to the run folder's run.toml. A run folder can therefore always be run again from its own run.toml. This page is the guide. The API is on Run configuration (API), every option is in the generated option reference, and the NetCDF input files are specified in Static input driver and Dynamic input driver.

TOML layout

There is one model and no run types: aeolus run config.toml runs it. A file sets options section by section; a key that is not set takes the schema default. A key the schema does not know is an error, and so is a value of the wrong type or outside its range; every problem is reported together, naming the key and the file it came from.

schema_version = 2
dynamic_driver = "input/lindenberg_era5_dynamic.nc"   # the domain's input drivers (optional)

[run]
name = "dcbl"
seed = 1

[timestep]             # run level: one scheme steps every domain
scheme = "rk3"

[time]                 # run level: one clock for every domain
dt = "adaptive"        # or a fixed step in seconds
cfl = 0.5
dt_max = 10.0
duration = 3600.0      # or nsteps, with duration = "none"

[grid]                 # per domain
size = [32, 32, 32]
extent = [3200.0, 3200.0, 1600.0]

[sgs]                  # an exclusive slot: one section, a selector key
model = "smagorinsky"  # the provider; the section holds its options only
c_s = 0.17

[surface_theta_flux]   # a component is enabled by its own section
bottom = 0.24

A bare config is a minimal dry LES: an empty file runs 32³ cells on 3.2 km × 3.2 km × 1.6 km, periodic in x and y between free-slip walls, the Boussinesq core with buoyancy on θ₀ = 300 K, Smagorinsky SGS and adaptive SSP-RK3 steps for one hour. Every other component is off until its section enables it.

The sections:

levelsections
run[run], [time], [timestep], [output], [checks], [checkpoint], [fftw], [logging]
per domain[grid], [core], [dynamics] (the core's parameters), [boundaries], [initial], and one section per component, generated from its schema: [advection], [sgs], [coriolis], [sponge], [surface_theta_flux]; the EX-d couplings [forcing], [surface], [microphysics], [tracer], [particles], [obstacles] (one component today, split in ONE-e); the urban site's [urban], one section per urban slot and one per additive urban component (ONE-e #454, ONE-m #476)
the domain itselfid, static_driver, dynamic_driver (top level for one domain, else in each [[domain]] block); a nested domain's parent, origin, refinement, feedback (ONE-f, #455)

[checks] takes one key per check the core and the enabled components publish (ONE-d, #453). The component interface and the stage pipeline are on Components.

Exclusive slots: one section, a selector key (ONE-m, #476). A slot that holds exactly one of several providers is one section whose selector key names the provider: [core] model, [timestep] scheme, [sgs] model, [surface] model, [microphysics] scheme, [advection] scheme, and on an urban site also [pressure] solver, [momentum_advection] scheme, [chemistry] scheme and the rest of its slots. The section holds the chosen provider's options and nothing else: a key of another provider is an error that names the providers that have it, and the resolved config shows the provider with every option it has. There are no enabled pairs to keep consistent: an additive component (on or off, any number of them) keeps its enabled key. A slot section the model and the urban site share offers each domain the providers of its kind ([sgs] model = "tke" is the model's TKE closure on a model domain, the site's on an urban site). A selector set at a higher level that names another provider replaces the provider: --set sgs.model="vreman" on a file with [sgs] model = "tke" drops the file's [sgs] options, and the vreman closure starts from its defaults and the other overrides (a [domain.sgs] block's selector does the same for its domain, and with from Julia). Naming the provider the file names changes nothing.

Conventions: keys are ASCII snake_case; values are SI and durations are in seconds; "none" stands for nothing (TOML has no null); a path is relative to the file that sets it and is stored absolute. Environment variables only fill a few defaults (AEOLUS_LOG, AEOLUS_FFTW_PLANNER, AEOLUS_FFTW_THREADS, AEOLUS_ALLOW_UNCOMMITTED). The resolved value is always written, so the environment never changes a replay.

Domains

A config without [[domain]] has one domain, "main". Several domains are [[domain]] blocks; the run-level per-domain sections apply to every domain, and a block's [domain.<section>] tables replace keys for its domain:

[time]
dt = 1.0                   # a nest takes a fixed step

[sgs]
model = "vreman"           # every domain …

[grid]
size = [8, 8, 8]           # the parent: 3200 × 3200 × 1600 m, Δ = 400 × 400 × 200 m

[[domain]]
id = "outer"

[[domain]]
id = "inner"
parent = "outer"
origin = [1200.0, 1200.0]  # its lower-left corner in the parent; it stands on the ground
refinement = [8, 8, 8]     # Δ = 50 × 50 × 25 m: grid.size = extent / parent spacing × refinement
feedback = "two_way"       # the default; "one_way" per child
static_driver = "input/inner_static.nc"
  [domain.sgs]
  model = "amd"            # … but this one (another provider: the run level's
                           # [sgs] options, if any were set, are dropped)
  [domain.grid]
  extent = [400.0, 400.0, 200.0]

The resolved config, and so run.toml, lists every domain with every option of every component ([[domain]] then [domain.grid], [domain.sgs], …), so a run is fully described by its record. A problem in a block is reported under domain[i].<section>.<key>; the cross-field checks run on each domain, and the checks of the domain graph once.

Nesting by domains (ONE-f, #455)

Several domains are a nest, and one aeolus run steps them all. The first domain is the root; every later one names an earlier domain as its parent, its origin (x, y) in it and its refinement per axis. A nested domain stands on its parent's ground: its lateral faces are nest faces fed by the parent (periodic along an axis it spans entirely if the parent is periodic there), its top a nest face below the parent's top. Each domain is built as a single domain would be — its own [initial], components and couplings — and runs its own stage pipeline. One step is one root step of dt; a child subcycles max(refinement) substeps per step of its parent, recursively (Berger & Oliger 1984), so several levels and siblings work as one (#328). feedback is per child: two_way, the self-nesting default (anterpolation onto the covered parent cells, interface flux correction, Berger–Colella refluxing, re-projection of the parent; see Two-way nesting), or one_way, where the parent never sees the child. The coupling is Components.nested_model, over Nesting.NestHierarchy.

A run writes one output file per domain (output.nc for the root, output_<id>.nc for the others), evaluates each published check on every domain (the value is the worst, each domain's under its id in results.toml; the reference comparisons are the root's), and a checkpoint holds the whole nest, so a resumed run continues bit for bit.

The nest engine (NEST-p2, #482; nested time coupling):

  • Steps. time.dt fixed: each child takes max(refinement) substeps per step of its parent. time.dt = "adaptive": the root takes its own stability limit, each child the smallest whole number of equal substeps that keeps it stable, chosen every window, and a failed step retries the window (half the root step, or twice the failing child's substeps).
  • Budgets. [nesting] budget_exchange = "exchange_term" (the default): every domain closes its own budgets, with one nest-exchange term per quantity, (:nest_feedback, :nest_exchange) — what crossed a child's nest faces, and in a parent its children's two-way feedback. "off": a nest measures no budgets (no budget_* output, no closure check).
  • Cores. Every domain runs the Boussinesq or the anelastic core, mixed freely, two-way included (a conservative density conversion in the boundary data and the feedback). An anelastic nested domain needs [timestep] scheme = "euler", and one nested in an anelastic parent the same dynamics.theta0 and g.
  • Exchanged fields (the PALM rule): qv, the Kessler ql and qr, and the tracer exist in a nested domain exactly when they exist in its parent; the check names both domains. (A child could carry an extra field only with its own dynamic driver giving its boundary values; a nested domain has no dynamic driver yet.)
  • Inflow turbulence. A nested domain's [inflow_turbulence] enabled = true puts synthetic turbulence on its lateral nest faces, with its parent's resolved statistics (statistics = "parent_resolved"); two-way, the feedback skips the generator's inflow band.
  • Subgrid model. It may differ per domain ([domain.sgs]); the nest passes resolved fields only (a TKE field on one side only is not exchanged: the child's e is zero-gradient at its nest faces). A child that refines its parent horizontally by 3 or more without [inflow_turbulence] is warned about when the model is built.

What a nested model does not do yet, each refused by the configuration with its reason: stretched grids (but in the parent of urban sites), a model child's dynamic_driver, and the EX-d couplings ([forcing], [surface], [microphysics], [tracer], [particles], [obstacles]) in a child, whose fields have no nest faces.

An urban site in a nest (NEST-p3, #483) is a [[domain]] block with [domain.urban] enabled = true, nested in a domain of the model's core (its parent; not the root, with no children of its own) at its origin and refinement. Its parent's [grid] origin is minus the site's origin (the site stands at its own corner), its [domain.nesting] is enabled with parent_driver = "aeolus", and its feedback is the block's. The run-level [time]: dt and nsteps are the site's (nsteps × dt the run), cfl and dt_max the root's adaptive step. The site keeps its own field set (qv and TKE from the parent, its other tracers zero on inflow), not the PALM rule of the model's domains. In a nest each domain writes the [output] variables it has, one file per domain. The Berlin configs are written this way (examples/urban/berlin_*.toml).

The enabled components of a domain are validated before anything is built: at most one per exclusive slot (:advection, :sgs, :microphysics, :radiation, :surface), an :advection provider, and each component's requires and incompatible; every problem names the sections involved.

Legacy cases

No legacy case is left: the last, urban_parent (the nest parent of an urban site alone), went with NEST-p3 (#483), where the parent became a [[domain]] of the model; the urban site itself is the model's since ONE-e #454. The seven validation run types of the former Aeolus.RunDrivers are gone (ONE-l, #475): advection, cbl, shear_layer and flat_plate are configurations of the model (with the components [kinematic_flow], [sgs] model = "tke", [inflow_statistics] and [fringe]), and inflow_fetch and obstacle_channel (channel cases) and sgs_decay (the filtered-DNS study) were dropped, their harnesses kept as test fixtures. The SBL cases are configurations of the model since ONE-g (#456); the channel, single-column and DNS a-priori validation cases are gone (maintainer decisions of 2026-10-09); the Kessler box of the kernel demos is a configuration of the model, and the column and dns_decay run types, which were Julia files under examples/, are gone (ONE-i #458). The mechanism stays ([run] legacy = "<case>", a schema registered in src/) with no case registered.

No inheritance

There is no extends: every file is self-contained (maintainer decision of 2026-10-09). Variants of a case (Berlin winter, smoke, the Mitte sample, the parent) are complete files of their own; a change that must reach several variants is made in each file, and the tests state the differences between variants explicitly (test/config_berlin.jl: winter differs from summer in exactly 11 keys). A file with extends, a file of schema_version = 1 and a [run] driver key are refused with what changed.

--set

On the command line an override is --set dotted.key=<TOML value>. Strings are quoted, arrays are TOML arrays:

julia --project -m Aeolus run examples/taylor_green_vortex/taylor_green_vortex.toml --set grid.size=[16,16,16]
julia --project -m Aeolus run examples/urban/berlin_smoke.toml --set sgs.model='"smagorinsky"'   # another provider
julia --project -m Aeolus check my_case.toml --set time.nsteps=10 --set time.duration='"none"'   # validate only
julia --project -m Aeolus resolve my_case.toml                            # print the canonical TOML
julia --project -m Aeolus options sgs                                     # the model's option reference, one section
julia --project -m Aeolus options sbl stepper                             # a legacy case's

An override of a per-domain section's key applies to every domain, over the [[domain]] blocks. bin/aeolus is the same command on any Julia version (-m needs Julia ≥ 1.12). Exit code 0 is success, 1 a failed run, 2 a usage or configuration error raised before anything is written, 3 a failed required check of [checks] (ONE-d, #453). A file with a [sweep] table expands into one run per member; --member k picks one.

The Julia escape hatch and replayable

Scripts can build or change a config in Julia:

using Aeolus
cfg  = load_run_config("examples/dry_convective_bl/dry_convective_bl.toml"; overrides = ["grid.size=[32,32,32]"])
cfg2 = with(cfg, "run.seed" => 7)          # a new, validated config
res  = run_config(cfg2)                    # what `aeolus run` does

with accepts any value the schema accepts, and also values TOML cannot hold, such as a Julia function for a Berlin parent's surface flux. Such a run is recorded with replayable = false and the keys in nonreplayable_keys. load_run_config refuses to replay it, because its run.toml does not describe it completely. Everything that has a TOML form (constants, series, tables, named kinds) should use it.

Running from run.toml versus --resume

commandrun IDstarts from
aeolus run <folder>/run.tomla new run and a new folderthe start, with the old run's [config]
aeolus run <folder> --resumethe same run, a new session in its run.tomlthe folder's newest checkpoint

A replay from run.toml is bit-identical to the original under the ESTIMATE FFTW planner and the same thread count (#245). --resume refuses --set, because a resumed run must be the run it continues. For the model (the SBL configurations among its runs) and the urban legacy case a run interrupted and resumed is bitwise equal to the uninterrupted run (test/config_roundtrip.jl (removed)).

The [inputs] hash check

Every input file option (a Path: a static or dynamic driver, a case table) is recorded in run.toml under [inputs] with its fnv1a64 content hash; a domain's under domain.<id>.<key>. Replaying or resuming a run whose input files have changed since is refused, naming each changed file, unless allow_changed_inputs = true is passed to load_run_config. A replay therefore cannot silently read different data.

The preprocessors

Geometry and forcing come from NetCDF-4 driver files with Aeolus's own schemas. They are written by the companion package AeolusPrep.jl (ONE-h, #457), which reads the run's grid from its config; Aeolus keeps the readers and the schemas:

# in an AeolusPrep.jl checkout
julia --project -m AeolusPrep static <aeolus>/examples/urban/berlin_summer.toml --source data/berlin/alexanderplatz_real.osm
# the parent-made driver of an offline nest is model output
julia --project -m Aeolus run examples/urban/berlin_smoke.toml --set 'urban.child_boundaries="child.nc"'

The static driver (terrain, buildings, land use, trees, surfaces) is written from OpenStreetMap or GeoJSON and read from the domain's static_driver (an urban site's ground too, ONE-e #454). The dynamic driver (initial profiles, large-scale forcing, surface series, boundary planes) is written from a sounding, a case table or ERA5, or by a recording parent run, and is read from the domain's dynamic_driver (the model; its large-scale tables by [large_scale_forcing], its surface series by [surface] model = "most") or [initial] dynamic (urban). Their variables, dimensions, units and attributes are listed on the static and dynamic pages; the API is Input drivers.

Where the shipped configs live

An example is a case directory, examples/<case>/ (ONE-i #458):

examples/<case>/<case>.toml        the configuration (and its variants, <case>_<variant>.toml)
examples/<case>/input/*.nc         its static and dynamic drivers (made by AeolusPrep.jl)
examples/<case>/data/*.csv         reference data its [checks.reference] compares against
examples/<case>/*.jl               optional scripts that read a finished run folder
examples/viz/                      the plotting library those scripts share

A case family that shares its drivers and data is one directory: examples/sbl/ (GABLS1–4 and CASES-99), examples/dns_vs_les/ (the DNS and one LES per SGS model), examples/urban/ (the Berlin variants).

An example is these files only. test/examples_enforcement.jl holds the rule with no exemptions: it parses every .jl under examples/ and fails on any call that builds or steps a model (a function of Aeolus whose name ends in !, a constructor of a grid, field, simulation, domain, model, component, nest, solver or run type, run_config, Aeolus.main, Config.build, register_driver!) or includes a file outside examples/; and it fails on a file out of the layout above (a configs/ directory, a TOML file below a case's top level, a driver outside input/, data outside data/). The forbidden names are read from the package, so a new entry point is caught without editing the test.

Each shipped config carries a [test] table with its smoke size:

[test]
overrides = ["grid.size=[16,16,16]", "time.duration=\"none\"", "time.nsteps=10"]
member = "lasd_32x32x32"     # sweeps only: the member replayed (default: the first)

The loader ignores [test] (it checks only its shape): it is not part of the resolved config, of run.toml or of the config hash. test/config_roundtrip.jl (removed) finds every examples/<case>/*.toml and checks that it validates, that resolving it is a fixed point, that every key it uses is in the option reference, and that its smoke run replays bit for bit from its run.toml. A new config without a [test] table fails that suite with a message naming the file.

The design follows PALM's split between a namelist and preprocessed driver files, without aiming at PALM compatibility. What it adds is that the config is the record: the canonical run.toml replays the run bit for bit, and the option reference is generated from the same schema that validates the file.
