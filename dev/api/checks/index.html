Checks

Aeolus.Checks (ONE-d, #453) runs the model's checks inside the run. The core and the components publish named checks. A run's [checks] section enables them, each required or advisory and with a tolerance. The run writes the results to output/results.toml, and aeolus run exits with code 3 when a required check failed. Without [checks] nothing is evaluated and no results.toml is written.

A check measures one error value ≥ 0 and passes when the value is at most its tolerance:

checkpublished byvaluedefault tolerance
finitethe corenon-finite interior values of u, v, w, p, θ (qv, νt, κt) at the end0
energy_closurethe core's energy budget(|closure| + |unattributed|) / elapsed, W m⁻²1e-6
water_closurethe water budgetthe same, kg m⁻² s⁻¹1e-12
momentum_closurethe momentum budgetthe larger of x and y, kg m⁻¹ s⁻²1e-9
tracer_closurethe tracer budgetthe same, kg m⁻² s⁻¹ per unit mixing ratio1e-12
<name>a component (checks(c), check_names(C))its ownits own
reference_<quantity>[checks.reference]distance outside the reference band, or the RMS of a profile0

A closure check measures its budget: enabling it turns the budget on (Budgets), just as selecting the budget_* output does, with the same requirements (water_closure needs moisture, and so on). The "unattributed" part is the change that no stage entry booked: (:core, :unattributed) and (:output, :between_steps). A closure check therefore also fails when something changed the air outside the pipeline. The budgets measure the state without changing it: a run with checks steps the same state as the run without them.

[checks]
finite = { required = true }
energy_closure = { required = true }                 # default tolerance 1e-6 W m-2
momentum_closure = { required = false, tolerance = 1e-12 }
reference_file = "data/gabls1_reference.csv"         # CSV or NetCDF, hashed under [inputs]

[checks.reference.u_star]                            # a quantity of the reference file
required = true
variable = "u_star"                                  # a time-series (scalar) or profile output variable
window = [28800.0, 32400.0]                          # the mean over hours 8-9; default: the end of the run
tolerance = 0.0                                      # widens the band [low, high]

The reference file is a CSV quantity table (quantity,low,high or quantity,value, as in examples/sbl/data/*_reference.csv), a CSV of profiles (z,<quantity>,…), or a NetCDF file (read_reference). The compared variable comes from the domain's output catalogue (Output), whether or not [output] writes it. A scalar fails outside [low − tolerance, high + tolerance]. A profile fails when the RMS of model − reference at the reference heights inside the column exceeds the tolerance.

results.toml holds passed (every required check passed), the lists failed_required and failed_advisory, and one table per check under [checks.<name>]: required, evaluated, passed, value, tolerance, units, description, and the check's own numbers (the closure, unattributed change and storage per second; the model value and the band; the window and its step count). An advisory failure only warns.

A run that blows up records the sanity check finite as failed (with the error, step and time). It does so even when only other checks were enabled, and records every other check as not evaluated. It exits with 1, like any failed run. A resumed run continues the window means: they are checkpointed with the run.

Aeolus.Checks — Module
Aeolus.Checks

The in-model checks (ONE-d, #453; the design is docs/src/design/single_model.md, "Budgets and checks"). The model and its components publish named checks (Check); the configuration's [checks] section enables them, each as required or advisory and with a tolerance; the run evaluates them and writes the results to results.toml (results_table); a failed required check stops aeolus run with a non-zero exit code (ChecksFailed).

A check measures one non-negative error value and passes when value ≤ tolerance:

checkvalue
a budget closurethe closure and the unattributed change, per second of the run
finite (the sanity check)the number of non-finite values in the state
a reference comparison (reference_check)the distance outside the reference band, or the RMS difference of a profile

A reference comparison reads a reference data file (CSV or NetCDF, read_reference) named in the configuration, so a comparison with an intercomparison ensemble (GABLS-style) is configuration plus data, not code.

The checks a component publishes are Components.checks(c); the core's (the sanity check and the budget closures) are Components.core_checks. This module holds what is common to all of them: the check, its settings and evaluation, the reference data and the results table.

Aeolus.Checks.Check — Type
Check(name; doc, units = "1", tolerance, evaluate, sample = nothing, acc = nothing)

One published check:

  • name — its key in [checks] and in results.toml;
  • doc — what it measures, in words (written to results.toml);
  • units — the units of its value and tolerance;
  • tolerance — its default tolerance ([checks] name = {tolerance} overrides it);
  • evaluate(acc) -> (value, info) — the error measure value ≥ 0 at the end of the run, and a Dict{String,Any} of numbers worth recording (the model's value, the reference band, …);
  • sample(acc, t, dt) — called after every step (stage 13, :checks) with the time t at its end and its length dt, for a check that accumulates over the run (nothing: none);
  • acc — that accumulator (checkpointed with the run, so a resumed run continues it).

It passes when value ≤ tolerance; a NaN value fails.

Aeolus.Checks.CheckResult — Type
CheckResult

The outcome of one enabled check: name, required, evaluated (false when the run stopped before the end), passed, value, tolerance, units, doc and info (the check's recorded numbers, or the reason it was not evaluated).

Aeolus.Checks.CheckRunner — Type
CheckRunner(checks, settings)

The enabled checks of a run: each of checks that settings (a Dict{String,CheckSetting}, from [checks]) names, with its setting. An ArgumentError names a setting no check publishes. Its accumulators are checkpointed with the run (checkpoint_state).

Aeolus.Checks.CheckSetting — Type
CheckSetting(required, tolerance)

What [checks] sets for one check: required (a failure stops the run with a non-zero exit code) or advisory (a failure warns), and the tolerance (nothing: the check's default).

Aeolus.Checks.ChecksFailed — Type
ChecksFailed(failed)

The error a run ends with when a required check failed (aeolus run exits with code 3): failed are the CheckResults. The run's fields and results.toml are complete; the session is recorded as failed.

Aeolus.Checks.ReferenceProfile — Type
ReferenceProfile(z, values)

A vertical reference profile: values at the heights z (m, increasing).

Aeolus.Checks.ReferenceValue — Type
ReferenceValue(low, high)

A scalar reference: the band [low, high] (an ensemble range; low == high for a single value).

Aeolus.Checks.WindowMean — Type
WindowMean(window)

The accumulator of a reference comparison: the step-length-weighted sum of the compared value over the steps that end in window = (t0, t1) (nothing: none, the value at the end is compared), the summed length and the number of steps.

Aeolus.Checks.advisory_failures — Method

The advisory checks of results that failed.

Aeolus.Checks.check_entry_problems — Method
check_entry_problems(tbl) -> Vector{String}

The problems of one [checks] entry name = {required, tolerance}: an empty table is "off"; otherwise required (a Bool) must be given and tolerance, if given, is a number ≥ 0.

Aeolus.Checks.enabled_checks — Method
enabled_checks(tbl) -> Dict{String,CheckSetting}

The checks a resolved [checks] table enables: every entry that is a non-empty table ({required, tolerance}), and every reference comparison (reference, named reference_<quantity>).

Aeolus.Checks.evaluate_checks — Method
evaluate_checks(r::CheckRunner) -> Vector{CheckResult}

Evaluate every enabled check at the end of the run. A check whose evaluation throws fails, with the error as its info["error"].

Aeolus.Checks.read_reference — Method
read_reference(path) -> Dict{String,Union{ReferenceValue,ReferenceProfile}}

The reference data of a file, by quantity name. Two formats:

  • CSV (# lines are comments; the first other line is the header): a header with a quantity column and low and high columns (or one value column) gives a ReferenceValue per row (other columns, such as unit and source, are ignored; the format of examples/sbl/data/*_reference.csv); a header whose first column is z (or z_m, heights in m) gives a ReferenceProfile per other column, named by its (lowercased) header;
  • NetCDF (.nc): a variable with one value (or attributes low and high) is a ReferenceValue; a one-dimensional variable along z, with the coordinate variable z, a ReferenceProfile.
Aeolus.Checks.reference_check — Method
reference_check(quantity, ref, value_of; variable, z = nothing, units = "", window = nothing,
                tolerance = 0.0) -> Check

The reference comparison reference_<quantity> of the model's variable against the reference data ref of quantity (read_reference). value_of() is the model's current value: a number (compared with a ReferenceValue) or a profile at the heights z (compared with a ReferenceProfile). With window = (t0, t1) the compared value is its time mean over the steps that end in the window (weighted by their length); otherwise the value at the end of the run. The error measure:

  • a scalar: the distance outside the band, max(low − x, x − high, 0);
  • a profile: the RMS of model − reference at the reference heights in the model's column (the model profile interpolated linearly; a NaN reference value is a gap in the data and is skipped, and so is a height where the model profile is undefined, NaN, such as above the virtual towers; a profile undefined everywhere fails).

tolerance (in the variable's units) is the default; it fails when no step ended in the window.

Aeolus.Checks.reference_entry_problems — Method
reference_entry_problems(tbl) -> Vector{String}

The problems of one reference comparison [checks.reference.<quantity>]: those of check_entry_problems and its own keys, variable (a string: the output-catalogue variable compared; default the quantity's name) and window = [t0, t1] (s, t0 < t1: the time mean over the steps ending in it; default the value at the end of the run). Unlike a published check, a reference comparison is always on: required is mandatory.

Aeolus.Checks.required_failures — Method

The required checks of results that failed.

Aeolus.Checks.results_table — Method
results_table(results) -> Dict{String,Any}

The results.toml table of a run's check results: passed (every required check passed), failed_required and failed_advisory (names), and per check [checks.<name>] with required, evaluated, passed, value, tolerance, units, description and its recorded numbers.

Aeolus.Checks.sample_checks! — Method
sample_checks!(r::CheckRunner, t, dt)

Let every enabled check that accumulates over the run sample the step that ended at t and was dt long (stage 13, :checks).

Aeolus.Checks.stopped_checks — Method
stopped_checks(r::CheckRunner, err; step, t) -> Vector{CheckResult}

The results of a run that stopped with the error err at step, time t: the sanity check finite fails (a blown-up run records it whether or not it was enabled; required) with the error as its reason, every other enabled check is recorded as not evaluated, and failed.
