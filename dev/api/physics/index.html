NetCDF output

NetCDF is read and written with NCDatasets (#310). Aeolus.NCIO holds the output policy: NetCDF-4, deflate with shuffle, chunks of one horizontal level and one record, streamed records, CF time units. Read any file with NCDataset(path) and index it (ds["theta"][:, :, k, r]; Julia index order, the reverse of ncdump).

Migration from NetCDFIO (removed in #310):

beforenow

nc_defdim!(nc, "x", n), nc_defdim!(nc, "time", nothing)ds.dim["x"] = n, ds.dim["time"] = Inf
nc_defvar!(nc, name, T, dims; attributes)same (now compressed and chunked)
nc_endef!(nc)not needed
nc_write!(nc, name, A)ds[name][:, :] = A
nc_append_record!(nc, data)same
nc_close!(nc)close(ds)
nc_write_fields(path, coords, fields)removed (unused)

nc_read_record(f, name, r)ds[name][:, :, :, r]
nc_nrecords(f), nc_varnames(f), nc_attributes(f)ds.dim["time"], keys(ds), ds.attrib

Files written before #310 are NetCDF-3 (CDF-2) and still read. Their time units, "seconds since simulation start", are not CF: NCDatasets warns and returns the raw seconds. New files carry the case start in UTC ("seconds since 2019-06-29 04:00:00") and ds["time"][:] decodes to DateTime; the raw seconds are ds["time"].var[:].

Aeolus.NCIO — Module
NCIO

NetCDF output policy for Aeolus, on top of NCDatasets.jl (#310).

NCDatasets is the one reader and writer of NetCDF in the package: it reads NetCDF-3 (CDF-1, CDF-2, CDF-5) and NetCDF-4/HDF5, and writes NetCDF-4. This module adds only what is Aeolus policy, so that every writer in the package and its examples produces the same kind of file:

  • nc_create: a NetCDF-4 file with the CF Conventions global attribute;
  • nc_defvar!: lossless deflate (level NC_DEFLATE_LEVEL) with the byte shuffle filter, and chunks of one horizontal level and one record (nc_chunksizes), so reading one level or one time of a 3-D field decompresses only that;
  • nc_append_record!: stream one record along the unlimited dimension, checked to be complete, and flush it to disk;
  • cf_time_units: CF time units from a reference date.

Reading needs nothing from here: open a file with NCDataset(path) (re-exported) and index it, ds["theta"][:, :, :, r]. Dimensions are in Julia index order, the reverse of the order ncdump prints.

Why NetCDF-4

NetCDF-4 is the format of ERA5, ICON, COSMO and PALM, and of the tools that read them (xarray, CDO, NCO, ncview, Paraview). Over NetCDF-3 it adds compression and chunking, and drops the 4 GiB limit per variable record. The package wrote NetCDF-3 with an in-package writer (NetCDFIO, removed in #310) because NCDatasets did not build on the development machine at the time; it does now (NCDatasets 0.14.15, NixOS, Julia 1.13.1).

Crash safety

An HDF5 file left open by a crashed writer can be unreadable. nc_append_record! therefore calls sync after every record, so the file on disk always holds every completed record.

References

  • Rew, R., Hartnett, E., Caron, J. (2006): NetCDF-4: software implementing an enhanced data model for the geosciences, 22nd Int. Conf. on IIPS, AMS.
  • CF Metadata Conventions v1.8.
Aeolus.NCIO.NC_DEFLATE_LEVEL — Constant
NC_DEFLATE_LEVEL = 4

Default zlib deflate level of nc_defvar!. Level 4 is the usual choice for model output (the CDO and xarray examples use 1 to 5): higher levels cost write time for a percent or two of size.

Aeolus.NCIO._MIN_CHUNK — Constant

Target number of values per chunk along the unlimited dimension of a small record variable.

Aeolus.NCIO.cf_time_units — Method
cf_time_units(t0::DateTime) -> String

CF time units "seconds since yyyy-mm-dd HH:MM:SS" for a time axis that starts at t0 (UTC: CF reads a reference time without a zone as UTC). NCDataset decodes a variable with these units to DateTime; its raw seconds are ds["time"].var[:].

Aeolus.NCIO.nc_append_record! — Method
nc_append_record!(ds, data::AbstractDict)

Append one record along the unlimited dimension. data maps variable name (String or Symbol) to the array of one record: every variable over the unlimited dimension must be present, with that dimension last; a variable over the unlimited dimension alone takes a one-element vector. The whole record is checked before any of it is written. Values are written raw (no CF time or scale encoding: pass the numbers the units attribute describes), then the file is flushed with sync.

Aeolus.NCIO.nc_chunksizes — Method
nc_chunksizes(ds, dims) -> Vector{Int}

The default chunk shape of a variable over dims (Julia index order): the full extent of the first two (horizontal) dimensions, and 1 along every further dimension (levels) and along the unlimited dimension, so a chunk is one horizontal level of one record. A variable whose slab is smaller than 4096 values (a profile, a time series) takes enough records per chunk to reach 4096, since a chunk per value would cost more in index than in data. Non-record variables are one chunk.

Aeolus.NCIO.nc_create — Method
nc_create(path; attributes = Dict()) -> NCDataset

Create (or overwrite) path as a NetCDF-4 file open for writing, with the global attribute Conventions = "CF-1.8" followed by attributes. Define dimensions with ds.dim["x"] = Nx (Inf for the unlimited record dimension), variables with nc_defvar!, and close(ds) at the end.

Aeolus.NCIO.nc_defvar! — Method
nc_defvar!(ds, name, T, dims; attributes = Dict(),
           deflatelevel = NC_DEFLATE_LEVEL, shuffle = true,
           chunksizes = nc_chunksizes(ds, dims))

Define variable name of element type T over dims (in Julia index order, the order of the array written), compressed with deflate and the shuffle filter and chunked as nc_chunksizes. attributes are the CF attributes (units, long_name, axis, coordinates, …). Returns the variable. deflatelevel = 0 stores it uncompressed.

Microphysics

Aeolus.Microphysics.KESSLER_N0 — Constant
KESSLER_N0 = 8.0e6

Intercept N₀ (m⁻⁴) of the Marshall & Palmer (1948) exponential drop size distribution N(D) = N₀ e^{-λD} that Kessler (1969) assumes for rain. It closes the single-moment scheme: given q_r the whole drop spectrum, hence its fall-speed spectrum, is fixed.

Aeolus.Microphysics.apply_kessler_step! — Method
apply_kessler_step!(qv, ql, qr, dt; k_auto=1e-3, ql_c=1e-3, k_acc=2.2,
                    Vt=:spectrum, ρ_air=1.225, N0=KESSLER_N0, mesh=qv.mesh)

Advance one microphysics substep in-place. Handles autoconversion, accretion, and 1st-order upwind sedimentation of qr.

  • k_auto [1/s] — autoconversion rate.
  • ql_c [kg/kg] — cloud-water threshold above which autoconversion activates.
  • k_acc [1/s] — accretion rate.
  • Vt — rain fall speed. :spectrum (default, Phase 44): each cell falls at the mass-weighted speed of its own Marshall-Palmer drop spectrum (kessler_fall_speed), recomputed every sub-step, with the conservative, Courant-sub-stepped column scheme P3Microphysics.p3_sediment!; nothing leaves except through the bottom face. A number (m/s, ≥ 0) instead selects the legacy single fall speed, bit-identical to the pre-Phase-44 kernel (which caps the Courant number at 0.5 and so slows rain whose Vt Δt/Δz exceeds it).
  • ρ_air [kg/m³] — air density, a scalar or one value per model level (bottom first); used only by Vt = :spectrum.
  • N0 [m⁻⁴] — Marshall-Palmer intercept, see KESSLER_N0.

qv is untouched here — evaporation of falling rain is a follow-up.

Aeolus.Microphysics.kessler_fall_speed — Function
kessler_fall_speed(q_r, ρ_air = 1.225; N0 = KESSLER_N0) -> V_M  (m s⁻¹)

Mass-weighted terminal fall speed of Kessler rain: the Marshall-Palmer spectrum of kessler_rain_number integrated against the drop terminal velocity by P3Microphysics.p3_rain_sedimentation_velocities (Beard 1976 / Atlas et al. 1973 drop speeds from Superdroplet.terminal_velocity, Foote & du Toit density correction). It rises with q_r because heavier rain has larger drops: 3.77 m s⁻¹ at 0.1 g m⁻³, 5.66 m s⁻¹ at 1 g m⁻³ and 7.48 m s⁻¹ at 10 g m⁻³ of rain at sea level, within 10 % of (and at 1-3 g m⁻³ within 0.2 % of) the Klemp & Wilhelmson (1978) fit V = 36.34 (ρ q_r [g cm⁻³])^0.1346 derived from the same Marshall-Palmer spectrum (see the tests).

Aeolus.Microphysics.kessler_rain_number — Method
kessler_rain_number(q_r, ρ_air; N0 = KESSLER_N0) -> N_r  (kg⁻¹)

Rain drop number per kg of air implied by the Marshall-Palmer spectrum N(D) = N₀ e^{-λD} holding rain mass q_r (kg kg⁻¹) in air of density ρ_air (kg m⁻³):

ρ_air q_r = (π/6) ρ_w N₀ Γ(4) / λ⁴  ⇒  λ = (π ρ_w N₀ / (ρ_air q_r))^{1/4},
N_r = N₀ / (λ ρ_air).

ρ_w is Superdroplet.DEFAULT_MICRO.ρ_water. Zero for q_r ≤ 0. This turns single-moment Kessler rain into the (q_r, N_r) pair the P3 rain functions take, so the fall-speed spectrum is P3's, not a new law.

Reference: Marshall & Palmer (1948, J. Meteor. 5, 165-166); Kessler (1969, Meteor. Monogr. 10).

Immersed boundaries

Aeolus.IBM.SolidMask — Type
SolidMask(mesh; init = zeros)

A Boolean mask on mesh (cell centers) marking solid cells. true = solid, false = fluid. Storage matches a Field(CellCenter, mesh) (interior + halos) so it can be inspected with interior_view on the underlying mask array.

Aeolus.IBM.add_ibm_penalty! — Method
add_ibm_penalty!(sim, sm; τ = 1e-3)

Angot-style volume penalization: add -(mask / τ) · u to each momentum tendency (sim.tu, sim.tv, sim.tw). With small τ the tendency strongly drives u → 0 in solid cells while leaving fluid cells alone; the pressure projection then resolves the flow around the obstacle in one consistent solve.

Call inside a custom step just after computing tendencies and before the predictor step, so the penalty is included in the flow the projection sees.

Aeolus.IBM.apply_solid_mask! — Method
apply_solid_mask!(sim, sm)

Zero the face-centered velocity components on any face that touches a solid cell (either side of the face is masked). Applied after the pressure projection every time step.

Aeolus.IBM.first_level_cells — Method
first_level_cells(sm::SolidMask; bottom = true) -> Array{Bool,3}

The fluid cells at the first grid level above a surface: those with a solid cell directly below, and (with bottom = true) every fluid cell of level 1 (above the domain floor). Interior-sized. The TKE closure multiplies its dissipation coefficient there by Moeng's (1984) factor 3.9.

Aeolus.IBM.implicit_ibm_correction! — Method
implicit_ibm_correction!(sim, sm; τ = 0.0, dt = 0.0)

Volume-penalization applied implicitly to the intermediate velocity after the predictor step. For each face touching a solid cell:

u* ← u* / (1 + Δt/τ)

Unlike add_ibm_penalty! — which is explicit and requires Δt / τ < 1 for stability — this form is unconditionally stable for any positive τ. τ = 0 treats the penalty as infinite and just zeros the face velocity (u* ← 0). Best combined with step!(sim, dt; post_predictor! = (s, Δt) -> implicit_ibm_correction!(s, sm; dt = Δt)).

Aeolus.IBM.mark_solid! — Method
mark_solid!(sm, predicate)

Set sm.mask[i,j,k] = true for every interior cell whose center satisfies predicate(x, y, z).

Aeolus.IBM.wall_distance — Method
wall_distance(sm::SolidMask; bottom = true, top = false,
              periodic = (true, true, false), bcs = nothing,
              maxsweeps = 50) -> Array{T,3}

Distance (m) from the centre of every interior cell to the nearest solid surface, an interior-sized Nx × Ny × Nz array (0 in solid cells). The surfaces are the faces of the solid cells of sm (each solid cell is the box it occupies) and, with bottom = true (top = true), the domain floor (lid).

A vector distance transform (Danielsson 1980), the chamfer-type raster-sweep algorithm that propagates the nearest surface point rather than a scalar distance, with no dependencies:

  1. Seed. A fluid cell next to a surface stores the displacement to the exact nearest point of it: the centre clamped into the box of each solid neighbour among its 26 (Δz/2 above a floor or roof, Δx/2 beside a wall, √(Δx² + Δz²)/2 off a roof edge), or the foot point on the floor (lid) for level 1 (Nz).
  2. Propagate. Forward and backward raster sweeps over the 26-neighbourhood offer each cell its neighbours' nearest points, r(c) ← r(n) + (x_n − x_c), and keep the closest, until nothing changes (periodic wraps the lateral neighbours across the seam; a velocity boundary-condition set bcs, when given, decides instead, through BoundaryConditions.neighbor_index: an open or wall face has no neighbour beyond it, N-open-d #262).

The distance is exact for a plane surface aligned with the grid (d = Δz/2 + (k−1)Δz above a floor) and next to every surface; elsewhere the raster propagation can miss the true nearest point only in rare configurations (Danielsson 1980). Around a cube on a 2:2:1 grid it equals the Euclidean distance to the box to round-off (test/era6_tke.jl); a plain chamfer transform with the 26 step lengths overestimated it there by up to 24 %.

The TKE closure (PrognosticSGS.TKEClosure) caps its mixing length at κ · wall_distance; every Era VI closure that needs a wall distance takes it from here.

References: Danielsson, P.-E. (1980), Euclidean distance mapping, Comput. Graph. Image Process. 14, 227; Borgefors, G. (1986), Distance transformations in digital images, Comput. Vision Graph. Image Process. 34, 344.

Domain decomposition

Aeolus.Parallel.AbstractPartition — Type
AbstractPartition

Base type for describing how a mesh is split across MPI ranks. Concrete subtypes:

  • SerialPartition — no distribution, single rank.
  • PencilPartition — 2D pencil split over x and y.

Serial execution should always work: everything in the operator layer is written such that a SerialPartition is a no-op in exchange_halos_distributed!.

Aeolus.Parallel.PencilPartition — Type
PencilPartition(nx, ny)

Two-dimensional MPI pencil layout with nx ranks along x and ny ranks along y. z is local to every rank.

Constructing a PencilPartition does not by itself require MPI — the actual MPI.Comm and neighbour lookup are populated by the future AeolusMPI extension when MPI.jl is loaded. Without MPI, using a PencilPartition in a running simulation will trip a helpful error rather than segfault.

Aeolus.Parallel.SerialPartition — Type

Serial (single-rank) partition. The default.

Aeolus.Parallel.exchange_halos_distributed! — Method
exchange_halos_distributed!(field, partition)

Exchange the halo layers of field between MPI neighbours according to partition. On SerialPartition this is a no-op — halo fill via the per-field BCs already handles the periodic/wall wrap.

On PencilPartition (MPI extension), the interior slabs on the split axes are packed into send buffers and mirrored into the receiver's halo cells via non-blocking Isend/Irecv.

Compute backends

Aeolus.Backends.SERIAL_THRESHOLD — Constant

Default serial threshold of CPUBackend: a launch covering fewer points runs serially even when Julia has several threads, because the task start-up (a few µs per thread) costs more than the work. 32 768 points is a 32×32×32 block; measured in ka_port.md.

Aeolus.Backends.AbstractBackend — Type
AbstractBackend

Base type for the compute-backend selector. Subtypes:

  • CPUBackend — default; Base.Array storage, kernels run by KernelAbstractions on the CPU's Julia threads (or serially).
  • GPUBackend — stub until Phase 81.
Aeolus.Backends.CPUBackend — Type
CPUBackend(; serial = false, threshold = SERIAL_THRESHOLD)

The CPU backend: Base.Array storage, kernels launched through KernelAbstractions.CPU() on Julia's threads (julia -t N).

  • serial = true runs every launch on the calling task, in the historical for k, for j, for i loop order. Pointwise kernels give the same bits as the threaded path (each point is computed by the same body); reductions use the same canonical order on both paths, so serial = true is the in-process reference of the thread-invariance tests.
  • threshold: launches over fewer points run serially (task start-up dominates below it).

With one Julia thread every launch runs serially as well, so a -t 1 run executes exactly the loops it executed before the port.

Aeolus.Backends.GPUBackend — Type
GPUBackend(kind = :cuda)

GPU backend stub (Phase 81). kind is one of :cuda, :rocm, :oneapi, :metal. Using it trips a helpful error rather than silently falling back to the CPU.

Aeolus.Backends.allocate — Method
allocate(backend, T, dims) -> array

A zero-filled array of element type T and size dims on backend (Array{T} for the CPU).

Aeolus.Backends.apply_transform! — Method
apply_transform!(backend, out, plan, in) -> out

Execute the precomputed transform plan (an FFTW plan on the CPU) from in into out. The spectral pressure solvers call every transform through this method, from host orchestration between kernel launches and never inside a kernel, so that Phase 81 can give the GPU backend its own transform library (cuFFT) behind the same call.

On the CPUBackend it is mul!(out, plan, in). The plan carries its own thread count (FFTW's, set at planning time through the FFTW policy; init_threads! makes it Threads.nthreads()). FFTW's threaded plans split the independent 1-D transforms of a multidimensional transform between the threads without changing any of them, so the result is identical at every thread count under a deterministic planner (measured in docs/src/design/ka_port.md).

Aeolus.Backends.backend — Method
backend(x) -> AbstractBackend

The backend that owns array x (for a Field, its storage): for a host Array, the default backend if that is a CPU backend, else CPUBackend().

Aeolus.Backends.backend_name — Function

backend_name(backend): :cpu, or the GPU kind (:cuda, :rocm, …).

Aeolus.Backends.column_partials — Method
column_partials([backend,] A, ranges::NTuple{3,UnitRange{Int}}) -> Matrix

P[a, b] = A[i, j, k1] + A[i, j, k1+1] + … (ascending k) for the column i = ranges[1][a], j = ranges[2][b]: one partial per column, computed by one work item, so thread-invariant. ordered_sum(P) is then a canonical total in column order (a different order, hence different bits, from interior_sum).

Aeolus.Backends.default_backend — Method
default_backend() -> AbstractBackend

The backend new fields are allocated on and plain arrays are launched on: CPUBackend() unless set_default_backend! (or init_threads!, or with_backend) changed it.

Aeolus.Backends.init_threads! — Function
init_threads!(backend = default_backend(); fftw_threads = nothing,
              blas_threads = nothing) -> NamedTuple

Prepare the process to run on backend: makes it the default_backend and sets the thread counts of the two libraries that thread on their own. Call it before the simulation (and so its FFT plans) is built: an FFTW plan keeps the thread count it was made with.

  • BLAS is pinned to one thread when Julia runs threaded (Threads.nthreads() > 1; maintainer decision on #294): BLAS threads would compete with the kernel tasks, and a threaded BLAS may split a reduction differently at different thread counts. blas_threads overrides.
  • FFTW runs on Threads.nthreads() threads (KA-h, #298; maintainer decision on #291): FFTW's threaded plans split the independent 1-D transforms between threads without changing any of them, so a solve gives the same bits at every thread count under a deterministic planner (ESTIMATE, or imported wisdom); measured in docs/src/design/kaport.md. A count chosen explicitly wins: `fftwthreads = nhere, or before the callAEOLUSFFTWTHREADS,Aeolus.Operators.setfftwpolicy!(threads = n)or a namelist's[fftw] threads. The count is set through that FFTW policy, sofftw_policy()` and the checkpoint record report it.

Returns (backend, julia_threads, blas_threads, fftw_threads).

Aeolus.Backends.interior_all_finite — Method
interior_all_finite([backend,] A, ranges::NTuple{3,UnitRange{Int}}) -> Bool

true iff every value of A over the storage ranges is finite (no NaN, no ±Inf). Thread-invariant.

Aeolus.Backends.interior_dot — Method
interior_dot([backend,] A, B, ranges::NTuple{3,UnitRange{Int}}) -> Σ A·B

Thread-invariant inner product over the storage ranges, in the canonical order of plane_partials!.

Aeolus.Backends.interior_max — Method
interior_max([backend,] A, ranges::NTuple{3,UnitRange{Int}}) -> maximum

Maximum of A over the storage ranges, NaN-propagating: any NaN in the region gives NaN (as Base.maximum), so a blown-up field is never hidden by a finite maximum. Per plane in the canonical lane order, then combined in ascending k: thread-invariant. -Inf for an empty region.

Aeolus.Backends.interior_sum — Method
interior_sum([backend,] A, ranges::NTuple{3,UnitRange{Int}}) -> sum

Thread-invariant sum of A over the storage ranges: the ordered_sum of the plane_partials!. Its bits differ from sum(view(A, ranges...)) (pairwise) — the canonical order is a named one-time change for the call sites the port moves to it.

Aeolus.Backends.launch! — Function
launch!(backend, body!, ranges::NTuple{N,UnitRange{Int}}, args...)

Run body!(i, j, k, args...) (N = 3), body!(i, j, args...) (N = 2) or body!(n, args...) (N = 1) once for every index of ranges, which are storage indices (halos included), so any region is a launch: the interior (Hx+1:Hx+Nx, …), a face range with one extra point (Hx+1:Hx+Nx+1), an extended range into the halo (Hx:i2), a halo shell, a 2-D (i, j) surface range, or a 1-D range of ids (surface elements, particles).

The contract (docs/src/design/ka_port.md):

  • the body writes only to point (i, j, k) of its outputs and reads its inputs anywhere — no two points write the same location, no point reads what another point writes in the same launch (use a scratch array);
  • the body carries its own @inbounds (or is @propagate_inbounds);
  • results must not depend on the order points run in. Pointwise bodies then give the same bits serially and threaded; reductions go through plane_partials! and friends, never through a shared accumulator.

Serial (serial = true, one Julia thread, or fewer points than the backend's threshold): the loops run on the calling task in the historical order for k, for j, for i. Threaded: a KernelAbstractions kernel whose work item is one i-row, in workgroups of four rows; a launch too small for every thread gets fewer, larger workgroups (at least 16 384 points per task).

Aeolus.Backends.launch_weighted! — Method
launch_weighted!(backend, weight, body!, ranges, args...)

launch! for a body that covers weight points per index: a column kernel launched over (i, j) (or over rows j) that loops over weight levels itself, such as the tridiagonal solve of StretchedPoissonSolver (KA-h, #298). The backend's serial threshold and its points-per-task rule then count weight × length(ranges) points, the work actually done, instead of the number of indices. Same contract and same serial order as launch!; weight = 1 is launch!.

Aeolus.Backends.ordered_sum — Method
ordered_sum(v) -> sum

v[1] + v[2] + … + v[end], strictly left to right (foldl). The fixed combination of the partial sums from plane_partials! or column_partials; zero(eltype(v)) for an empty v.

Aeolus.Backends.plane_map! — Method
plane_map!(partials, [backend,] plane, ranges::NTuple{3,UnitRange{Int}}, args...)
    -> partials

partials[c] = plane(k, ranges[1], ranges[2], args...) for k = ranges[3][c]: a function of a whole plane, one work item per plane (the plane parallelism of plane_reduce!), so every partial is computed by one task in the plane function's own fixed loop order and partials is identical at every thread count and with serial = true. Combine with ordered_sum.

For the reductions where the eight-lane order of plane_reduce! costs more than it gains: a fused update that touches few points and calls an expensive function there (apply_wet_deposition!: exp in the raining cells only), where keeping eight lanes live across the call is slower than one running sum in cell order (measured in ka_port.md). The plane function carries its own @inbounds and may write any point of its own plane k, and only of it.

Aeolus.Backends.plane_mean! — Method
plane_mean!(profile, [backend,] A, ranges::NTuple{3,UnitRange{Int}}) -> profile

Horizontal-mean profile: profile[c] = the canonical plane sum of level k = ranges[3][c] (plane_partials!) divided by the number of points of the plane. Thread-invariant.

Aeolus.Backends.plane_partials! — Method
plane_partials!(partials, [backend,] f, ranges::NTuple{3,UnitRange{Int}}, arrays...)
    -> partials

partials[c] = the canonical sum, over the plane k = ranges[3][c] and the points (i, j) of ranges[1] × ranges[2], of f(arrays[1][i,j,k], …). The order of the additions is fixed (eight lanes per row, rows in order; see kaport.md), and each plane is summed by one work item, so partials is identical at every thread count and with serial = true. Combine with [`orderedsum](@ref) for a total, or divide by the plane size for a horizontal-mean profile ([plane_mean!`](@ref)).

Aeolus.Backends.plane_reduce! — Method
plane_reduce!(partials, [backend,] body, ranges::NTuple{3,UnitRange{Int}}, args...)
    -> partials

The canonical plane sums of an indexed body: partials[c] = the sum, over the plane k = ranges[3][c] and the points (i, j) of ranges[1] × ranges[2], of body(i, j, k, args...), added in the order of plane_partials! (eight lanes per row, rows in order, one work item per plane). Thread-invariant, and the same bits as plane_partials! for a body that returns f(A[i,j,k], …).

The body follows the launch! contract: it may read its inputs anywhere (a stencil: a strain rate, a centred w), may write point (i, j, k) of its outputs (an update fused with the sum of what it changed: a chemistry step returning its production), carries its own @inbounds, and takes everything it reads as an argument. A per-level coefficient is an argument indexed by k.

A body that returns an NTuple of N numbers sums every component in the same canonical order: pass partials as an NTuple of N vectors (plane_reduce!((S, n), b, body, r, …) for a masked sum and its count).

ranges are whatever indices the body takes — storage indices of halo-padded arrays, or axes(view) of interior-sized arrays.

Aeolus.Backends.range_map! — Method
range_map!(backend, f, out, ranges, args...) -> out

out[I] = f(args[1][I], args[2][I], …) for every storage index I of ranges (3-D or 2-D); an argument that is not an array (a number) is passed as is. A pointwise kernel: bit-identical serially and threaded. Fields.interior_map! is the field-level form.

Aeolus.Backends.range_max — Method
range_max([backend,] body, ranges::NTuple{3,UnitRange{Int}}, args...) -> maximum

The maximum of the indexed body(i, j, k, args...) (indexed as in plane_reduce!) over ranges, NaN-propagating like interior_max: any NaN gives NaN. max is exact and commutative, so the result equals any serial maximum of the same values (a CFL rate, max |∇·u|, a speed cap).

Unlike a plane_reduce! body, a range_max body must only read: it is evaluated once per point, but a fused update belongs in plane_reduce!. The result type is the inferred (floating-point) return type of body, Float64 when inference gives no concrete real type; an empty region gives -Inf.

Radiation (Era I scaffold)

Superseded for production use by the Era III stack; retained because it is cheap and adequate for idealised cases. SlabLand is the first implementer of the Era V surface interface (SurfaceExchange): surface_temperature is the SurfaceExchange generic, and step_surface! computes its own Monin–Obukhov fluxes.

Aeolus.Radiation.SlabLand — Type
SlabLand(; T = 290.0, C_s = 2e5, albedo = 0.2, emissivity = 1.0,
           z0m = 0.1, z0h = z0m / 10, β = 0.0)

A single-layer soil-temperature reservoir governed by

C_s dT/dt = (1 - α) SW↓ + ε LW↓ - ε σT⁴ - H - LE

where α is the albedo, ε the emissivity, σ the Stefan-Boltzmann constant (RadiationCore.STEFAN_BOLTZMANN), H the upward sensible heat flux to the atmosphere (typically ρ cₚ w'θ'|₀), LE the latent heat flux, and C_s [J/m²/K] the effective heat capacity.

SlabLand is the first implementer of the Era V SurfaceExchange.AbstractSurface interface. Its moisture availability is the constant β (moisture_availability(land) = β): β = 0, the default, is a dry surface (LE = 0); β = 1 an open-water surface with an unlimited supply (the slab carries no water store, so LE never runs out). It has roughness lengths z0m, z0h (= z0q), so step_surface!(land, forcing, dt) computes its own Monin–Obukhov fluxes. step_land! remains for callers that supply H themselves.

This is deliberately the simplest useful LSM — vegetation, soil moisture, and multi-layer conduction are future refinements.

Aeolus.Radiation.apply_radiative_cooling! — Method
apply_radiative_cooling!(tθ, rate; solid = nothing)

Add a radiative-cooling tendency to tθ at every interior cell.

  • rate::Real — uniform tendency (K/s) applied everywhere.
  • rate::AbstractVector — length-Nz vertical profile (K/s at each interior z-level, from bottom up).

Signs: positive rate = warming, negative = cooling. The typical free-atmosphere clear-sky longwave cooling in ABL LES is ≈ -2 K/day = -2.3e-5 K/s.

solid (optional) is a Bool array in the halo layout of the mesh (the .mask of an IBM.SolidMask): cells marked true are left unchanged. A radiative heating rate is a property of the air; applied inside an immersed building it would put energy into cells that are not air, from where the scalar diffusion carries it back into the fluid next to the walls.

Aeolus.Radiation.step_land! — Method
step_land!(land, sw_in, lw_in, sensible_flux, dt)

Advance land.T by dt seconds under the balance above with a prescribed sensible_flux and no latent flux. Positive sensible_flux means heat flows from the surface to the air (cooling the ground).

Aeolus.SurfaceExchange.step_surface! — Method
step_surface!(land::SlabLand, forcing, dt; Q_extra = 0, kwargs...) -> SurfaceFluxes

Forward-Euler step of the slab under SurfaceExchange.turbulent_fluxes (Monin–Obukhov H, LE from the current skin temperature): C_s ΔT = G dt with G = Rn - H - LE + Q_extra.

Q_extra (W m⁻², positive into the surface) is energy the surface receives besides radiation and the turbulent fluxes, e.g. the latent heat of dew formed on it, or (negative) sunlight transmitted through glazing into a building. It is part of the returned G, the energy the slab stored. kwargs go to turbulent_fluxes.

Aeolus.Chemistry.apply_dry_deposition! — Method
apply_dry_deposition!(c, v_d, dt; dz, k = 1) -> removed

Remove dry-deposited mass from the lowest air cell of every column of the 3-D array c (or Field): $c ← c\, e^{-v_d Δt/Δz}$, the exact solution of $dc/dt = -v_d c/Δz$ over the step (surface flux $F = -v_d c$). v_d is a scalar or an (Nx, Ny) matrix (m s⁻¹); k is the level of the first air cell, a scalar or an (Nx, Ny) integer matrix (roof-aware). Returns $Σ_{ij} Δc\,Δz$ (units of c × m), the column-integrated amount removed summed over columns.

Aeolus.Chemistry.apply_linear_chemistry! — Method
apply_linear_chemistry!(tc, c, τ; source = nothing)

Add first-order chemical relaxation -c/τ (plus an optional source S) to the tracer tendency tc. If source is a scalar, it's applied uniformly; if it's a 3D array (interior-sized), the per-cell values are added.

Positive τ implies decay (photolysis, dry deposition); pass τ = Inf for an inert tracer with only the source term.

Aeolus.Chemistry.apply_photochemistry! — Method
apply_photochemistry!(NO, NO2, O3, VOC, HNO3, dt; μ₀ | J, T, p, OH = 0, ν = 2)
    -> (P_Ox, L_Ox, HNO3_formed)

Advance 3-D arrays of mixing ratios (ppb, e.g. interior_views) by dt with photochemistry_cell. The photolysis frequency is J (s⁻¹) or, if J is not given, j_NO2(μ₀). Temperature T (K), pressure p (Pa) and the prescribed OH number density OH (cm⁻³) are scalars or per-level vectors (length size(NO, 3)); the rate constants are evaluated once per level.

Aeolus.Chemistry.apply_wet_deposition! — Method
apply_wet_deposition!(c, qr, dt; scav) -> removed

Below-cloud scavenging by rain, $dc/dt = -Λ c$ with $Λ = s\,q_r$, integrated exactly over dt: $c ← c\,e^{-s q_r Δt}$. c and qr (rain mixing ratio, kg kg⁻¹) are 3-D arrays of the same size or Fields; scav is s in (kg/kg)⁻¹ s⁻¹ (rain_scavenging_coefficient). Cells without rain are untouched. Returns $Σ Δc$ over all cells (units of c × cells).

Aeolus.Chemistry.dry_deposition_velocity — Method
dry_deposition_velocity(r_a, r_b, r_c) -> m s⁻¹

$v_d = 1/(r_a + r_b + r_c)$: aerodynamic, quasi-laminar and surface resistances in series (s m⁻¹). r_a = 1/(C_H U) is the scalar aerodynamic resistance of the surface layer, e.g. from SurfaceExchange.solve_surface_layer.

Aeolus.Chemistry.emission_ppb_flux — Method
emission_ppb_flux(F, M_molar; p = 101325, T = 293.15) -> ppb m s⁻¹

Convert a surface emission mass flux F (kg m⁻² s⁻¹) of a gas with molar mass M_molar (kg mol⁻¹) to a mixing-ratio flux: the molar flux divided by the molar density of air $p/(RT)$, times 10⁹. Spread over a layer of depth $Δz$ for a time $Δt$, it raises the mixing ratio by $F_{ppb} Δt/Δz$ ppb.

Aeolus.Chemistry.j_NO2 — Method
j_NO2(μ₀) -> s⁻¹

Clear-sky NO2 photolysis frequency (NO2 + hν → NO + O(³P), the O(³P) forming O3 at once) as a function of the cosine of the solar zenith angle, in the MCM form $J = l\,μ_0^m \exp(-n/μ_0)$ with $l = 1.165×10^{-2}$, $m = 0.244$, $n = 0.267$ (MCM v3, J4; Saunders et al. 2003). Zero for $μ_0 ≤ 0$; 8.9 × 10⁻³ s⁻¹ with the sun overhead. It ignores clouds, aerosol and shading, so it is an upper bound in a street canyon.

Aeolus.Chemistry.k_NO2_OH — Method
k_NO2_OH(T, M) -> cm³ molecule⁻¹ s⁻¹

NO2 + OH (+M) → HNO3, the termolecular JPL form $k = \frac{k_0 M}{1 + k_0 M/k_∞} F_c^{\{1 + [\log_{10}(k_0 M/k_∞)]^2\}^{-1}}$ with $k_0 = 1.8×10^{-30} (T/300)^{-3}$, $k_∞ = 2.8×10^{-11}$, $F_c = 0.6$ (Burkholder et al. 2019). M is the air number density (cm⁻³, air_number_density). About 1.05 × 10⁻¹¹ at the surface.

Aeolus.Chemistry.k_NO_O3 — Method
k_NO_O3(T) -> cm³ molecule⁻¹ s⁻¹

NO + O3 → NO2 + O2: $k = 3.0×10^{-12} \exp(-1500/T)$ (Burkholder et al. 2019, JPL Publication 19-5). 1.9 × 10⁻¹⁴ at 298 K.

Aeolus.Chemistry.k_VOC_O3 — Method
k_VOC_O3(T) -> cm³ molecule⁻¹ s⁻¹

Ozonolysis of the lumped reactive VOC, taken as isoprene: $k = 1.03×10^{-14} \exp(-1995/T)$ (IUPAC; Atkinson et al. 2006). 1.3 × 10⁻¹⁷ at 298 K.

Aeolus.Chemistry.k_VOC_OH — Method
k_VOC_OH(T) -> cm³ molecule⁻¹ s⁻¹

OH oxidation of the lumped reactive VOC, taken as isoprene: $k = 2.7×10^{-11} \exp(390/T)$ (IUPAC; Atkinson et al. 2006). 1.0 × 10⁻¹⁰ at 298 K.

Aeolus.Chemistry.leighton_ratio — Method
leighton_ratio(NO, NO2, O3, J, k) -> φ

The Leighton ratio $φ = J[NO_2]/(k[NO][O_3])$: 1 in the photostationary state of the triad alone, above 1 where peroxy radicals also convert NO to NO2, below 1 in fresh NO emissions that have not yet reached the photostationary state.

Aeolus.Chemistry.nox_triad — Method
nox_triad(NO, NO2, O3, dt, J, k) -> (NO, NO2, O3)

Exact solution over dt of

NO2 + hν → NO + O3     (J,  s⁻¹)
NO + O3  → NO2 + O2    (k,  ppb⁻¹ s⁻¹)

With $NO_x = NO + NO_2$ and $O_x = O_3 + NO_2$ invariant, $y = [NO_2]$ obeys the Riccati equation $\dot y = k (y - y_1)(y - y_2)$ with roots $y_1 ≤ \min(NO_x, O_x) ≤ y_2$, whose solution is

$y(t) = y_1 + \frac{(y_0 - y_1) E}{1 - (y_0 - y_1)(1 - E)/r}$, $r = y_2 - y_1$, $E = e^{-k r t}$

(the $r → 0$ limit, night-time titration with $NO_x = O_x$, is taken through expm1). It is unconditionally stable, positive, relaxes to the photostationary state photostationary_NO2 on the time scale $1/(k r)$, and conserves $NO_x$ and $O_x$ to round-off for any dt.

Aeolus.Chemistry.photochemistry_cell — Method
photochemistry_cell(NO, NO2, O3, VOC, HNO3, dt; J, k1, k3, L4, L5, ν = 2)
    -> (NO, NO2, O3, VOC, HNO3, P_Ox, L_Ox)

Advance one cell of the reduced urban mechanism by dt (mixing ratios in ppb):

R1  NO2 + hν  → NO + O3               J   (s⁻¹)
R2  NO + O3   → NO2 + O2              k1  (ppb⁻¹ s⁻¹)
R3  VOC + O3  → products              k3  (ppb⁻¹ s⁻¹)
R4  VOC + OH  → ν (NO → NO2) + …      L4 = k_VOC_OH [OH]  (s⁻¹)
R5  NO2 + OH  → HNO3                  L5 = k_NO2_OH [OH]  (s⁻¹)

OH is prescribed (the mechanism has no HOx budget). In R4 the peroxy radical RO2 and the HO2 it yields each convert one NO to NO2, so each VOC oxidised converts $ν = 2$ NO (limited by the NO available): this is the ozone production of the mechanism.

Operator splitting (first order): R3–R5 as pseudo-first-order losses over dt with the partners frozen (exact exponentials), then the triad R1–R2 exactly by nox_triad. All species stay ≥ 0. Returns the new state and the cell's Ox production $P_{Ox}$ (R4) and loss $L_{Ox}$ (R3 + R5), in ppb, so that $Δ(O_3 + NO_2) = P_{Ox} - L_{Ox}$ and $Δ(NO + NO_2) = -ΔHNO_3$ exactly.

Aeolus.Chemistry.photostationary_NO2 — Method
photostationary_NO2(NOx, Ox, J, k) -> ppb

The photostationary NO2 for total $NO_x = NO + NO_2$ and $O_x = O_3 + NO_2$ (ppb): the smaller root of $k (NO_x - y)(O_x - y) = J y$, the state in which $J [NO_2] = k [NO][O_3]$. k in ppb⁻¹ s⁻¹ (ppb_rate_constant). At night ($J = 0$) it is $\min(NO_x, O_x)$: all the NO titrated, or all the O3.

Aeolus.Chemistry.ppb_rate_constant — Method
ppb_rate_constant(k, p, T) -> ppb⁻¹ s⁻¹

Convert a bimolecular rate constant k (cm³ molecule⁻¹ s⁻¹) to mixing ratios: $k_{ppb} = k M × 10^{-9}$, so that $d[\mathrm{A}]/dt = -k_{ppb} [\mathrm{A}][\mathrm{B}]$ with both in ppb.

Aeolus.Chemistry.quasi_laminar_resistance — Method
quasi_laminar_resistance(u_star; Sc, Pr = 0.72, κ = 0.4) -> s m⁻¹

Quasi-laminar (sub-layer) resistance to gas transfer over a surface, $r_b = \frac{2}{κ u_*}(Sc/Pr)^{2/3}$ (Wesely & Hicks 1977; Seinfeld & Pandis 2016, §19.3). u_star is floored at 0.01 m s⁻¹.

Aeolus.Chemistry.rain_scavenging_coefficient — Method
rain_scavenging_coefficient(species) -> (kg/kg)⁻¹ s⁻¹

Coefficient s of the below-cloud scavenging rate $Λ = s\,q_r$ (s⁻¹) used by apply_wet_deposition!, with $q_r$ the rain mixing ratio (kg kg⁻¹).

  • :HNO3: 1.0, so that $Λ ≈ 10^{-4}$ s⁻¹ at $q_r = 10^{-4}$ (about 2 mm h⁻¹ of rain) — the order of magnitude of below-cloud scavenging of a highly soluble gas (Seinfeld & Pandis 2016, ch. 20). Order of magnitude only, not a fit.
  • :NO, :NO2, :O3, :VOC: 0. Their Henry's-law solubilities are so low that rain removes a negligible fraction.

Machine-learning closures

Aeolus.ML.MLSGS — Type
MLSGS(fn)

Wraps a user function fn(νt, u, v, w, mesh) that populates νt::Field in-place from the current velocity state. Signature is intentionally minimal — any framework can provide the callable. Register on a BoussinesqSimulation by:

mlsgs = MLSGS((νt, u, v, w, m) -> my_neural_net(νt, u, v, w, m))
apply_mlsgs!(sim, mlsgs)      # populates sim.νt from the callable

Aeolus then feeds sim.νt into the existing add_eddy_viscosity_*! and add_eddy_diffusion_scalar! kernels — the ML kernel is a drop-in replacement for compute_smagorinsky_νt!.

An MLSGS is an AbstractEddyViscosityClosure of the Era VI SGS contract, so it is passed to any core directly, step!(sim, dt; sgs = mlsgs), with κt = νt / sim.Pr_t. It is stateless.

Aeolus.ML.apply_mlsgs! — Method

Aeolus.DataAssimilation.assimilate_nudging! — Method
assimilate_nudging!(sim, obs, γ, dt)

Apply Newtonian nudging of the observed field toward obs.value at the observation location: field[i,j,k] += γ · (obs.value - field[i,j,k]) · dt. γ [1/s] is the relaxation rate — inverse of the nudging time scale.
