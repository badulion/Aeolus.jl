Run configuration

Aeolus.Config (CFG-a, #356) is how a run is configured: a TOML file, checked against a declarative schema, resolved into an immutable typed RunConfig, and stored in run.toml in a canonical form from which the run can be rebuilt. The loader, the CLI's --set (CFG-b) and the drivers' option tables (CFG-c) all build on it.

Quick reference

# case.toml
extends = "base.toml"          # next to this file, else in the driver's config directory

[run]
driver = "common"
name   = "cbl"
seed   = 42

[fftw]
planner = "measure"

[checkpoint]
every_steps = 500
using Aeolus

cfg = load_run_config("case.toml"; overrides = ["checkpoint.keep=3", "run.seed=7"])
cfg.checkpoint.every_steps            # 500
cfg["fftw.planner"]                   # :measure
cfg2 = with(cfg, "run.seed" => 8)     # a new, validated config

write_config("resolved.toml", cfg)    # the canonical resolved form
config_hash(cfg)                      # fnv1a64 of that text

with_run(cfg) do rf                   # run.toml stores [config], its hash and [inputs]
    ck = checkpoint_schedule(cfg, checkpoint_dir(rf))
    # …
end

cfg3 = load_run_config("runs/2026-10-06_cbl_1a2b3c4d")   # == cfg

Files, extends and overrides

A configuration file may start from another with extends = "base.toml". The base is looked up next to the extending file first, then in the config directory the driver registered (register_driver!). Chains are followed up to 8 links deep; a cycle, a missing file or a deeper chain is an error naming the files.

Merging is key by key for tables; arrays and scalars replace (a child's levels = [1.0] replaces the base's whole array). overrides are "dotted.key=<TOML value>" strings applied last, so precedence is base < child < override. Strings are quoted: run.name="x".

load_run_config also reads a run folder or its run.toml: then the record's [config] is used.

Strict validation

Every problem is collected and thrown as one ConfigError: unknown keys (with a "did you mean" suggestion within Damerau–Levenshtein distance 2), wrong types, values out of range or outside the allowed set, tuples of the wrong length, failed cross-field checks. Each problem names the dotted key, the file the value came from, what was expected and what was given:

ConfigError: 3 problems in the run configuration
  - clock.nsteps (/work/case.toml): expected an integer in [0, 9223372036854775807], got "ten"
  - clock.scheme (/work/case.toml): expected a string (allowed: "rk3", "ab2", "imex"), got "rk4"
  - grid.sise (/work/base.toml): unknown key in [grid]; did you mean "size"?

Conventions

  • Keys are ASCII snake_case, transliterated from the Julia field names (ν → nu, θ₀ → theta0, C_s → c_s); table names are singular nouns ([grid], [clock]).
  • Values are SI; durations and cadences are in seconds. A unit appears in a key only where the Julia field carries one (start_h).
  • nothing is written "none". A missing key takes the default, never nothing.
  • A path is resolved against the directory of the file that set it (the working directory for an override or with) and stored absolute.
  • Environment variables do not configure runs. AEOLUS_LOG, AEOLUS_FFTW_PLANNER, AEOLUS_FFTW_THREADS and AEOLUS_ALLOW_UNCOMMITTED only fill the defaults of [logging] console_level, [fftw] planner / threads and [run] allow_uncommitted; the resolved value is always written.

The common sections

Every driver's schema starts with these:

sectionoptions
[run]driver (default and only value: the driver's name), name, seed = 0, root = "runs", allow_uncommitted
[fftw]planner (estimate, measure, patient, exhaustive), threads ("none": one per Julia thread), wisdom
[logging]console_level, file_level = "debug", flush_interval = 5.0 s, diagnostics_cadence = 60.0 s
[checkpoint]every_steps = 0 (off), every_seconds = inf (off), keep = 2, prefix = "checkpoint"
[output]path ("none": the run folder's output/), cadence = 3600.0 s

checkpoint_schedule and apply_fftw_config! read the [checkpoint] and [fftw] sections. Their Dict methods (a namelist from load_config) take their missing keys from the same schema defaults.

Drivers

A driver registers its sections, cross-field checks and config directory:

using Aeolus.Config

grid = section("grid"; doc = "the mesh") do s
    option!(s, "size", NTuple{3,Int}; default = (64, 64, 32), range = (1, 4096),
            doc = "cells per direction")
    option!(s, "extent", NTuple{3,Float64}; default = (3200.0, 3200.0, 1600.0),
            range = (0, Inf), open_lower = true, units = "m", doc = "domain size")
end
schema = register_driver!("cbl"; sections = [grid], config_dir = joinpath(@__DIR__, "config"))
check!(schema, cfg -> cfg.grid.size[3] > cfg.grid.size[1] ?
       [ConfigError("grid.size", "more vertical than horizontal cells")] : ConfigError[])

[run] driver = "cbl" then selects this schema; the driver "common" (the common sections only) is always registered.

The canonical form and run.toml

write_config writes every option, defaults included, keys sorted, schema_version = 1 at the top, no extends, paths absolute and floats in Julia's shortest round-trip representation (inf, -inf, nan for the specials). Writing a loaded canonical file again gives the same bytes; 0.1, 5e-324, -0.0, ±Inf and NaN keep their bits. config_hash is the fnv1a64 of this text.

start_run(cfg) (or start_run(case; config = cfg)) writes to run.toml:

keycontents
[config]the canonical resolved table
config_schema_version, config_hash1, 16 hex digits
config_sourcesfiles (the extends chain, leaf first), overrides, and the keys set by with
[inputs]every input Path option: path and its fnv1a64 content hash
replayable, nonreplayable_keysfalse and the keys if with set a value TOML cannot hold (a closure)

load_run_config(folder) returns a config equal to the one the run started with. It refuses a run whose input files changed (naming each file) unless allow_changed_inputs = true, and a run that is not replayable; a restart (start_run(…; resume = folder)) checks the inputs the same way before it writes anything. A Dict, NamedTuple or other object passed as config is recorded as before (toml_value).

OpenTable(validator = tbl -> String[])

Option type for a table whose keys a driver decides (the per-coupling options of the Berlin case). validator(tbl::Dict{String,Any}) returns the problems it finds: strings (attached to the option's key) or ConfigErrors whose keys are relative to the table.

Aeolus.Config.Option — Type
Option

One typed option of a Section: key, type (see option!), default (a value, a zero-argument function giving it at load time, or NoDefault()), doc, units, allowed, range, open_lower, required, input (a Path is an input file) and allow_julia (with may set a value TOML cannot hold).

Aeolus.Config.Optional — Type
Optional{T}

Option type marker for a value of type T or nothing. TOML has no null: nothing is written as the string "none". A missing key means "take the default", never nothing.

Aeolus.Config.Path — Type
Path

Option type marker for a filesystem path. Written as a TOML string; a relative path is resolved against the directory of the file that set it (the working directory for an override or with), and the resolved config holds it absolute. An option declared with input = true (the default) is an input file: its content hash is recorded under [inputs] of run.toml.

Aeolus.Config.RunConfig — Type
RunConfig

A fully resolved, validated, typed run configuration, made by load_run_config or with. Field access goes through the sections: cfg.grid.size, cfg.run.seed; cfg["grid.size"] takes a dotted key. It is not modified in place: with returns a new config. Two configs are == when their canonical texts (write_config) are identical.

Internals (use the accessors): the schema (config_schema), the file each value came from (config_origin), the sources (extends chain and overrides, config_sources) and the keys holding values TOML cannot hold (nonreplayable_keys).

Aeolus.Config.Section — Type

Aeolus.Config.apply_fftw_config! — Method
apply_fftw_config!(cfg::RunConfig) -> NamedTuple
apply_fftw_config!(cfg::AbstractDict) -> NamedTuple

Apply the [fftw] section to the FFTW planning policy (set_fftw_policy!), before the simulation is built:

[fftw]
planner = "measure"   # estimate | measure (default) | patient | exhaustive
threads = 4           # "none": one per Julia thread
wisdom  = "run/fftw_wisdom"   # optional: import before planning

From a RunConfig every option is resolved, so the planner is always set (threads = "none" leaves the thread count automatic). From a Dict (a namelist from load_config) only the keys present change anything, and without the table nothing changes. Returns the resulting fftw_policy.

Add a cross-field check: f(cfg::RunConfig) returns a vector of ConfigErrors (empty when the config is consistent). Run after every option has passed its own checks; their problems go into the one error the loader throws.

Aeolus.Config.load_run_config — Method
load_run_config(path; overrides = String[], schema = nothing,
                allow_changed_inputs = false) -> RunConfig
load_run_config(io::Base.IO; …)

Load, merge, validate and resolve a run configuration.

path is a .toml file, a run folder or its run.toml; for the last two the canonical [config] table of the record is used, the input files recorded under [inputs] must be unchanged (else a ConfigError names each changed file, unless allow_changed_inputs = true), and a record marked replayable = false is refused.

A .toml file may name a base file with extends = "base.toml", looked up relative to the extending file first, then in the driver's config directory (register_driver!); chains are followed up to 8 links deep, and a cycle is an error. Tables merge key by key; arrays and scalars replace. overrides are "dotted.key=<TOML value>" strings ("clock.nsteps=12", "grid.size=[16,16,16]", "run.name=\"x\""), applied last: precedence is base < child < override.

The schema is schema, or that of the driver named by [run] driver (default "common"). Unknown keys, wrong types, values out of range or outside allowed, tuples of the wrong length and failed cross-field checks are all collected and thrown as one ConfigError.

Aeolus.Config.nonreplayable_keys — Method
nonreplayable_keys(cfg) -> Vector{String}

The dotted keys holding a value TOML cannot hold (a closure set with with); a run with any is recorded replayable = false.

Aeolus.Config.option! — Method
option!(s::Section, key, T; default, doc = "", units = "", allowed = nothing,
        range = nothing, open_lower = false, required = false, input = true,
        allow_julia = false) -> Option

Declare the option key of type T in section s. Types:

  • Float64 (a TOML integer is accepted and converted), Int, Bool, String;
  • Symbol, written as a string and checked against allowed;
  • Path, resolved against the directory of the file that set it;
  • NTuple{N,T} of a scalar type, a TOML array of exactly N elements;
  • Vector{T};
  • Date and Time (TOML local date and local time);
  • Optional{T}, where "none" stands for nothing;
  • OpenTable(validator), a table whose keys a driver decides.

default is the value a missing key takes (a zero-argument function is called at load time, so an environment variable can fill it; the resolved value is always written). An Optional option defaults to nothing, an OpenTable to an empty table; any other option needs a default or required = true. range = (lo, hi) bounds numbers (closed, or open at lo with open_lower = true; Inf for no upper bound), elementwise for tuples and vectors; allowed lists the permitted values (elementwise too). units and doc go into the generated option reference.

Aeolus.Config.register_driver! — Method
register_driver!(name; sections = Section[], checks = Function[],
                 config_dir = nothing) -> ConfigSchema

Register the configuration schema of the driver name ([run] driver = "name" selects it). config_dir is where extends = "base.toml" looks when the file is not next to the extending one. Registering a name again replaces it. The driver "common" (the common sections only) is always registered.

Aeolus.Config.shipped_configs — Method
shipped_configs() -> Vector{String}

Every .toml file in the registered drivers' config directories.

Aeolus.Config.to_toml — Method
to_toml(cfg::RunConfig) -> Dict{String,Any}

The canonical resolved form as a TOML-ready table: schema_version = 1 and every section with every option, defaults included; symbols as strings, nothing as "none", tuples as arrays, paths absolute, no extends. A value TOML cannot hold is written as "<julia: …>".

Aeolus.Config.with — Method
with(cfg::RunConfig, "section.key" => value, …) -> RunConfig

A new, validated config with the given options replaced (Julia values: Symbols, tuples, nothing for an Optional, …; a relative Path is resolved against the working directory). Unknown keys and invalid values throw a ConfigError listing every problem; the cross-field checks run again. An option declared allow_julia = true also takes a value TOML cannot hold (a closure); the config is then not replayable (nonreplayable_keys), and run.toml records it so.

Aeolus.Config.write_config — Method
write_config(io::Base.IO, cfg) / write_config(path, cfg) / write_config(cfg) -> String

Write the canonical resolved form of cfg (to_toml): keys sorted, top-level scalars first, then one [table] per section (and [section.sub] for nested tables), floats in Julia's shortest round-trip representation (inf, -inf, nan for the specials). Loading the text back gives the same config, and writing that again gives the same bytes. write_config(cfg) returns the text.

Aeolus.IO.start_run — Method
start_run(cfg::RunConfig; kwargs...) -> RunFolder

start_run(cfg.run.name; config = cfg, kwargs...): the run folder's root, the dirty-tree policy and the log levels come from [run] and [logging] unless given as keywords. run.toml stores the canonical [config], config_schema_version, config_hash, config_sources, the [inputs] hashes and replayable.
