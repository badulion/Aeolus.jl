Run configuration

Aeolus.Config (CFG-a, #356) is how a run is configured: a TOML file, checked against a declarative schema, resolved into an immutable typed RunConfig, and stored in run.toml in a canonical form from which the run can be rebuilt. The loader, the aeolus command line and its --set (CFG-b, #357) and the drivers' option tables all build on it.

julia --project -m Aeolus run examples/configs/taylor_green_vortex.toml   # Julia ≥ 1.12
bin/aeolus run examples/configs/taylor_green_vortex.toml                  # any Julia

Quick reference

# case.toml
extends = "base.toml"          # next to this file, else in the driver's config directory

[run]
driver = "common"
name   = "cbl"
seed   = 42

[fftw]
planner = "measure"

[checkpoint]
every_steps = 500
using Aeolus

cfg = load_run_config("case.toml"; overrides = ["checkpoint.keep=3", "run.seed=7"])
cfg.checkpoint.every_steps            # 500
cfg["fftw.planner"]                   # :measure
cfg2 = with(cfg, "run.seed" => 8)     # a new, validated config

write_config("resolved.toml", cfg)    # the canonical resolved form
config_hash(cfg)                      # fnv1a64 of that text

with_run(cfg) do rf                   # run.toml stores [config], its hash and [inputs]
    ck = checkpoint_schedule(cfg, checkpoint_dir(rf))
    # …
end

cfg3 = load_run_config("runs/2026-10-06_cbl_1a2b3c4d")   # == cfg

Files, extends and overrides

A configuration file may start from another with extends = "base.toml". The base is looked up next to the extending file first, then in the config directory the driver registered (register_driver!). Chains are followed up to 8 links deep; a cycle, a missing file or a deeper chain is an error naming the files.

Merging is key by key for tables; arrays and scalars replace (a child's levels = [1.0] replaces the base's whole array). overrides are "dotted.key=<TOML value>" strings applied last, so precedence is base < child < override. Strings are quoted: run.name="x".

load_run_config also reads a run folder or its run.toml: then the record's [config] is used.

Strict validation

Every problem is collected and thrown as one ConfigError: unknown keys (with a "did you mean" suggestion within Damerau–Levenshtein distance 2), wrong types, values out of range or outside the allowed set, tuples of the wrong length, failed cross-field checks. Each problem names the dotted key, the file the value came from, what was expected and what was given:

ConfigError: 3 problems in the run configuration
  - clock.nsteps (/work/case.toml): expected an integer in [0, 9223372036854775807], got "ten"
  - clock.scheme (/work/case.toml): expected a string (allowed: "rk3", "ab2", "imex"), got "rk4"
  - grid.sise (/work/base.toml): unknown key in [grid]; did you mean "size"?

Conventions

  • Keys are ASCII snake_case, transliterated from the Julia field names (ν → nu, θ₀ → theta0, C_s → c_s); table names are singular nouns ([grid], [clock]).
  • Values are SI; durations and cadences are in seconds. A unit appears in a key only where the Julia field carries one (start_h).
  • nothing is written "none". A missing key takes the default, never nothing.
  • A path is resolved against the directory of the file that set it (the working directory for an override or with) and stored absolute.
  • Environment variables do not configure runs. AEOLUS_LOG, AEOLUS_FFTW_PLANNER, AEOLUS_FFTW_THREADS and AEOLUS_ALLOW_UNCOMMITTED only fill the defaults of [logging] console_level, [fftw] planner / threads and [run] allow_uncommitted; the resolved value is always written.

The common sections

Every driver's schema starts with these:

sectionoptions
[run]driver (default and only value: the driver's name), name, seed = 0, root = "runs", allow_uncommitted
[fftw]planner (estimate, measure, patient, exhaustive), threads ("none": one per Julia thread), wisdom
[logging]console_level, file_level = "debug", flush_interval = 5.0 s, diagnostics_cadence = 60.0 s
[checkpoint]every_steps = 0 (off), every_seconds = inf (off), keep = 2, prefix = "checkpoint"
[output]path ("none": the run folder's output/), cadence = 3600.0 s

checkpoint_schedule and apply_fftw_config! read the [checkpoint] and [fftw] sections. Their Dict methods (a namelist from load_config) take their missing keys from the same schema defaults.

Drivers

A driver registers its sections, cross-field checks and config directory:

using Aeolus.Config

grid = section("grid"; doc = "the mesh") do s
    option!(s, "size", NTuple{3,Int}; default = (64, 64, 32), range = (1, 4096),
            doc = "cells per direction")
    option!(s, "extent", NTuple{3,Float64}; default = (3200.0, 3200.0, 1600.0),
            range = (0, Inf), open_lower = true, units = "m", doc = "domain size")
end
schema = register_driver!("cbl"; sections = [grid], config_dir = joinpath(@__DIR__, "config"))
check!(schema, cfg -> cfg.grid.size[3] > cfg.grid.size[1] ?
       [ConfigError("grid.size", "more vertical than horizontal cells")] : ConfigError[])

[run] driver = "cbl" then selects this schema; the driver "common" (the common sections only) is always registered. A driver section named like a common one adds its options to it (the simulation driver's [output] fields); redeclaring a common option is an error.

Run drivers

A schema says what a config may contain; a run driver (AbstractRunDriver) also says how to build and run it. A driver type implements driver_name, driver_sections, driver_checks (optional), config_dir (optional), build(d, cfg), run!(d, obj, rf, ck; callback) and state_fields(obj), and is registered with register_driver!(D()):

using Aeolus, Aeolus.Config

struct CBLDriver <: AbstractRunDriver end
Config.driver_name(::CBLDriver) = "cbl"
Config.driver_sections(::CBLDriver) = [grid]                 # as above
Config.build(::CBLDriver, cfg) = build_my_simulation(cfg)
function Aeolus.run!(::CBLDriver, sim, rf, ck; callback = nothing)
    d = resume!(ck, sim)                                     # a resumed run continues
    # … step, maybe_checkpoint!(ck, sim; step = n), callback(sim, n) …
end
Config.state_fields(sim) = (u = sim.u.data, θ = sim.θ.data)
register_driver!(CBLDriver())

run_config(cfg; root, resume) is the Julia API behind aeolus run: apply_fftw_config!, start_run, run_checkpoints from [checkpoint] (before the build, so a resumed run imports the folder's FFTW wisdom before it plans), build, run!, then finish_run! (failed or interrupted with the error, which is rethrown). It returns a RunResult (folder, obj).

Drivers that live under examples/ (the Berlin, SBL and validation drivers) are not moved into src/: DRIVER_FILES maps their names to files relative to the package directory, and the first config that names one includes the file into a fresh module. The migrations of #311 add their entries.

Each example script is now "run the config(s), then analyse or plot": run_configs(path, ARGS) takes the script's command line (--set, --member, --root, --allow-uncommitted) and returns one RunResult per run. A driver gets a new section only where the case has structure of its own; a driver with a case switch keeps one section per case and refuses a key set in the section of a case that is not selected (selected_case_sections). A section whose options are the fields of a keyword struct is made with kwdef_section (the struct's defaults are the schema's: FogColumnSettings is [fog], BroadeningCase is [parcel]) and read back with kwdef_value.

Not runs, so without a config (EXEMPT in test/config_examples.jl, each with its reason): validation/canopy_profiles.jl (steady 1-D boundary-value solves), validation/dynamic_roughness_cubes.jl (a-priori roughness of a height map), validation/dns256_generate.jl (the offline fixture generator), the Poisson manufactured-solution checks, and the library files the drivers include. The same test lists every example that calls a stepping entry point and requires a config or an exemption; the scripts of #360's later parts are listed there until they move.

Sweeps

A config may carry a [sweep]: axes (a product, the first axis outermost) and/or explicit members. The runner expands it into ordinary overrides, base < member < --set, and each member is its own run folder whose run.toml records the member's overrides and no [sweep], so it replays as a single run:

extends = "base.toml"

[[sweep.member]]
label = "no_feedback"
fog = { droplet_feedback = false }

[sweep]
axis = [ { key = "sgs.closure", values = ["smagorinsky", "lasd", "lasi"] },
         { key = "channel.size", values = [[32, 32, 32], [48, 48, 48]] } ]

Members are labelled by their label (or index) joined with the axis values (lasd_32x32x32); the run name gets the label as a suffix. load_run_config refuses a sweep file and says how to run it; load_sweep and sweep_members expand it; aeolus run/check/resolve handle sweeps, and run and resolve take --member k (index or label).

The command line

commanddoes
run <config.toml> [--set k=v]… [--root DIR] [--allow-uncommitted]a new run (new run ID and folder) from a config file
run <run-folder>/run.toml …a new run with the configuration of an earlier run
run <run-folder> --resumecontinues that run: same run ID, a new session, from its newest checkpoint (--set is refused)
check <config> [--set k=v]…validates and prints every problem
resolve <config> [--set k=v]…prints the canonical resolved TOML
options [driver] [section]prints the option reference, generated from the schema
preprocess <kind> …a registered preprocessor (register_preprocessor!)

Exit codes: 0 success; 1 the run failed (blowup or error; its session is recorded as failed); 2 a usage or configuration error, raised before anything is written. --root and --allow-uncommitted change where and whether the run starts, not its recorded config. julia --project -m Aeolus … needs Julia ≥ 1.12 (the -m flag; the @main entry point is marked on ≥ 1.11); bin/aeolus works on every Julia the package supports. In Julia, Aeolus.main(["run", "case.toml"]) returns the exit code.

The simulation driver

[run] driver = "simulation" is a bare run of one dynamical core on a box (Aeolus.SimulationDriver): what examples/taylor_green_vortex.jl, dry_convective_bl.jl and buoyant_convection.jl used to build in code. Their configs are in examples/configs/, and the scripts are now three-line runners.

[run]
driver = "simulation"
name = "taylor_green_vortex"

[grid]
size = [32, 32, 32]
extent = [6.283185307179586, 6.283185307179586, 6.283185307179586]

[dynamics]
nu = 0.01

[initial]
u = { kind = "taylor_green", amplitude = 1.0, k = 1.0 }
v = { kind = "taylor_green", amplitude = 1.0, k = 1.0 }

[stepper]
dt = 0.07853981633974483        # shortened to end_time / ceil(end_time / dt) = 2/26
end_time = 2.0

This config is, bit for bit, the simulation the script built before (test/config_simulation_driver.jl). Notes on the sections:

  • [stepper]: dt or cfl (adaptive, step_adaptive!, with a finite dt_max), and end_time or nsteps. euler is step!, rk3 step_rk3!.
  • [sgs] closure = "smagorinsky" without a stability correction is the simulation's built-in closure (C_s ≠ 0); every other choice is passed to the steps as a closure object.
  • [dynamics] nu is also θ's (and qv's) molecular diffusivity: the cores have one coefficient (Prandtl number 1), so there is no separate kappa.
  • Combinations a core cannot run are config errors: the anelastic core needs z walls, theta0 > 0, a fixed dt with euler, a uniform grid and no checkpoints; a stretched grid takes the none or smagorinsky closure.
  • The run writes diagnostics.csv (the run monitor, every [logging] diagnostics_cadence), checkpoints on [checkpoint], and the [output] fields every [output] cadence as output/fields_<step>.nc.

The options:

# options of driver "simulation"

[run]  What runs and where its folder goes.
  driver : string = "simulation" (allowed: "simulation")
      the driver whose schema validates this config
  name : string = "simulation"
      the case name: part of the run folder name runs/<date>_<name>_<id>
  seed : integer = 0 in [0, 9223372036854775807]
      the seed of the run's random numbers
  root : string = "runs"
      the directory the run folders go in (relative to the working directory)
  allow_uncommitted : boolean = false (from the environment if set)
      start on a dirty git tree, saving the diff (default: AEOLUS_ALLOW_UNCOMMITTED=1)

[fftw]  The FFTW planning policy (set_fftw_policy!).
  planner : string = "estimate" (from the environment if set) (allowed: "estimate", "measure", "patient", "exhaustive")
      estimate | measure | patient | exhaustive (default: AEOLUS_FFTW_PLANNER, else measure)
  threads : integer | "none" = "none" (from the environment if set) in [1, 4096]
      FFTW threads; "none": one per Julia thread (default: AEOLUS_FFTW_THREADS)
  wisdom : path | "none" = "none"
      FFTW wisdom file imported before planning, if it exists

[logging]  The run log and the diagnostics.
  console_level : string = "info" (from the environment if set) (allowed: "debug", "info", "warn", "error", "off")
      lowest level shown on the console (default: AEOLUS_LOG, else info)
  file_level : string = "debug" (allowed: "debug", "info", "warn", "error", "off")
      lowest level written to run.log
  flush_interval : float = 5.0  [s] in [0, Inf]
      run.log is flushed at most this often (warnings at once); 0: every record
  diagnostics_cadence : float = 60.0  [s] in (0, Inf]
      simulated time between the costly diagnostics (RunMonitor cadence)

[checkpoint]  Periodic checkpoints (CheckpointSchedule).
  every_steps : integer = 0 in [0, 9223372036854775807]

  every_seconds : float = inf  [s] in (0, Inf]

  prefix : string = "checkpoint"

[output]  Output files.
  path : path | "none" = "none"
      output directory; "none": the run folder's output/
  cadence : float = 3600.0  [s] in (0, Inf]
      simulated time between output files
  fields : [string, …] = [] (allowed: "u", "v", "w", "p", "theta", "qv")
      fields written to output/fields_<step>.nc every cadence (cell-index arrays, Float32); [] : none

[grid]  The box and its mesh.
  size : [3 × integer] = [32, 32, 32] in [1, 65536]
      cells in x, y, z
  extent : [3 × float] = [1.0, 1.0, 1.0]  [m] in (0, Inf]
      domain size Lx, Ly, Lz
  halo : [3 × integer] = [2, 2, 2] in [1, 8]
      halo cells per side
  stretching : string = "uniform" (allowed: "uniform", "geometric", "tanh", "tanh_both")
      vertical spacing (StretchedGrid): uniform (a RegularGrid), geometric (dz[k+1] = r dz[k]), tanh (clustered at the bottom), tanh_both (at both walls)
  stretching_parameter : float = 1.0 in (0, Inf]
      r of geometric, β of tanh / tanh_both; unused for uniform

[dynamics]  The dynamical core and its parameters.
  core : string = "boussinesq" (allowed: "boussinesq", "anelastic")
      boussinesq (BoussinesqSimulation) or anelastic (AnelasticSimulation on an isentropic base state)
  nu : float = 0.0  [m^2 s^-1] in [0, Inf]
      kinematic viscosity; θ and qv diffuse with the same coefficient (Prandtl number 1)
  theta0 : float = 0.0  [K] in [0, Inf]
      reference potential temperature of the buoyancy; 0 turns buoyancy off (boussinesq); anelastic: the base state's θ (> 0)
  g : float = 9.81  [m s^-2] in [0, Inf]
      gravitational acceleration
  f_coriolis : float = 0.0  [s^-1]
      Coriolis parameter
  moisture : boolean = false
      carry the water-vapour mixing ratio qv (boussinesq only)
  sponge_alpha_max : float = 0.0  [s^-1] in [0, Inf]
      Rayleigh-damping rate at the top; 0: no sponge
  sponge_z_start : float | "none" = "none"  [m]
      height where the sponge starts; "none": the top (no sponge)

[boundaries]  Boundary conditions per axis.
  x : string = "periodic" (allowed: "periodic", "free_slip", "noslip")
      the x faces: periodic, free_slip (impermeable, stress free) or noslip (z only); θ and qv have no flux through a wall, except the prescribed θ fluxes
  y : string = "periodic" (allowed: "periodic", "free_slip", "noslip")
      the y faces: periodic, free_slip (impermeable, stress free) or noslip (z only); θ and qv have no flux through a wall, except the prescribed θ fluxes
  z : string = "periodic" (allowed: "periodic", "free_slip", "noslip")
      the z faces: periodic, free_slip (impermeable, stress free) or noslip (z only); θ and qv have no flux through a wall, except the prescribed θ fluxes
  theta_flux_bottom : float = 0.0  [K m s^-1]
      prescribed kinematic θ flux w'θ' through the bottom (z walls)
  theta_flux_top : float = 0.0  [K m s^-1]
      prescribed kinematic θ flux through the top (z walls)

[sgs]  The subgrid-scale closure.
  closure : string = "none" (allowed: "none", "smagorinsky", "dynamic_smagorinsky", "vreman", "sigma", "amd")
      none, smagorinsky (Smagorinsky-Lilly), dynamic_smagorinsky (Germano-Lilly, plane averaged), vreman, sigma (Nicoud et al. 2011), amd (anisotropic minimum dissipation)
  c_s : float | "none" = "none" in (0, Inf]
      the closure's coefficient; "none": its default (smagorinsky 0.17, vreman 0.17, sigma 1.35, amd 0.3); not used by dynamic_smagorinsky
  pr_t : float = 0.3333333333333333 in (0, Inf]
      turbulent Prandtl number
  stability : string = "none" (allowed: "none", "brown_et_al_1994", "lilly_cutoff", "short_tail", "long_tail")
      Richardson-number stability correction of the eddy viscosity (StabilityCorrected); none: off

[initial]  The initial state.
  u : table = {}
      initial u: {kind = "constant", value}, {kind = "mixed_layer_lapse", value, z_i, lapse}, {kind = "table", z, values}, or {kind = "taylor_green", amplitude, k} (u = A sin kx cos ky cos kz, v = -A cos kx sin ky cos kz); {} (the default): 0
  v : table = {}
      initial v: {kind = "constant", value}, {kind = "mixed_layer_lapse", value, z_i, lapse}, {kind = "table", z, values}, or {kind = "taylor_green", amplitude, k} (u = A sin kx cos ky cos kz, v = -A cos kx sin ky cos kz); {} (the default): 0
  theta : table = {}
      initial theta: {kind = "constant", value}, {kind = "mixed_layer_lapse", value, z_i, lapse}, {kind = "table", z, values}; {} (the default): theta0 (anelastic: the base state)
  qv : table = {}
      initial qv: {kind = "constant", value}, {kind = "mixed_layer_lapse", value, z_i, lapse}, {kind = "table", z, values}; {} (the default): 0
  perturbation_amplitude : float = 0.0  [K] in [0, Inf]
      white noise on θ, uniform in [-a/2, a/2], drawn from Xoshiro([run] seed)
  perturbation_depth : float = inf  [m] in [0, Inf]
      the noise is added below this height

[stepper]  Time stepping. Give dt or cfl, and end_time or nsteps.
  scheme : string = "euler" (allowed: "euler", "rk3")
      euler (step!, the forward-Euler projection) or rk3 (step_rk3!, SSP-RK3); anelastic: euler
  dt : float | "none" = "none"  [s] in (0, Inf]
      fixed step; with end_time it is shortened to end_time / ceil(end_time / dt)
  cfl : float | "none" = "none" in (0, Inf]
      adaptive step (step_adaptive!) with this advective Courant number
  dt_max : float = inf  [s] in (0, Inf]
      the largest adaptive step (with cfl; the step of a fluid at rest)
  end_time : float | "none" = "none"  [s] in (0, Inf]
      simulated time to run
  nsteps : integer | "none" = "none" in [0, 9223372036854775807]
      steps to run

The bit-identical round trip

test/config_roundtrip_harness.jl is the check every config migration uses: roundtrip_check(path; nsteps, overrides) runs a config through run_config, re-runs the run from its own run.toml (a new run), and compares every array of state_fields bitwise (reinterpret(UInt64, a) == reinterpret(UInt64, b)), diagnostics.csv outside its wall-clock column, and the two [config] tables. Both runs use [fftw] planner = "estimate" (the bitwise policy of #245) and the same thread count.

The canonical form and run.toml

write_config writes every option, defaults included, keys sorted, schema_version = 1 at the top, no extends, paths absolute and floats in Julia's shortest round-trip representation (inf, -inf, nan for the specials). Writing a loaded canonical file again gives the same bytes; 0.1, 5e-324, -0.0, ±Inf and NaN keep their bits. config_hash is the fnv1a64 of this text.

start_run(cfg) (or start_run(case; config = cfg)) writes to run.toml:

keycontents
[config]the canonical resolved table
config_schema_version, config_hash1, 16 hex digits
config_sourcesfiles (the extends chain, leaf first), overrides, and the keys set by with
[inputs]every input Path option: path and its fnv1a64 content hash
replayable, nonreplayable_keysfalse and the keys if with set a value TOML cannot hold (a closure)

load_run_config(folder) returns a config equal to the one the run started with. It refuses a run whose input files changed (naming each file) unless allow_changed_inputs = true, and a run that is not replayable; a restart (start_run(…; resume = folder)) checks the inputs the same way before it writes anything. A Dict, NamedTuple or other object passed as config is recorded as before (toml_value).

The prognostic arrays with their halos: u, v, w, p, θ (and, for the Boussinesq core, qv and the eddy coefficients νt, κt of the last step, as a checkpoint stores them).

Aeolus.SimulationDriver._profile_validator — Method

The validator of the profile table of variable var (an empty table: the default profile).

Aeolus.SimulationDriver.profile_value — Method
profile_value(p::AbstractDict, z) -> Float64

The value at height z of a vertical profile of [initial]:

  • {kind = "constant", value};
  • {kind = "mixed_layer_lapse", value, z_i, lapse}: value below z_i, value + lapse (z − z_i) above (a capping inversion; with z_i at the ground, a linear profile);
  • {kind = "table", z = […], values = […]}: linear interpolation, constant beyond the ends.
