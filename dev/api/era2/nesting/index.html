Parent ↔ child grid nesting (Phase 30)

Aeolus.Nesting is the single home of every parent-child operator: the NestedGrid geometry (any integer refinement per direction), the conservative staggered prolongation, conservative restriction, Berger–Colella refluxing, the NestSponge, the field-set NestInterpState (velocities, θ, qv, extra scalars), and the time coupling: NestedRun, the per-domain domain_advance closures, boundary_time and step_nested! — or, for a caller that advances the child itself (the Berlin case, #265), begin_parent_step!, subcycle_dt and end_parent_step!, with each child step bracketed by begin_child_step! and end_child_step! in a two-way run (#267) — and the child's boundary conditions: nest_bcs (OpenBoundary nest faces) fed by NestBoundaryData (the nest parent as a two-snapshot WindowedBoundaryData), refreshed by fill_nest_halos!, and the two-way feedback: TwoWayFeedback (anterpolation with buffer zone, canopy restriction, inflow exclusion and relaxation, scalar refluxing from NestFluxRegisters, re-projection), anterpolate!, feedback_mask and two_way_feedback!; a tracer moved by a separate transport books its interface flux with book_nest_flux!, and a user core declares its stage weights with nest_stage_weights. The parent may be z-stretched (StretchedGrid), the operators may run in the reference-mass measure of a sound-proof pair (NestMeasure, nest_measure), and restriction may be solid-aware (nest_fluid_mask). The block-structured AMR of Aeolus.AdaptiveMesh builds on these operators. The theory is on the nesting theory page, the nested time-coupling page, the nested boundary-conditions page and the two-way nesting page.

Aeolus.Nesting._NO_LEDGER — Constant
begin_parent_step!(run::NestedRun; dt = nothing) -> window

Steps 1–4 of step_nested!(run): pick the parent step Δt_p (or take dt), prolongate the parent field set at t_p (reused from the previous step in a one-way run), advance the parent (with its retries), prolongate at t_p + Δt_p, and point the child's open faces at the new window [t_p, t_p + Δt_p]. The child is not advanced: a caller that drives the child itself — the Berlin case, whose child step is a whole stage loop (examples/urban, N-berlin-nest #265) — then takes any child steps that land on window.t_child_end (the child's open faces read the time-blended parent at every stage time, boundary_time) and closes the window with end_parent_step!.

Returns window = (t_child_end, Δt, I0, m0): the child time the window ends at, the parent step taken, and (two-way runs that record) the composite integrals at the start (the run's scratch vector, in the order of the scalar ledger keys), which end_parent_step! compares.

step_nested!(run) is exactly begin_parent_step!, the run's own child subcycling (advance_child), end_parent_step!.

A run with a NestSponge is refused (ArgumentError): the sponge relaxes the child inside the run's own subcycling (the velocity on every stage's predicted velocity, the scalars after each substep), so an externally driven child would silently get none (#349). Drive a sponged run with step_nested!, or relax the externally driven child with the core's own sponge (the Berlin case's top sponge).

Aeolus.Nesting.DomainAdvance — Type
DomainAdvance

A per-domain advance!(sim, dt) closure built by domain_advance: a dynamical core plus the hooks and keywords that domain's steps must carry (body_force!, post_predictor!, momentum_advection, sgs, sgs_stress, …). Calling it, adv(sim, dt), runs core(sim, dt, args...; kwargs...). A caller may pass an extra post_predictor! hook, adv(sim, dt; post_predictor! = f), which is chained after the domain's own, and an extra body_force! hook, adv(sim, dt; body_force! = f), chained before the domain's own (the two-way nest books its flux registers there, N-nest-e #263).

Aeolus.Nesting.NestBoundaryData — Type
NestBoundaryData{S<:NestInterpState} = WindowedBoundaryData{S}

The parent of a nest as the boundary data of the child's OpenBoundary faces (built by nest_bcs). It holds two NestInterpStates — the parent field set prolongated onto the child mesh at the two ends of the current parent step, a = B(t₀) and b = B(t₀ + Δt) — and

boundary_values!(planes, data, t)

writes (1 − τ) a + τ b, τ = (t − t₀)/Δt, into every open-boundary buffer, at the buffer's own storage points: the normal-velocity face planes (the boundary face and the H layers beyond it) and the tangential-velocity and scalar halos, for every member of the field set (u, v, w, θ, qv, extra scalars). Δt = 0 is steady data (a). It is the generic two-snapshot WindowedBoundaryData with the prolongated field set as the snapshot (#329): the time blend is the one of boundary_time, one kernel (blend_window!) for both, exact for data linear in time, second order otherwise (N-nest-c, #257).

Faces inside solids are not this type's business (#327, M4): a NestedRun built with solid = mask (and apply_nest_boundary!(…; solid)) marks them with the one open-boundary path, mark_open_boundary_solids! (N-open-d #262): every velocity buffer — normal and tangential — is zero at the solid points, and the mass-flux correction neither counts nor adjusts them.

The prolongated parent states are filled by a NestedRun (or, steady, by apply_nest_boundary!); see nest_boundary_data.

References: Hellsten, A. et al. (2021), A nested multi-scale system implemented in the large-eddy simulation model PALM model system 6.0, Geosci. Model Dev. 14, 3185–3214, §3.2–3.3 (Dirichlet child boundary from the interpolated parent, mass-flux correction); Kadasch, E. et al. (2021), Geosci. Model Dev. 14, 5435–5465, §2.2–2.3 (the same interface for a mesoscale parent).

Aeolus.Nesting.NestFluxMismatch — Type
NestFluxMismatch

Per-face-patch difference between the parent's coarse flux and the summed fine child fluxes on the six nest-boundary planes, in flux units (field value × area). Populated pairs depend on the field's Location: FaceX fills west/east (size ny × nz), FaceY fills south/north (nx × nz), FaceZ fills bottom/top (nx × ny). Unused planes are 0 × 0.

Aeolus.Nesting.NestFluxRegisters — Type
NestFluxRegisters

The Berger–Colella flux registers of a two-way NestedRun: for every refluxed scalar (θ, qv, declared tracers) and every interface plane (the child's open faces), the time integral ∫ F dt of the face flux density (∫ W F dt for a sound-proof pair) through every parent face of the plane and every child face of the plane, and the volume (mass) flux ∫ W u_n dt that carried it (for the volume-consistent refluxing of two_way_feedback!). Scalars transported inside the cores (applied_by = :core) are booked by a hook the run chains in front of each domain's body_force!, at every stage of every attempted step, with the stage weight of the core; scalars moved by a separate transport (applied_by = :transport) are booked by that transport through book_nest_flux!. A rejected step's bookings are discarded with it; the registers are consumed by the refluxing of two_way_feedback!. Only the planes are stored, not whole face fields.

Aeolus.Nesting.NestInterpState — Type
NestInterpState

The parent solution interpolated onto the child mesh — boundary data for the child and the relaxation target for apply_nest_sponge!. It is a state over a named field set:

  • the velocities u, v, w (fields s.u, s.v, s.w);
  • θ (field s.θ);
  • qv, when built from moist simulations with nest_interp_state(nest, parent_sim, child_sim);
  • any extra cell-centred scalars, passed as scalars = (:co2 => (child_field, parent_field), …).

Every cell-centred scalar of the set other than θ is bound to its child and parent fields; read the interpolated buffer of any member with s[name] (e.g. s[:qv], s[:co2], s[:u]) and list the scalar names with nest_scalar_names. Prolongation (interpolate_parent_state!), the halo write (apply_nest_boundary!), the sponge, restriction (restrict_state_to_parent!), composite_integral and refluxing (reflux_scalars!) all iterate over the whole set, through the same operator per member — so a tracer initialised equal to θ stays bit-identical to θ through all of them.

s.measure is the vertical NestMeasure of the set's operators: nothing (volume) for Boussinesq sims, the reference-mass measure for a MassWeightedSimulation pair, so prolongation, restriction, refluxing and the composite integrals conserve ∫ W φ dV.

Storage. A storage = :full state (the default of nest_interp_state) holds child-sized fields. A storage = :shell state holds only the halo slabs and the boundary-normal face plane of each member (#329): what the child's open faces read. It is what a NestedRun without a sponge keeps (the two window ends and the blend), (N+2H)³ − N³ instead of (N+2H)³ points per member; reading its interior is an error, so it cannot be a sponge target or take a region = :all prolongation.

Aeolus.Nesting.NestMeasure — Type
NestMeasure

Vertical measure of the nesting operators of one NestedGrid: the coordinate in which the conservative prolongation reconstructs parent averages and the weights with which restriction averages child cells. Build with nest_measure.

  • kind = :volume — volume (height) measure. On a uniform parent the operators are exactly the N-nest-a (#250) operators; on a z-stretched parent the reconstruction uses the actual face heights.
  • kind = :mass — the reference-mass measure dμ = W(z) dz of a MassWeightedSimulation pair (W = ρ̄ anelastic, ρ̄θ̄ pseudo-incompressible, from constraint_weights). Restriction is W-weighted (scalars) and W-area-weighted (horizontal-normal faces); prolongation conserves ∫ W φ dV exactly.

Fields (all storage-indexed, halos included): pc/cc the parent/child face coordinates in the measure, ph/ch the parent/child face heights (child faces that coincide with parent faces are bit-identical copies), cw the child cell measure per level (Δz or W Δz), pw the parent cell measure per level from the parent's own weight (Δz or W_p Δz_p), and the plan cache.

Two parent cell masses exist in the mass measure. Inside the covered layers the coordinate pc takes a parent layer's mass to be the sum of its children's (Σ W_c Δz_c), which is what makes prolongation and restriction exactly conservative and the Lagrange basis exactly 0/1 on coincident faces. The parent simulation itself conserves W_p Δz_p, which differs from that sum by the midpoint-rule error of sampling one profile on two grids (nest_reference_mismatch, ~4e-7 for a 25 m layer). Cell integrals over uncovered parent cells (composite_integral, the refluxing correction) therefore use pw, so the composite integral is exactly what the two simulations conserve; covered parent cells only ever exchange with their own children and use pc.

Aeolus.Nesting.NestScalarFlux — Type
NestScalarFlux(; scheme = :centered, molecular = false, sgs = :none, applied_by = :core)

The transport of a cell-centred scalar whose interface flux a two-way nest books in its flux registers (TwoWayFeedback).

applied_by = :core (default): the scalar is transported inside the core's stages (the core's own θ/qv transport, or an owner that updates it in the body_force! hook), and the run's register hook books, at every stage with the core's stage weight, the advective face flux of scheme (a name of boundary_scalar_flux or a reconstruction descriptor; the Boussinesq and sound-proof cores advect θ and qv with :centered), plus the molecular diffusion ν∇ϕ of the simulation (molecular = true, when the simulation has viscosity) and the SGS flux of the domain's closure: sgs = :theta with θ's diffusivity (sgs_scalar_face_diffusivity), sgs = :tracer with the diffusivity the core gives a tracer (sgs_tracer_diffusivity!, as for qv), :none without.

applied_by = :transport: the scalar is transported by a separate transport (a WENO tracer slot after the dynamics, as in the Berlin case), whose state, velocity and time weight the core's stages do not see. The hook books nothing for it; the transport books exactly the flux it applies, at the state it applies it to, by calling book_nest_flux! (#327, M3). scheme, molecular and sgs are then unused.

θ and a core-transported qv get their models from the simulations; a tracer of the field set (also qv when it is a tracer, as in a moist sound-proof nest) is refluxed only when its owner declares how it is transported, TwoWayFeedback(tracer_fluxes = (:co2 => NestScalarFlux(),)).

Aeolus.Nesting.NestSponge — Type
NestSponge(; width=4, α_max=1.0, profile=:cos2, sides=ntuple(_->true, 6))

Relaxation zone width child cells deep inside the child, adjacent to its nest boundaries. apply_nest_sponge! blends the child solution toward the interpolated parent solution with rate α_max (1/time), ramped by profile (:cos2 — smooth sin² taper — or :linear) from 0 at the inner edge of the zone to α_max at the boundary. sides is (west, east, south, north, bottom, top).

The smooth taper is the point: a hard relaxation edge is itself a reflector. Without a sponge, the halo/interior mismatch at a nest boundary reflects outgoing waves back into the child.

In a NestedRun the velocity relaxation acts on the predicted velocity before the pressure solve, so the child stays divergence-free (#329); see apply_nest_sponge!.

Aeolus.Nesting.NestedGrid — Type
NestedGrid(parent_mesh, child_mesh; refinement, offset)

Geometric description of a child domain embedded in a parent.

  • parent_mesh — a RegularGrid or a z-stretched StretchedGrid (N-nest-b, #256); child_mesh is a RegularGrid.
  • refinement — integer ratio per dimension, Int or NTuple{3,Int} (rx, ry, rz; commonly 2 or 3).
  • offset — (ix, iy, iz), the 1-based interior index of the first parent cell the child covers.

The constructor validates that the child aligns to parent cell boundaries, that child.N is divisible by the refinement, that child.d * r == parent.d, and that the covered box fits inside the parent's interior. Any violation raises a descriptive error.

On a stretched parent the vertical checks use the parent's actual face heights (zfaces) and cell thicknesses (cell_thickness): the child's bottom and top must sit on parent faces and every covered parent layer must be exactly rz child layers thick — an integer number of child layers per parent layer in the overlap, so the overlap is uniform in the parent. The parent may stretch freely above (or below) the overlap; the halo stencils that reach into those layers interpolate on the actual face heights.

Use nested_grid to build the child mesh from a physical extent.

Aeolus.Nesting.NestedRun — Type
NestedRun(parent, child, nest; kwargs...)

A parent and a child simulation coupled through nest (a NestedGrid) and advanced together, one parent step per step_nested!(run). Either domain may be a BoussinesqSimulation or a sound-proof MassWeightedSimulation.

Keywords:

  • advance_parent, advance_child — per-domain DomainAdvance closures (default domain_advance(step!)), each carrying its own hooks and keywords;
  • cfl_parent, cfl_child — CFLConstraints for each domain's adaptive_dt (cfl_child defaults to cfl_parent). cfl_parent = nothing means a fixed step: pass dt to step_nested!. cfl_child = nothing means a fixed number of child substeps, substeps (default max(rx, ry, rz));
  • sync — :subcycle (default): the parent takes its own adaptive step and the child subcycles to land exactly on its end; :shared_min_dt: both domains take one step of the smaller of the two limits (PALM's scheme, Hellsten et al. 2021, §3.1);
  • feedback — :one_way (default; the parent never sees the child), :two_way (the default TwoWayFeedback) or a TwoWayFeedback(…): anterpolation of the child field set onto the covered parent cells outside a buffer zone, an optional relaxation, canopy restriction and inflow exclusion, the interface flux correction on the open faces, Berger–Colella scalar refluxing from flux registers and the re-projection of the parent (N-nest-e, #263);
  • limit_scalars (:positive, for qv and the tracers), limit_theta (:none), limit_momentum (:none) — the limiters of the prolongation (#329), see interpolate_parent_state!;
  • order (3), flux_correction (true), scalars, state — as for the operators of NestInterpState. The run allocates its three field sets (the parent prolongated at both ends of the parent step and their blend) with storage = :shell, halo slabs only, unless it has a sponge, whose target is the child interior (#329);
  • sponge (nothing, the default, as in Kadasch et al. 2021 §2.2–2.3 and Hellsten et al. 2021, which use none) or a NestSponge: relaxation of every member of the field set toward the time-blended parent (at the end of the child substep), on the child's open faces only (nest_open_sides). The velocities are relaxed on the predicted velocity of every stage, in the core's post_predictor! hook, so the pressure solve that follows keeps the child divergence-free; the scalars after each child substep (#329). A user core must call post_predictor! for the velocity part to act;
  • solid (nothing) — the child's IBM SolidMask (or a Bool array). The open faces inside solids are marked with mark_open_boundary_solids!: zero normal and tangential velocity there, left out of the mass-flux correction; and the two-way restriction is solid-aware (restrict_state_to_parent!);
  • max_retries (3), divergence_tol (Inf, parent only, through max_divergence), max_velocity (Inf), validate (true) — the step-rejection test, as in step_adaptive!;
  • reuse_boundary (true) — in one-way runs, take the boundary data at the start of a parent step from the end of the previous one instead of prolongating again (valid as long as nothing but advance_parent changes the parent);
  • record (true) — write the two-way conservation ledger (nest_conservation_error).

Two-way feedback needs parent and child of the same core family (two Boussinesq sims, or two MassWeightedSimulations of one sound-proof system sharing one ReferenceState, whose transfers then use the reference-mass measure nest_measure); a mixed pair can only be nested one-way, and asking for two-way throws an ArgumentError (a Boussinesq/sound-proof pair has no consistent measure: the restriction would weight by volume where the sound-proof grid needs its reference mass, and the flux registers would mix volume and mass fluxes).

Boundary conditions. The child must be built with nest_bcs(child_mesh, …; moisture, scalars) naming the same field set as the run: its nest faces are OpenBoundary faces, and the run attaches a NestBoundaryData to them. Every core then refreshes the child's boundary at its own stage times (update_open_boundaries!), with the parent field set linearly blended in time over the parent step and the single global mass-flux correction of N-open-b, so the child's pressure solve (all-Neumann CosineFFTPoissonSolver) sees the parent's boundary flux. A child without open faces (periodic or walled everywhere) runs, but nothing reaches it from the parent.

The clocks of the two simulations must agree when the run is built (check_clocks = false lets the child keep its own clock origin; it then advances by the parent's Δt_p per step). run.t is the common time, run.stats a NestRunStats.

Aeolus.Nesting.TwoWayFeedback — Type
TwoWayFeedback(; buffer = 2, z_anterp = -Inf, τ = nothing, exclude_width = 0,
               exclude_sides = :inflow, reflux = true, reproject = true,
               tracer_fluxes = (), theta_flux = nothing)

The child → parent feedback of a two-way NestedRun (feedback = TwoWayFeedback(…), or feedback = :two_way for the defaults), applied once per parent step after the child substeps:

  1. Anterpolation (Clark & Farley 1984; Hellsten et al. 2021, §3.5, Eq. 15). A covered parent cell takes the conservative child mean $⟨φ_C⟩$ of θ, qv, the tracers and the velocities: the N-nest-a / N-nest-b restriction (restrict_to_parent!, volume- or reference-mass-weighted, solid-aware). With a relaxation time τ it is relaxed instead,

    φ_P ← φ_P + (Δt_p/τ)(⟨φ_C⟩ − φ_P),

    so a covered-parent deviation decays as $(1 − Δt_p/τ)^n$. τ = nothing (default) is direct replacement, as in PALM, and so is any τ ≤ Δt_p. The relaxation is our extension, not PALM's.

  2. Buffer zone. No anterpolation in the outermost buffer parent cells next to every open (nest) face of the child (PALM's default is 2): there the child's solution is still dominated by its boundary data.

  3. Canopy restriction. Only parent cells whose lower face is at or above z_anterp are anterpolated (PALM leaves the canopy layer out, where the coarse parent cannot represent what the child resolves).

  4. Inflow exclusion. A band of exclude_width parent cells at the child's inflow faces is left out too, so synthetic inflow turbulence (N-inflow-c) is never fed back. exclude_sides = :inflow picks the open faces whose mean normal velocity points into the child at the time of the feedback; a tuple of side names ((:west,)) or an NTuple{6,Bool} (west, east, south, north, bottom, top) fixes them.

  5. Scalar refluxing (Berger & Colella 1989): every parent step and child substep books the flux of θ, qv and the declared tracers through the interface planes (advective, molecular and SGS — exactly the face fluxes the cores used, at every stage with the stage weights of the core) into flux registers; the coarse-minus-fine mismatch is put into the parent cells just outside the nest (apply_flux_correction!). The composite integral $∫φ dV$ ($∫Wφ dV$ for a sound-proof pair) is then conserved to round-off. tracer_fluxes declares the transport of the tracers (name => NestScalarFlux(…); :qv too when it is a tracer of the field set rather than a core prognostic); undeclared tracers are not refluxed. A tracer moved by a separate transport is declared with applied_by = :transport and booked by that transport (book_nest_flux!). theta_flux replaces the model of θ (default: the cores' centred advection, molecular and SGS diffusion) for a user core that transports θ otherwise.

  6. Re-projection of the parent after the feedback, so $∇·u = 0$ holds in the parent again (anterpolated faces next to the buffer and the interface flux correction leave the parent divergent).

The anterpolated velocity faces are those strictly inside the covered region whose two parent cells are both anterpolated; the interface faces themselves get the child's flux from the interface flux correction (flux_correction of the run, on the open faces only).

Refluxing needs a core whose stage structure is known (nest_stage_weights): step! (Boussinesq or sound-proof; one stage), step_rk3! (weights 1/6, 1/6, 2/3), or a user core that declares its weights; the IMEX cores (step_imex!, implicit θ diffusion) are refused with reflux = true. A run whose scalars are all booked by their transports (theta_flux and every tracer_fluxes entry with applied_by = :transport) needs no stage weights: any core runs, as the Berlin case's stage loop does (#267). qv can be declared in tracer_fluxes wherever it is a tracer of at least one domain (a moist Boussinesq parent around a child that carries qv as a tracer). The SGS closure needs a two-point face diffusivity. Exact conservation also needs sponge = nothing (a sponge is a source).

References: Clark, T. L. & Farley, R. D. (1984), J. Atmos. Sci. 41, 329–350; Berger, M. J. & Colella, P. (1989), J. Comput. Phys. 82, 64–84; Hellsten, A. et al. (2021), Geosci. Model Dev. 14, 3185–3214, §3.5 (anterpolation, buffer, canopy) and §4.1 (the spurious secondary circulation of two-way nests in a convective boundary layer).

Aeolus.Nesting._ShellArray — Type
_ShellArray{T} <: AbstractArray{T,3}

A storage-indexed child array (size n, halos included) that stores only its halo shell: lo[d] layers on the low side and hi[d] on the high side of axis d, as six dense slabs (see _shell_boxes). Reading or writing an interior point is an error. Aeolus.Nesting.apply_flux_correction! — Method
apply_flux_correction!(parent_field, mismatch, nest; measure=nothing)          # face field
apply_flux_correction!(parent_field, mismatch, nest; periodic, measure=nothing) # cell-centred

Remove the coarse-fine flux inconsistency recorded in mismatch.

  • face-located parent_field — replace the parent's interface face value with the summed fine flux (u_p -= δΦ / A_p). The parent's transport through the interface then matches the child's exactly.
  • cell-centred parent_field (the Berger-Colella refluxing step, with mismatch built from time-accumulated flux registers) — adjust the parent cells immediately outside the nest: θ ± δΦ·A / V_p. This is what makes the composite integral of a conserved scalar exactly invariant across a nested step. The parent's boundary conditions decide where the cell outside a child face that lies on the parent's own boundary is: along a periodic axis of the parent the index wraps; along a non-periodic one there is no parent cell beyond the face (the flux there is the parent's boundary condition's) and the correction of that plane is dropped (#329: it used to wrap on every axis, so a child touching the parent's top put its top-plane correction into the parent's lowest layer). periodic = (px, py, pz), the parent's periodic axes, is required (#349: it defaulted to (true, true, true), which is wrong for any parent with a wall or an open face and was silently taken by a caller that forgot it). Pass periodic = nest_periodic_axes(parent_sim) to read them from the parent's boundary conditions, as the two-way feedback, reflux_scalars! and the AMR refluxing do.

A_p and V_p use the parent's actual layer thickness (stretched parents). With the mass measure of a sound-proof pair they are the reference mass of the face and cell (W Δz; for the corrected cells, which lie outside the nest, the parent's own W_p Δz_p, see NestMeasure): a face correction then matches the parent's mass flux to the child's, and refluxing with mass-flux registers (Φ = ∫W F dt) preserves the composite ∫ W θ dV. Use the measure the mismatch was computed with (face fields).

Without this correction two-way nesting leaks: the parent kept the coarse flux while the child used the fine ones.

Aeolus.Nesting.apply_nest_boundary! — Method
apply_nest_boundary!(child_sim, state; solid = nothing) -> child_sim

Make the interpolated parent state (a NestInterpState) the steady boundary data of the child's open (nest) faces (nest_boundary_data), refresh the open-boundary buffers with the mass-flux correction, and write them into the child: the boundary faces of the normal velocity, the tangential-velocity halos and the halos of every scalar of the set (θ, qv, tracers). Faces that are not nest faces (periodic, walls) are filled by their own condition. solid (a SolidMask or a Bool array) marks the open faces inside solids (mark_open_boundary_solids!).

A NestedRun does this itself, with the time-blended parent; calling this on a run's child replaces the run's boundary data.

Aeolus.Nesting.apply_nest_sponge! — Method
apply_nest_sponge!(child_sim, parent_interp, sponge; dt=1.0, velocity=true, scalars=true)

Relax the child solution toward parent_interp inside the sponge zone: f ← (1-β) f + β f_parent with β = clamp(α_max·dt·ramp, 0, 1). Applied to every member of the field set: the velocities u, v, w (velocity = true) and the scalars θ, qv, tracers (scalars = true).

The relaxation of the velocity is a source the projection must see: a velocity relaxed after a step is no longer divergence-free (the prolongated parent velocity is flux-consistent on parent cells, not on child cells). A NestedRun therefore relaxes the velocities on the predicted velocity, inside every stage's post_predictor! hook and before the pressure solve, and only the scalars after the step (#329). Aeolus.Nesting.book_nest_flux! — Method
book_nest_flux!(sim, name, ϕ, dt; scheme = nothing, diffusivity = nothing,
                velocity = (sim.u, sim.v, sim.w), weights = :sim, sgs = nothing) -> Bool

Book into the flux registers of the two-way NestedRun that sim belongs to (parent or child) the interface flux that a separate transport of the tracer name (field ϕ, declared TwoWayFeedback(tracer_fluxes = (name => NestScalarFlux(applied_by = :transport),))) applies over the time dt (#327, M3): a transport that moves its tracers outside the core's stages — after the dynamics, with its own scheme, velocity and time step, as the Berlin case's WENO slot does — calls it with the state it is about to apply the flux to, before updating ϕ:

  • scheme (a name of boundary_scalar_flux or a reconstruction; nothing for no advection) books the advective flux u_n ϕ_f with the transport's velocity (halos as the transport filled them), and the volume flux that carried it (volume-consistent refluxing);
  • diffusivity = (ν = …, κh = …, κv = …, scale = 1) books the diffusive flux −(ν + s·½(κ_L + κ_R)) ∂ϕ/∂n (κh on the lateral, κv on the vertical planes: cell-centred fields, halos filled), the face form of add_eddy_diffusion_scalar!. A Lie-split transport that diffuses after advecting calls it a second time with the advected ϕ;
  • diffusivity = :theta or :tracer books the diffusive flux the core gives the scalar inside its stages — molecular ν (when the simulation has viscosity) plus the domain closure's θ diffusivity (:theta) or tracer diffusivity (:tracer, as for qv), the closure being sgs or the simulation's own — exactly what the run's hook books for a core-transported scalar. Both are formed by the one face kernel scalar_face_flux and weighted by the simulation's constraint weights W (weights = :sim; nothing for none; a tuple (Wc, Wf) of storage-indexed vectors to override) — the ∫ W ϕ the composite conserves. A multi-stage transport calls it once per stage with dt times the stage weight.

Bookings land in the step being attempted and are discarded with it if the step is rejected. Returns false (and books nothing) when sim is in no refluxing two-way run, name is not declared with applied_by = :transport, or no step of sim's domain is under way — so a transport can call it unconditionally.

Aeolus.Nesting.interpolate_to_nest_boundary! — Method
interpolate_to_nest_boundary!(child_field, parent_field, nest; order=3,
                              impose_interface=false)

Fill every halo cell of child_field (faces, edges and corners) by conservative order-order interpolation of parent_field. The rule used in each direction follows the field's Location:

  • cell-centred scalars — conservative in all three directions, so the child sub-cell averages sum back to the parent average exactly;
  • FaceX/FaceY/FaceZ velocities — nodal (point-value) in their own direction and conservative in the two tangential directions. That is what preserves the flux: the summed fine-face fluxes through a parent face equal the parent flux, and a child face coincident with a parent face reproduces the parent value exactly.

parent_field's halos must already be filled. With impose_interface=true the child's boundary-normal interior face plane (e.g. i = Hx+1 for FaceX) is also overwritten with the parent value, i.e. a Dirichlet inflow face.

On a z-stretched parent the vertical stencils use the parent's actual face heights. measure (a NestMeasure) selects the vertical measure; with the mass measure of a sound-proof pair (nest_measure) the conservative directions conserve ∫ W φ dV (W = ρ̄ or ρ̄θ̄) instead of ∫ φ dV. The default is the volume measure.

limiter (#329): the 3rd- and 5th-order reconstructions overshoot at a sharp front — a negative qv or tracer next to a dry or clean parent cell. For a cell-centred field the children of every parent cell are scaled about the parent value, which keeps the prolongation conservative (the children's mean is the parent value):

  • :positive (Zhang & Shu 2010, J. Comput. Phys. 229, 3091) — no child below zero where the parent cell is non-negative; inactive away from zero, so a smooth positive field keeps the full order. For quantities that cannot be negative (qv, tracer concentrations): a signed field crossing zero inside a parent cell would be clipped;
  • :monotone (Barth & Jespersen 1989, AIAA paper 89-0366) — no child outside the range of its parent cell and the 26 neighbours: no new extrema at a front, but smooth extrema are clipped to second order;
  • :none (default of this low-level operator; the field set of a NestedRun limits qv and the tracers with :positive, see interpolate_parent_state!).

A velocity takes :none or :monotone, a clip to the range of the parent values its stencil reads (monotone, but not flux-preserving). Where no child overshoots, the values are unchanged bit for bit.

The thermodynamic constants must agree exactly (an error is raised otherwise).

Aeolus.Nesting.reflux! — Method
reflux!(parent_field, parent_registers, child_registers, nest; periodic,
        measure=nothing)

Berger & Colella (1989) refluxing of one cell-centred scalar. parent_registers and child_registers are (Φx, Φy, Φz): the time-integrated advective+diffusive fluxes Φ = ∫ F dt (field value × length) on the parent and child faces over one parent step. The coarse-minus-fine mismatch on the six interface planes is booked into the parent cells just outside the nest (periodic, required: the parent's periodic axes, e.g. nest_periodic_axes(parent_sim), see apply_flux_correction!), so the composite integral (composite_integral) of the scalar is unchanged by the nest to round-off.

With the mass measure of a sound-proof pair the registers are mass fluxes (Φ = ∫ W F dt) and the correction is divided by the parent cell's reference mass, so the composite ∫ W φ dV is unchanged.

Reference: Berger, M. J. & Colella, P. (1989), J. Comput. Phys. 82, 64–84, §3 (the flux-register correction).

Aeolus.Nesting.restrict_state_to_parent! — Function
restrict_state_to_parent!(parent_sim, child_sim, nest, state=nothing; solid=nothing)

Conservative restriction of the whole field set, child → parent: θ and every bound scalar of state (qv, tracers) by volume-weighted averaging, and u, v, w by area-weighted averaging on the faces strictly inside the nest (the interface planes belong to apply_flux_correction!). Without a state only u, v, w, θ are restricted.

Selected by dispatch: for a MassWeightedSimulation pair the averages are weighted by the shared reference mass (ρ̄ or ρ̄θ̄, see restrict_to_parent!). solid (the child's IBM SolidMask or a Boolean solid array) makes every member solid-aware: building cells and faces are left out of the averages. A mixed Boussinesq / sound-proof pair throws an ArgumentError (no consistent measure, #327).

Aeolus.Nesting.restrict_to_parent! — Method
restrict_to_parent!(parent_field, child_field, nest; measure=nothing, solid=nothing)
restrict_to_parent!(parent_face_field, child_face_field, nest;
                    include_boundary=false, measure=nothing, solid=nothing)

Conservative restriction.

  • CellCenter — volume-weighted average of the rx·ry·rz child cells inside each covered parent cell. Since V_parent = rx·ry·rz · V_child in the (uniform) overlap, ∫ over the overlap is preserved to machine precision.
  • FaceX/FaceY/FaceZ — area-weighted average of the r·r child faces covering each aligned parent face, i.e. flux-preserving. By default only faces strictly inside the nest are overwritten; the two interface planes are owned by the flux correction (apply_flux_correction!). Pass include_boundary=true to overwrite them as well.

measure — with the mass measure of a sound-proof pair (nest_measure) the averages are weighted by the child cell mass W Δz (W = ρ̄ anelastic, ρ̄θ̄ pseudo-incompressible): a scalar becomes Σ W φ ΔV / Σ W ΔV, so ∫ W φ dV is preserved, and a horizontal-normal velocity (u, v) becomes Σ W u A / Σ W A, so the parent face carries the child's summed mass flux. w faces are horizontal planes at one height, where W is common to all r·r children and cancels: the plain area mean is already the mass-flux mean.

solid — the child's IBM SolidMask (or a storage-sized Boolean array, true = solid, such as the Berlin solid field) makes the restriction solid-aware (Hellsten et al. 2021, GMD 14, 3185, §3.5): only fluid child cells, and only fluid child faces (both neighbouring cells fluid), enter the average, so no parent value is ever averaged from the zero velocity inside a building. A parent cell or face with no fluid child keeps its value. The fluid-weighted integral Σ_fluid W φ ΔV is what is preserved.

Aeolus.Nesting.stage_times — Method
stage_times(adv::DomainAdvance) -> NTuple

The times, as fractions cᵢ of the step Δt, at which adv's core evaluates its tendencies, i.e. the times at which it reads the boundary data in the halos: (0,) for the projection step (step!, Boussinesq or sound-proof) and for a user core, (0, 1, 1/2) for SSP-RK3 (Shu & Osher 1988), (0, γ) for ARK2 and (0, a₂₁) for Rosenbrock2. Aeolus.Nesting.step_nested! — Method
step_nested!(run::NestedRun; dt = nothing) -> run

Advance run by one parent step:

  1. the parent step Δt_p is adaptive_dt(parent) (or dt; under sync = :shared_min_dt the smaller of the two domains' limits);
  2. the parent field set is prolongated onto the child at t_p (in a one-way run, reused from the end of the previous step);
  3. the parent takes its step. A rejected parent step (non-finite state, exception, divergence_tol, max_velocity) is rolled back and retried with Δt_p/2 — before any child substep. Only a numerical failure (is_numerical_failure) is rejected; any other exception (a MethodError, a BoundsError, …) propagates at once;
  4. the parent field set is prolongated at t_p + Δt_p;
  5. the child subcycles to land exactly on t_p + Δt_p: n = ⌈Δt_p / Δt_c^max⌉ substeps, re-evaluated before every substep as n_rem = max(n_rem, ⌈R/Δt_c^max⌉) with Δt_c = R / n_rem (R the remaining time; the last substep takes exactly R). The child's open faces hold the linearly interpolated, mass-corrected boundary data at every stage time of its core (stage_times, boundary_time, NestBoundaryData). A rejected child substep rolls back only the child (its StateSnapshot, its bound scalars and its SGS memory); the rejected piece is redone at half its size and the remaining time is re-divided;
  6. two-way: the feedback of the run's TwoWayFeedback (two_way_feedback!): anterpolation, interface flux correction, scalar refluxing from the flux registers booked at every stage of the parent step and the child substeps, re-projection.

The child clock is set to the parent's at the end (the discrepancy it had is recorded in run.stats.max_clock_error).

Aeolus.Nesting.step_nested! — Method
step_nested!(parent_sim, child_sim, nest, dt; substeps=nothing, order=3,
             flux_correction=true, sponge=nothing, solid=nothing,
             scalars=(), state=nothing, record=true,
             feedback=TwoWayFeedback())

One two-way parent step of fixed size dt plus substeps equal child steps (default max(rx,ry,rz), which keeps the child CFL equal to the parent's), both with step! and no hooks. A thin wrapper over step_nested!(::NestedRun): it builds a NestedRun with feedback = :two_way, fixed steps and no step validation, and takes one step. Use a NestedRun directly for adaptive steps, hooks, other dynamical cores or one-way nesting.

The transferred field set is u, v, w, θ, qv when both simulations are moist, and the extra cell-centred scalars (:co2 => (child_field, parent_field), …); see NestInterpState. The child's open faces (nest_bcs) hold the parent state linearly interpolated in time to the child's stage times; after the child substeps the child field set is fed back onto the parent with feedback (a TwoWayFeedback: anterpolation outside the buffer zone, interface flux correction, scalar refluxing, re-projection). Conservation diagnostics for :mass, :momentum_x and every scalar of the set are recorded in nest.ledger; read them with nest_conservation_error. Returns (parent_sim, child_sim).

state may be a pre-allocated NTuple{3,NestInterpState} (built with nest_interp_state(nest, parent_sim, child_sim; scalars)) to avoid re-allocating the boundary buffers every step; it then defines the field set and scalars is ignored.

The parent may be z-stretched (a BoussinesqSimulation on a StretchedGrid). Both sims may instead be MassWeightedSimulations sharing one ReferenceState profile: every transfer then uses the reference-mass measure (nest_measure) and the ledger records ∫ W φ dV. solid (the child's IBM mask) makes the restriction solid-aware.

Aeolus.Nesting.subcycle_dt — Method
subcycle_dt(remaining, limit) -> dt

The next child substep of a parent-step window with remaining seconds left, for a child whose own step limit is limit: remaining / n, n = ⌈remaining / limit⌉ (a ratio that is an integer up to 1e-9 relative is not rounded up), so the substeps land exactly on the window end. The rule step_nested!'s subcycling re-evaluates before every substep; a caller that drives the child itself (begin_parent_step!) uses it to pick its steps.

Aeolus.Nesting.two_way_feedback! — Method
two_way_feedback!(run::NestedRun) -> run

Apply the child → parent feedback of a two-way run now (what step_nested!(run) does once per parent step, after the child substeps), as configured by the run's TwoWayFeedback:

  1. anterpolate! the field set onto the cells of feedback_mask(run), relaxed with α = min(1, Δt_p/τ) (Δt_p the last parent step) and solid-aware with the run's solid;
  2. correct the parent's velocity on the interface planes of the child's open faces to the child's flux (flux_correction);
  3. reflux θ, qv and the declared tracers from the flux registers booked since the last feedback, and clear them. What is refluxed is the flux of ϕ − ϕ_ref, ϕ_ref the parent's mean of ϕ over the covered cells (one constant per scalar): the two grids are each volume-conserving, but their time-integrated volume fluxes through a face patch differ (the child's boundary velocity is interpolated in time, the parent's is its stage velocity), and the flux of ϕ itself would book ϕ × that volume mismatch — for θ ≈ 300 K a spurious heating of the cells outside the nest by up to kelvins per step. The volume mismatches of the patches sum to zero over the closed interface (both velocity fields are divergence-free), so the total correction, and with it the exact conservation of the composite ∫ϕ dV, is the same for every ϕ_ref;
  4. re-project the parent.

The interface mass-flux imbalance is written to the ledger before the flux correction (:mass_before_correction), after it (:mass, round-off) and after the re-projection (:mass_after_projection: the projection moves the parent's interface faces too, by the divergence that the anterpolation next to the buffer zone and the flux correction left in the parent; the next step's child boundary data take the projected parent).
