Urban site

Aeolus.Urban (EX-a #438; on the model since ONE-e #454; a component of its domain since ONE-k #474, formerly Aeolus.UrbanCase) is the urban site of the model: a 3-D LES of a city window whose buildings and land use come from a static input driver, whose initial state and boundary forcing come from a sounding, a dynamic input driver or an online Aeolus nest parent, and whose urban physics is a set of components of the domain's stage pipeline (one file per component under src/components/urban/; Components). A model config with [urban] enabled = true is an urban site: one section per urban slot names its provider ([sgs] model = "tke", [pressure] solver = "cosine_fft", [chemistry] scheme = "none"; URBAN_SLOT_SECTIONS, ONE-m #476) and holds that provider's options, and the additive components' sections enable them.

The site is a Model of one domain like any other: the UrbanSite is the domain's first component (it holds the site's shared state: options, geometry, surface bus, tracers, budgets and reference state), every enabled urban component follows it, and the site's :timestepper component takes the core step. step!(model) advances it; aeolus run runs it with the model's run loop, output writer, checkpoints and checks. There is no case object and no run loop of its own (ONE-k, #474).

The Berlin (Alexanderplatz) case is configuration only: examples/urban/berlin_*.toml, its static drivers (input/*_static.nc: the OpenStreetMap buildings and the parent's land-use tiles), its dynamic driver (input/berlin_20190629_dynamic.nc: the Lindenberg sounding) and the source data in examples/urban/data/.

Running it

configwhat runsoutput (run folder)

Every file is complete (no extends, ONE-b #451): with [[domain]] blocks each domain carries all its sections. The site's options are site_options(cfg), read from the resolved config; they change in the TOML file or with --set. The options are on Run configuration: the urban site.

julia --project -m Aeolus run examples/urban/berlin_summer.toml --set time.nsteps=1800
julia --project -m Aeolus run examples/urban/berlin_smoke.toml
julia --project -m Aeolus run examples/urban/berlin_parent.toml

From Julia (tests, the bitwise harnesses), Config.build(...).model builds the nest (build_case(site_options(cfg)) a site alone) and Components.run_to!(model, t_end) runs it as the run loop does, without output, monitor and checkpoints.

Output

The run's writer (Aeolus.Output) writes the variables [output] variables selects from the domain's catalogue: the core's (u, v, w, p, theta, their profiles and means) and the site's (Components.outputs of the site: the local hour and the solar_elevation as time series, every output tracer, the surface maps Ts, sw_in, lw_in, and every enabled component's fields), plus the site's static geometry (sky-view factor, building height, surface class) once. The Berlin configurations list what the flagship's renderers read.

The run's own checks: results.toml

Every run of an urban site writes output/results.toml: a finite state, the surface-energy budget per class, the water residual of the air and the air-heat closure, each against BUDGET_TOLERANCES ([budgets] closed), every air-heat term in W m⁻² of ground, the heat carried in through the open or nest faces, the mean θ of the lowest 100 m at the start and the end, and the wall time per simulated hour (the site's Components.run_results), with the checks [checks] enables. A run whose budgets do not close logs a warning; the run itself is failed only by a required check (urban_budgets).

Analysis of the output

The scripts left in examples/urban/ read run output only: alexanderplatz_animation.jl and alexanderplatz_surface_diagnostics.jl (the NetCDF of a berlin_summer.toml run), berlin_parent_figures.jl, berlin_parent_lindenberg_check.jl and plot_parent_surface.jl (the output folder of a run of the parent alone, read by parent_output.jl). test/urban_run.jl checks that no script there builds or runs the model.

Aeolus.Urban.ANALYSIS_BUFFER_DEFAULT — Constant
ANALYSIS_BUFFER_DEFAULT

The default cfg.analysis_buffer (m): 140 m, the canopy-top inflow fetch of the Alexanderplatz child estimated from the rule N-inflow-d (#266) measured: behind a digital-filter inflow the turbulence recovers to 10 % in 1.2 local eddy-turnover distances, $L = 1.2\,U k/ε$ (6.6δ at 0.22δ and 12.3δ at 0.47δ of the half channel, docs/src/theory/transition.md). With the neutral surface-layer values $U = (u_*/κ)\ln((z-d)/z_0)$, $k = 5.48u_*^2$ (Panofsky & Dutton 1984: σ{u,v,w} = 2.39, 1.92, 1.25 u) and ``ε = u_^3/(κ(z-d))$this is$L = 6.58\,(z-d)\ln((z-d)/z0)$, independent of$u``; at the mean roof height of the flagship scene (h = 21.6 m, λp = 0.223, λf = 0.151; Macdonald et al. 1998: d = 9.6 m, z_0 = 2.0 m) L = 141 m. (At 100 m the same rule gives 2.3 km, more than the child: there the child keeps what the generator and the parent give it.) The Berlin fetch measured on the nested child, day and night (#268 step 2), replaces it when the 24 h runs are made (#270). Macdonald, R. W., Griffiths, R. F. & Hall, D. J. (1998), *Atmos. Environ. 32, 1857-1864.

Aeolus.Urban.AQChem — Type
AQChem

Slot :chemistry, provider :aq_chem (default; [chemistry] scheme = "aq_chem", ONE-m #476; formerly :nox_o3_voc). Every step in :chemistry:

  1. emissions into the first air cell of each column (k_air, above the roof on building columns): traffic NOx on street and building-adjacent columns, isoprene on park columns;
  2. apply_photochemistry! on the whole domain;
  3. dry deposition apply_dry_deposition! of NO, NO2, O3 and HNO3 from the first air cell with $v_d = 1/(r_a + r_b + r_c)$;
  4. wet deposition apply_wet_deposition! of HNO3 by the rain qr (the other species are too insoluble).

The species are registered tracers (advect = true), so the :transport stage moves them. In :surface_update, on the surface cadence, $r_a = 1/(C_H U)$ and $u_*$ are recomputed per column from solve_surface_layer (first-air-cell wind and θ, surface skin Ts) and the deposition velocities with them.

Aeolus.Urban.AdaptiveStep — Type
AdaptiveStep

Slot :timestepper, provider :adaptive (default): TimeIntegration.adaptive_dt picks each step (CFLConstraints from the options C_advective, C_diffusive, C_buoyancy, C_coriolis, dt_min, dt_max, growth_max) and step_adaptive! takes it, rolling back and halving on failure (max_retries, divergence_tol, max_velocity). With imex = true the dynamics is step_imex!(…, ARK2()) and the step is limited only by the explicitly treated processes.

Each step (and each retried piece) is step! — or step_imex! — with the numerics slots' case.step_kwargs. The diffusive limit is computed from the selected SGS closure's νt and κt of the current flow (with the stress form, sgs_stress = :symmetric, the momentum part uses 2νt, the bound of `stressformcflviscosity), and the closure's memory is snapshot / restored bystep_adaptive!` around a rejected step, so it commits exactly once per accepted piece.

dt_max is further capped at the shortest period in cfg.cadence, so a step never skips a firing of a cadence (the soil and building couplings integrate over their period). A run goes to the simulated time nsteps · cfg.dt rather than a number of steps; the first step grows from cfg.dt (at most growth_max · cfg.dt).

Aeolus.Urban.BoussinesqCore — Type
BoussinesqCore

Slot :core, provider :boussinesq (default): the dry Boussinesq core of Aeolus.Simulations built by boussinesq_core (buoyancy about the constant cfg.θ₀, advanced by step!).

Aeolus.Urban.Cadence — Type
Cadence(period; first = false)
Cadence(key::Symbol; first = false)

When a stage entry runs. period is in seconds: the entry fires on the step that crosses a multiple of it, floor(t_new/P) > floor(t_old/P), and on step 1 as well when first = true. period ≤ 0 means every step. The Symbol form names a period in cfg.cadence (e.g. :radiation), resolved when the case is built.

With a fixed dt that divides P this is exactly n % (P/dt) == 0, and it keeps working when dt changes from step to step.

Aeolus.Urban.CaseReference — Type
CaseReference

Hydrostatic reference state of a case (see site/reference_state.jl).

  • p̄, ρ̄, θ̄, T̄, π̄ — cell-centred profiles, length Nz (Pa, kg m⁻³, K, K, 1), copied from state so that couplings see concrete vectors;
  • state — the Aeolus.Anelastic.ReferenceState itself (face profiles, max_hydrostatic_residual);
  • p_surface — pressure at the ground (the bottom wall face), Pa;
  • cp — the specific heat of dry air the conversions use, J kg⁻¹ K⁻¹.

Accessors: ref_pressure, ref_density, ref_exner, surface_pressure, ref_ρcp, ref_θ_per_heat.

Aeolus.Urban.CityMeanBuildings — Type
CityMeanBuildings

Slot :buildings, provider :citymean. The CityBuildings state is built from the scene at init!; at the :radiation cadence (after the radiosity, which it needs for the wall irradiance) the zone is advanced over the radiation interval against the mean first-layer air of the open columns; every step, in :sources, its release goes into θ and qv and the window sun on the walls leaves the surface budget (apply_building_heat!).

Aeolus.Urban.Clock — Type
Clock

Step counter and time state of a site: n (steps taken), hour (local hour of day at the start of the current step), sun (the solar position of the last radiation update), blowup (set by the sanity check of the :budgets stage), nrecord (output frames logged: the :output cadence), t_wall0 (wall-clock start of the run) and the run's horizon, set by the run loop for its length (Components.run_begin!, ONE-k #474): a step starts at time t exactly when t_stop - t > stop_margin (t_stop = NaN: unknown, a caller steps the site itself). A coupling that works ahead of the child (the nest's prefetched parent step, SC-c #403) does so only for steps that will run. n0, t0, θ_start and t_first are the run's start (its step count, model time, mean θ below RESULTS_LAYER) and the wall clock at the end of its first step, for run_results.

Aeolus.Urban.CloudShadow — Type
CloudShadow

Additive coupling. At the :radiation cadence (and step 1), right after the radiosity solve:

  1. the per-cell cloud optical depth τ = k·ρ·q·Δz from ql (and qi, if a coupling registered it), with the RadiationCore mass extinction for effective radii r_eff_liq, r_eff_ice (the same as the column radiation's cloud optics) and the density profile of the column radiation; zero in solid cells;
  2. delta-scaled (TwoStream.delta_scale, with the single-scattering albedo and asymmetry of the Mie liquid cloud in the visible), so the forward-scattered peak stays in the beam, as in the two-stream solve;
  3. the direct-beam transmittance T[i, j] along the slant path toward the sun, from the top of each column's solid stack (cloud_shadow_transmittance! with k_start);
  4. bus.sw ← bus.sw · (1 − f_dir·(1 − T)), where f_dir is the share of the column's absorbed shortwave that arrived as direct beam in the radiosity solution.

It runs at the radiation cadence, like the radiosity solve whose beam it attenuates, so it cannot compound between updates. The optical-depth field and the per-column rays are launches on the case's backend (KA-n, #305): pointwise, so identical at every thread count.

Known limitations: interreflections of the shaded beam and the window sun the buildings take from the radiosity solution are not attenuated; the diffuse light the cloud scatters sideways is not added (the column radiation's diffuse is the clear-LES one).

Aeolus.Urban.ColumnRadiation — Type
ColumnRadiation

Slot :column_radiation, provider :twostream (default): the ColumnRadiationModel m of Aeolus.ColumnRadiation on the case's domain-mean column, and ghi_bird, the Bird clear-sky GHI of the radiosity coupling's sky (for the log).

At the :radiation cadence (and step 1), before the radiosity solve:

  1. the fluid-cell mean profiles of θ, qv and ql on the LES levels become a hydrostatic column (column_from_profiles, surface pressure surface_pressure(case) of the reference state), which is stitched (stitch_columns) under us_standard_column (nz_upper layers to 30 km, its surface temperature chosen so that it matches the LES top temperature, the humidity profile of the scenario's season);
  2. the surface is the domain: radiative temperature (Σε Ts⁴ / Σε)^{1/4} of the columns, mean emissivity, and the effective albedo of the last radiosity solve (class-mean albedo before the first one);
  3. correlated-k gas optics (correlated_k_optics) plus Mie cloud optics (mie_cloud_optics, r_eff_liq) → solve_lw! and, with the sun up, solve_sw!, scaled by the Earth–Sun distance factor; all through the multi-column forms (KA-n, #305: optics τ[k, g, column], one work item per layer for the optics and per g-point for the solves) on one column;
  4. bus.L_sky = downwelling longwave at the surface; bus.dni, bus.dhi = direct-normal and diffuse shortwave at the surface of the same column with the LES condensate removed; heat = the LES-layer heating rate (K/s) from the net-flux divergence with cloud.

Every step (:column_tendency) θ += heat·dt/Π̄k on every LES level (heat is dT/dt and T = θΠ̄; the same 1/(ρ̄cpΠ̄) as ref_θ_per_heat with ρ̄cp already divided out), in the fluid cells only (`Radiation.applyradiative_cooling!` with the solid mask): the heating rate is a property of the air, and heating the immersed buildings' cells leaks into the air next to the walls.

Aeolus.Urban.SurfaceExchangeMOST — Type
SurfaceExchangeMOST

Slot :surface_exchange, provider :most (default).

  • Surfaces. At init!, one AbstractSurface per column that has air above it, from the factory of its class (register_surface_factory!) or, for a class without one, a SlabLand (C_s, albedo, emissivity from bus.params; β = 1 on water, 0 elsewhere; roughness from the options).

  • Air level. bus.k_air is the first non-solid level of each column, so roof fluxes go into the air above the roof. The forcing height is the centre of that cell above the surface, z_ref = Δz/2; the air temperature and pressure are $T = θ\,\bar Π_k$ and $\bar p_k$ of the case's reference state (#131), the conversion every other coupling uses.

  • Cadence. The surfaces are stepped every period seconds (cfg.cadence[:surface] if present, otherwise cfg.cadence[:soil]): on step 1 in :surface_flux, then in :surface_update on the step at which the air reaches the time the surfaces were advanced to. Each surface step covers the next period seconds, and the air receives its fluxes for exactly that long, so the air gets what the surface gave away. With a fixed dt dividing period that is every step's dt. With a variable dt (the adaptive time stepper, #133) a step can run past the end of a surface interval: it delivers the held fluxes only up to that end, and the time beyond it is delivered with the next surface step's fluxes, which cover it (dt ≤ period is assumed; the adaptive stepper caps dt at the shortest cadence).

  • Air side, every step in :surface_flux: $Δθ = H\,τ/(\bar ρ_k c_p \bar Π_k Δz)$ (ref_θ_per_heat), $Δq_v = E\,τ/(\bar ρ_k Δz)$ in the first air cell, τ the air time this step delivers ($τ = Δt$ with a fixed step), with $\bar ρ_k$ and $\bar Π_k$ the reference density and Exner function of that level (case.ref, the state the ledgers integrate with) and $c_p$ the moist heat capacity of that air. The air-heat ledger weights θ with the dry $c_{pd}$, so it books this heating as $H τ\, c_{pd}/c_p$, about 0.8 % below $H τ$ at $q_v ≈ 0.01$.

  • Momentum, every step in :post_predictor (after the IBM): the ground is a wall of Aeolus.WallModels. Every surface step sets, per column, a MOSTWallLaw with the column's z0m and the Obukhov length L of that step (matching_obukhov_length: the L for which the law gives back the step's $u_*$); apply_wall_stress! then applies its stress over the k_air level mask, implicitly (each first-air-cell face multiplied by $1/(1 + Δt\,τ_w/(U\,Δz))$, stable for any Δt), along the resolved wind; a face between two columns gets the mean of the two columns' stresses (a column contributes only at its own air level). The law is evaluated every step at the instantaneous first-air-cell wind (L held from the surface step), and bus.u_star is that step's $u_τ$ (before #169 the stress $u_*^2/U$ of the surface step was held between surface steps).

  • Wall-model input (P57-b, #183; WallModels.MatchingInput): the wind the law is evaluated at is the first-air-cell wind passed through the exponential time filter of Yang, Park & Moin (2017), time scale input_T_f (default 10 s, the order of the eddy time $z_{ref}/u_*$ of the 6.25 m first cell in a daytime wind; 0 switches it off), advanced once per accepted step in :surface_update. The stress keeps the direction of the instantaneous first-cell wind. The matching height stays at the first air cell (h_wm_cells = 1): three cells above a street (18.75 m) lie in or above the canyon, where no log law holds. h_wm_cells = n samples the n-th air cell ($(n-½)Δz$) of the columns whose class is in h_wm_classes (default park and water, the open surfaces; a column whose n-th cell is not air falls back to its first) — a smoke variant.

  • Non-equilibrium wall model (P57-c, #189; option wall_model = :nonequilibrium, default :equilibrium): the ground stress is that of a WallModels.TBLEWallModel instead of the MOSTWallLaw — the thin-boundary-layer equations on a 30-point column under every ground and roof column, between the surface (u = 0, the column's own z0m, rough-wall eddy viscosity $κu_τ(y + z_{0m})$) and the matching point of the same MatchingInput (time-filtered wind), with the pressure gradient of the resolved p at the first air level (one-sided next to a building) and the terms of tble_terms (default :pressure_gradient). The columns' stress is applied by the same apply_wall_stress! face loop in :post_predictor; the columns are advanced once per step in :surface_update; bus.u_star is their $u_τ$ (set again after a surface step, whose MOST $u_*$ stays internal to its heat and moisture fluxes). Neutral: the Monin–Obukhov stability correction of the equilibrium law is not carried into the TBLE (its eddy viscosity has no buoyancy term until P58). The surface-layer heat and moisture fluxes are unchanged (MOST). A smoke variant runs it.

  • Extra energy. bus.sensible (energy other couplings take from the surfaces, W m⁻²) is collected every step in :surface_update and handed to the surfaces as Q_extra at their next step.

  • Maximum sustainable heat flux (P58-e, #193), every surface step: per column, SurfaceExchange.surface_mshf_ratio of the MOST fluxes of the skin at the start of the step (turbulent_fluxes), one 1-D maximisation at the column's wind, z_ref, z0m and $θ_{va}$ (Van de Wiel et al. 2012). H_max (W m⁻²) and the ratio of the downward buoyancy flux to the MSHF are output fields; the diagnostics give the mean ratio of the stable street, roof and park columns and the share of them beyond the MSHF point ($z_{ref}/L$ past the peak of the flux curve: the very stable, collapsed branch); the smoke check asserts ratio ≤ 1 + 1e-8 everywhere (and < 1.1 for the fluxes the surface returned, which a soil skin linearises in $T_{skin}$).

  • Dynamic roughness (P57-e, #190; option z0m = :dynamic, off by default): the ground wall law's momentum roughness becomes the dynamic roughness of Anderson & Meneveau (2011), WallModels.DynamicRoughness: $z_0 = \sqrt{z_{0,f}^2 + α^2σ_Δ^2}$, $σ_Δ$ the RMS of the OSM building heights below the grid — the footprints rasterised on a grid dynamic_refine times finer, with their true heights, about the immersed-boundary staircase the LES resolves ($(k_{air}-1)Δz$), i.e. the staircase loss — and $z_{0,f}$ each column's own roughness (the per-class table, which stays the roughness of the surface-layer solve, so H, LE and the Obukhov length are unchanged). α is solved at every surface step (the period cadence, not every step) from the first-air-cell wind, test filter dynamic_filter (:spectral, default, or :box), resolved-relief drag coefficient dynamic_C_d. The default stays the table: the dynamic value's Berlin calibration has not been reviewed, and with buildings resolved at 15.6 m the sub-filter relief is only staircase loss. A smoke variant.

Options: U_min (m s⁻¹, the minimum wind of the surface-layer solve), z0m (per class, m; or :dynamic, above), z0h_ratio ($z_{0h} = z_{0m}$·ratio), period (s, overrides the cadence), wall_formulation (:local, default; :schumann or :moeng, the plane-mean forms of apply_wall_stress!, over all ground and roof columns), input_T_f (s, the time filter of the wall-model input; 0 = off), h_wm_cells and h_wm_classes (the matching height of the open columns), wall_model (:equilibrium or :nonequilibrium) and tble_terms (:pressure_gradient, :full or :equilibrium_ode), dynamic_refine, dynamic_filter, dynamic_C_d (the dynamic roughness).

                     window = 8, blending = nothing,
                     macdonald = (;)) -> ParentSurface

Build the parent's tiled surface.

  • case — the class-to-surface factory: a built urban site (its registry's class_surface, per-class parameters, roughness table and initial temperatures, cfg.Ts0, water + cfg.Ts_water_offset) or the TileClasses of a tiled surface's own options.
  • child — the urban site whose class map fills the parent under its footprint (parent_fractions): case when it is a site (the tests of #249), else nothing, the land use everywhere (a domain's static driver holds the child's classes under its footprint).
  • columns — :all, or the CartesianIndexes / a CartesianIndices range of the columns to build (the whole parent is 36 864 columns of up to six tiles; building only a subset is how the tests stay cheap).
  • z_centres — the parent's level centres (m above ground; default the uniform Δz = 25 m of the maintainer's grid; only the lowest levels are looked at).
  • window — the morphometry window (parent_morphometry).
  • blending — nothing for a plain SurfaceMosaic per column (each tile forced at its own level, measured from its own displacement; see ParentColumn), or an AbstractBlendingHeight for a BlendedMosaic, whose tiles are forced at the blending height (one forcing per column, at the column level above the area-mean displacement).
  • macdonald — keyword overrides for SurfaceTiles.macdonald_roughness (A, β, C_D, κ).
  • unresolved = false switches the unresolved-building treatment off (every tile with its class's own roughness, d = 0, forced at the first level): the parent is then the class-weighted mean of the child's surfaces, which the tests use as a control.

Each tile is class_surface(case, SurfaceSite(c; T_skin, z0m, z0h)). A built tile takes z0m = max(z0_Macdonald, class z0m) but keeps its class's scalar roughness z0h: the form drag of the buildings raises the momentum exchange, and heat has no pressure-drag analogue — the transfer of heat from bluff obstacles stays governed by their facets, which is why urban arrays have large $kB^{-1} = \ln(z_{0m}/z_{0h})$ (Kanda et al. 2007). Inheriting $z_{0h} = 0.1 z_{0m}$ from the child's ratio instead puts the parent's footprint-mean sensible heat flux +8.8 % above the child's at 13:00 and +9.8 % over 06-18 h (+2.8 % and +3.8 % with the class z0h; offline run of test 4 of #249). Park and water tiles keep both of their own roughness lengths.

Reference: Kanda, M., Kanega, M., Kawai, T., Moriwaki, R. & Sugawara, H. (2007). Roughness lengths for momentum and heat derived from outdoor urban scale models. J. Appl. Meteorol. Climatol., 46, 1067-1079.

A coupling's wall-clock diagnostic, declared as wall.<x> and prefixed by collect_diagnostics to <coupling>.wall.<x>, renamed wall.<coupling>.<x>: every wall-clock column of the files starts with wall, as the stage timing and the CSV's own wall column, so a comparison of two runs that must agree bit for bit drops them all by the prefix. Any other diagnostic is returned as it is.

Aeolus.Urban.write_sounding_driver — Method
write_sounding_driver(cfg, path; preprocessor) -> path

The sounding driver of the case cfg at path (CFG-g, #362): the tables of case_dynamic_inputs, cfg.sounding hashed as the source and preprocessor recorded. For an open, non-nested case (cfg.lateral === :open, no nesting coupling) also the steady planes of its profile boundary data on its faces, one time_bc record at t = 0, taken from the CSV in memory (cfg.dynamic is ignored: the file being written is not read). The one writer of a sounding driver: AeolusPrep.jl's aeolusprep dynamic --from-sounding and the tests call it.

Aeolus.Urban.θ_top_bc — Method
θ_top_bc(cfg) -> AbstractBC

The θ boundary condition of the top face for cfg.θ_top: FluxBC(Γ) with Γ = θ_top_gradient(cfg) for :initial_gradient, NoFlux() for :noflux, FluxBC(x) for a number x (K/m).

Aeolus.Urban.θ_top_gradient — Method
θ_top_gradient(cfg; H = cfg.extent[3], dz = H / cfg.size[3]) -> K/m

∂θ/∂z of the initial profile initial_θ of cfg at the top face, as the centred difference across it, (θ(z_top + Δz/2) − θ(z_top − Δz/2))/Δz, the difference the ghost cell of a FluxBC top reproduces (exact for the piecewise-linear profile of the case when the inversion is below the top level). H and dz (the top and the thickness of the top cell) default to the child's grid; the nesting parent (#259) passes its own 3 km top and top-cell thickness.
