I/O, checkpoints and restart

Aeolus.IO holds the run's persistence: field snapshots for output, full-state, versioned checkpoints from which a run continues bit for bit (#245), periodic checkpoints with automatic resume for long drivers, and TOML namelists. The design (what a checkpoint must contain, why the FFT planner matters, what is not covered yet) is on the design page Checkpoint / restart and FFT planning.

Quick reference

using Aeolus, Random

sim = BoussinesqSimulation(mesh; θ₀ = 300.0, bcs = bcs)
c   = TKEClosure(mesh); initialize_tke!(c, sim)
st  = StepperState(:adaptive)
cfl = CFLConstraints(; dt_max = 5.0)

for _ in 1:100
    _, dt, nr = step_adaptive!(sim, cfl; dt_prev = previous_dt(st), sgs = c)
    record_step!(st, dt; retries = nr)
end
checkpoint!(sim, "run/ckpt.jls"; sgs = c, stepper = st, rng = Random.default_rng(),
            extra = Dict(:note => "after 100 steps"))

# … in another process, with the run built the same way:
restart!(sim2, "run/ckpt.jls"; sgs = c2, stepper = st2, rng = Random.default_rng())
read_checkpoint("run/ckpt.jls")[:extra][:note]

A wall-modelled channel is checkpointed through its case harness, one component that carries the closure memory, the wall model (TBLE columns, input filters), the dynamic roughness and the counters:

checkpoint!(case.sim, path; components = (case = case,))
restart!(case2.sim, path; components = (case = case2,))

A long driver hands its run loop a CheckpointSchedule: built before the simulation (it loads the folder's FFTW wisdom), resumed after it, checked after every step:

ck = CheckpointSchedule("run"; every_steps = 500, every_seconds = 1800, keep = 2)
sim = …; series = Float64[]
resume!(ck, sim; sgs = c, stepper = st, components = (series = series,))
while st.step < nsteps
    step_rk3!(sim, dt; sgs = c); record_step!(st, dt); push!(series, kinetic_energy(sim))
    maybe_checkpoint!(ck, sim; step = st.step, sgs = c, stepper = st,
                      components = (series = series,))
end

run_channel! (WallModels) and the SBL driver's sbl_run! take the schedule as their checkpoint keyword; dns256_generate.jl, the relaminarisation driver and gabls1–gabls4.jl use it by default (driver_checkpoints: every 30 min of wall clock, AEOLUS_CHECKPOINT=0 / _EVERY / _SECONDS / _KEEP override).

A production run keeps its log, provenance, output and checkpoints in a run folder, runs/<date>_<case>_<runID>/ (start_run, with_run, run_checkpoints; #334). It refuses to start on uncommitted code unless allow_uncommitted = true; a restart reuses the folder and keeps the run ID. See Run folder and provenance on the Logging page.

checkpoint! is write_checkpoint of checkpoint_payload, the in-memory checkpoint. A BlowupGuard keeps the last good state of a run as such a payload and, when the run blows up, writes it as the crash checkpoint crash/crash_<step>.jls, which restart! continues from like any other (#335; see Blowup on the Logging page).

FFT planning policy

The planner of every FFT plan is set in one place, Aeolus.Operators.set_fftw_policy! (planner = :estimate | :measure | :patient | :exhaustive, threads), default :measure (:patient opt-in), or from the environment (AEOLUS_FFTW_PLANNER, AEOLUS_FFTW_THREADS) or a namelist [fftw] table (apply_fftw_config!). fftw_policy() reports the planner, the thread count, whether wisdom was loaded and whether the run is bitwise reproducible; every checkpoint records it, and save_fftw_wisdom / load_fftw_wisdom! keep a restart on the same plans. The suite runs with AEOLUS_FFTW_PLANNER=estimate. These functions are documented with Operators.

Namelist tables

The [fftw] and [checkpoint] tables are sections of the run configuration (Run configuration, CFG-a #356): checkpoint_schedule(load_run_config("case.toml"), dir) applies the [fftw] section and returns the schedule of the [checkpoint] section. An untyped namelist from load_config still works, with dir read from its [checkpoint] table and the missing keys taking the schema defaults:

[fftw]
planner = "measure"        # estimate | measure (default) | patient | exhaustive
threads = 4
wisdom  = "run/fftw_wisdom"

[checkpoint]
dir           = "run"
every_steps   = 500
every_seconds = 1800.0
keep          = 2

Reference

Aeolus.IO.CHECKPOINT_FORMAT — Constant

Format tag stored under :format in every checkpoint.

Aeolus.IO.CHECKPOINT_VERSION — Constant
CHECKPOINT_VERSION

The checkpoint format version this build writes (and the newest it reads). Version 1 (#245): full state — fields with halos, closure memory, named components, stepper, RNG, FFTW provenance. Files without a version (the pre-#245 checkpoint! / write_snapshot output) are refused by restart!.

Aeolus.IO.BlowupError — Type
BlowupError <: Exception

The error that stops a blown-up run (check_blowup!, guarded_step!): step and t of the failure, fields (the NonFiniteFields; empty when the state stayed finite and a step threw), cause (the exception a step threw, or nothing), checkpoint (the crash checkpoint's path, or "" when none was written), checkpoint_step and checkpoint_t (the state it holds), and diagnostics (the last diagnostics, see last_diagnostics).

Aeolus.IO.BlowupGuard — Type
BlowupGuard(sim; every_steps = 10, dir = nothing, sgs = nothing, components = (;),
            stepper = nothing, rng = nothing, diagnostics = nothing,
            prefix = "crash")

Blowup handling of a run (epic #293: diagnose, dump, stop).

  • Check. check_blowup!(guard, sim; step) inspects blowup_fields for non-finite values every every_steps steps (and whenever forced). A state that passes is kept as the last good state: an in-memory checkpoint_payload with the closure memory sgs, the components, the stepper and the rng (the same keywords as checkpoint!).
  • Diagnose. On a non-finite value, or when the step run by guarded_step! throws, it logs an Error record (subsystem = :blowup) naming each non-finite field with its count and the position of its first bad value, the step and time, the cause, and the last diagnostics of diagnostics (a DiagnosticsWriter).
  • Dump. It writes the crash checkpoint dir/<prefix>_<step>.jls of the last good state: the current state if it is still finite (a step that threw after step_adaptive! restored its start), else the last state that passed a check. restart! continues from it like from any checkpoint. With dir = nothing (or for a simulation checkpoint! does not cover) nothing is written, and the diagnosis says so.
  • Stop. It throws a BlowupError with all of the above.

Cost: the check reads every value of the inspected fields once (allfinite), a snapshot copies them into the previous snapshot's buffers; on a 64×64×32 case 0.12 ms and 0.26 ms, so 0.04 ms per step at the default every_steps = 10 (0.4 % of an 8.6 ms step; benchmarks/bench_run_monitor.jl).

Aeolus.IO.CheckpointSchedule — Type
CheckpointSchedule(dir; every_steps = 0, every_seconds = Inf, keep = 2,
                   prefix = "checkpoint", wisdom = true)

Periodic checkpoints of a long run in the folder dir, with automatic resume — the one helper the long drivers (dns256_generate.jl, the relaminarisation and SBL drivers) hook into:

  1. Construct it first, before the simulation: it creates dir and, with wisdom = true, imports the FFTW wisdom dir/fftw_wisdom if a previous (interrupted) run left one, so the new process makes the same FFT plans (load_fftw_wisdom!).
  2. Build the run, then call resume!(ck, sim; …): it saves the FFTW wisdom at run start (if dir has none yet) and, if dir holds a checkpoint, restores the newest one (restart!) and returns its payload (nothing on a fresh start).
  3. After every step, maybe_checkpoint!(ck, sim; step, …) writes dir/<prefix>_<step>.jls when every_steps steps or every_seconds of wall clock have passed since the last one, and deletes all but the newest keep.

The fresh start or resume (with the FFTW provenance) and every checkpoint written are Debug events (subsystem = :checkpoint, see the Logging page): a run log records them, the default console does not, and inside with_run the restart itself is announced at Info by the run header. The [checkpoint] table of a TOML namelist builds one with checkpoint_schedule.

Aeolus.IO.NonFiniteField — Type
NonFiniteField

One field of a blown-up state (nonfinite_fields): name, count (non-finite interior values), nan and inf (how many of each), index (the interior (i, j, k) of the first one in memory order), position (its coordinates in m at the field's own staggered location; NaN where the mesh does not say) and size (the interior size).

Aeolus.IO.RunFolder — Type
RunFolder

A run's folder and provenance record, made by start_run: path, run_id, case, session (1 for the first start, n for the (n-1)-th restart), logger (the run log, to install with Logging.with_logger; see with_run), record (the contents of run.toml) and finished. Paths inside it: run_log_path, run_toml_path, diagnostics_path, output_dir, checkpoint_dir.

Aeolus.IO.RunMonitor — Type
RunMonitor(sim; run = nothing, components = (;), diagnostics = nothing,
           t_end = nothing, t_start = sim.t, cadence = 60.0,
           progress_every = 10.0, csv = …, check_every = 10, crash = …,
           sgs = nothing, checkpoint_components = (;), stepper = nothing,
           rng = nothing)

Everything a run reports, behind one call per step, monitor!:

  • the diagnostics diagnostics (default: collect_diagnostics(sim, components)) written to the CSV csv (default: the run folder's diagnostics_path when run is a RunFolder, else no file), the costly ones every cadence simulated seconds;
  • the progress line towards t_end (none when t_end = nothing), at most every progress_every wall seconds;
  • the blowup guard (BlowupGuard): a check every check_every steps, crash checkpoints in crash (default: the run folder's crash/, else none) of the state with sgs, checkpoint_components, stepper and rng, as checkpoint! takes them.

close(m) flushes and closes the CSV. with_monitor does that and feeds the warnings to the progress line.

Aeolus.IO.StepperState — Type
StepperState(scheme = :fixed; keep = 16)

The time stepper's own state across steps, checkpointed with the run: scheme (a label: :euler, :rk3, :imex, :adaptive, …), step (accepted steps so far), dt_prev (the last accepted dt, NaN before the first step), retries (total rejected tries of step_adaptive!) and dt_history (the last keep accepted dts). The adaptive controller's input is dt_prev: pass previous_dt(st) as step_adaptive!'s dt_prev and record each step with record_step!, so a restarted run limits its first dt's growth exactly as the continuous run did.

The fixed-dt cores (step!, step_rk3!, step_imex!) keep no state between steps beyond the simulation and the closure: for them the stepper state is only the step count.

Aeolus.IO.allfinite — Method
allfinite(a) -> Bool

Whether every value of a is finite. Branch-free (x * 0 is 0 for a finite x and NaN otherwise, summed with @simd along the contiguous first dimension), so the healthy case, the one the blowup check pays for every time, vectorises; about 10× faster than all(isfinite, a) on an interior view.

Aeolus.IO.blowup! — Method
blowup!(guard, sim; step, fields = nonfinite_fields(sim), cause = nothing)

Diagnose, dump and stop: log the diagnosis, write the crash checkpoint, throw the BlowupError. check_blowup! and guarded_step! call it; a driver with its own failure detection may too.

Aeolus.IO.blowup_fields — Method
blowup_fields(sim) -> NamedTuple of Fields

The fields the blowup check inspects: for a BoussinesqSimulation its checkpoint_fields (u, v, w, p, θ, qv, νt, κt); for any other simulation those of u, v, w, p, θ, qv it has.

Aeolus.IO.check_blowup! — Method
check_blowup!(guard, sim; step, force = false) -> Bool

If every_steps steps have passed since the last check (or force), inspect sim: a healthy state becomes the last good state and false is returned; a non-finite one is diagnosed, dumped and stopped (see BlowupGuard): this throws a BlowupError. Returns false without looking when no check is due.

Aeolus.IO.check_restart_config — Method
check_restart_config(config, record; allow_changed_inputs = false)

Called by start_run before a restart writes anything: nothing for a plain object; for a RunConfig, a ConfigError names every input file whose content changed since the run started.

Aeolus.IO.checkpoint! — Method
checkpoint!(sim, path; sgs = nothing, components = (;), stepper = nothing,
            rng = nothing, extra = Dict()) -> path

Write a full-state, versioned checkpoint of a run to path (format CHECKPOINT_VERSION), from which restart! continues the run bit for bit:

  • the fields of checkpoint_fields with their halos, and sim.t;
  • sgs: the closure the run steps with (an AbstractSGSClosure, or a legacy f(νt, u, v, w) function, stateless) — its memory via checkpoint_state, i.e. the closure contract's sgs_state;
  • components: a NamedTuple (or Dict) of any other stateful objects — wall models, input filters, a WallBoundedCase, a driver's accumulators — each through checkpoint_state; restored by name;
  • stepper: a StepperState; rng: an AbstractRNG the run draws from (e.g. Random.default_rng());
  • extra: free-form serialisable metadata (a driver's series, tags);
  • provenance: format and version, Julia version, the mesh, the run's scalar parameters, and the FFTW policy (fftw_policy: planner, threads, wisdom loaded, bitwise reproducible).

The file is written to path * ".tmp" and renamed, so an interrupted write never leaves a truncated checkpoint under path. The format is Julia's Serialization: portable across machines with the same Julia version (recorded; a mismatch warns on restart).

Aeolus.IO.checkpoint_dir — Method

path/checkpoints, the folder of the run's checkpoints and FFTW wisdom (created).

Aeolus.IO.checkpoint_due — Method
checkpoint_due(ck::CheckpointSchedule, step) -> Bool

Whether maybe_checkpoint! would write at step: every_steps steps or every_seconds of wall clock since the last checkpoint (or the run start).

Aeolus.IO.checkpoint_fields — Method
checkpoint_fields(sim) -> NamedTuple of Fields

The fields of sim a checkpoint stores with their halos: the prognostic u, v, w, p, θ, qv and the eddy coefficients of the last evaluation νt, κt (a step's CFL estimate or a driver's dt choice may read them before the closure recomputes them). Tendencies and scratch buffers are rewritten before they are read in every step and are not stored.

Aeolus.IO.checkpoint_path — Method

dir/<prefix>_<step, 9 digits>.jls: the checkpoint of step step.

Aeolus.IO.checkpoint_payload — Method
checkpoint_payload(sim; sgs = nothing, components = (;), stepper = nothing,
                   rng = nothing, extra = Dict(), buffers = nothing) -> Dict{Symbol,Any}

The in-memory checkpoint that checkpoint! writes: everything it lists, self-contained (the field data and every component state are copies, nothing is aliased to the run). write_checkpoint puts it on disk. The blowup guard (#335) holds the last good state of a run this way and writes it as the crash checkpoint. buffers, the :fields of an earlier payload of the same simulation, are reused for the field copies (no allocation); they then belong to the new payload.

Aeolus.IO.checkpoint_state — Method
checkpoint_state(x) -> state
restore_checkpoint_state!(x, state) -> x

The generic pair through which a stateful component of a run is checkpointed: checkpoint_state returns a self-contained, serialisable copy of everything of x that the run's next step reads (plain arrays, numbers, tuples, named tuples, dicts of them — nothing aliased to x), and restore_checkpoint_state! copies such a state back into an x built the same way, in this or another process.

Methods shipped:

componentstate
nothingnothing
any AbstractSGSClosurea deep copy of sgs_state (the closure contract, #167)
AbstractRNG (including the task-local default)copy(rng)
StepperStateits fields
Field, Arraya copy of the data
Vector, Dict, Base.RefValue (a driver's accumulators)a deep copy of the contents
NamedTuple, Tupleelement-wise
WallModels: MatchingInput, WallModel, TBLEWallModel, DynamicRoughness, WallBoundedCasesee src/wall_models/checkpoint.jl

Anything else throws a MethodError-like ArgumentError naming the type: add the two methods for it (for a mutable struct, fieldwise_checkpoint_state does the work). The Berlin case's own state (soil, buildings, tracers, surface bus, radiation) is not covered yet (#269 / #134): its hook is exactly this pair, one method per coupling state, collected as the components of checkpoint!.

config_record(config) -> Dict{String,Any}

The top-level entries run.toml records for config: for any object, config as toml_value gives it. A RunConfig (Aeolus.Config) adds its canonical table, schema version, hash, sources, input-file hashes and replayability.

Aeolus.IO.driver_checkpoints — Method
driver_checkpoints(dir; every_steps = 0, every_seconds = 1800, keep = 2,
                   prefix = "checkpoint") -> Union{Nothing, CheckpointSchedule}

The CheckpointSchedule of a long example driver: on by default (every 30 min of wall clock, the newest 2 kept), overridden by the environment so every driver is controlled the same way:

variableeffect
AEOLUS_CHECKPOINT=0no checkpoints (returns nothing)
AEOLUS_CHECKPOINT_EVERY=nevery n steps
AEOLUS_CHECKPOINT_SECONDS=severy s s of wall clock (Inf: off)
AEOLUS_CHECKPOINT_KEEP=kkeep the newest k

Call it before building the run (it imports the run folder's FFTW wisdom), then hand it to the driver's run loop; finish_checkpoints! removes the folder once the driver has stored its result.

Aeolus.IO.fieldwise_checkpoint_state — Method
fieldwise_checkpoint_state(x, names) -> NamedTuple
restore_fieldwise!(x, state) -> x

Helpers for a mutable struct's checkpoint_state / restore_checkpoint_state!: the state is a deep copy of the fields names; restoring copies arrays in place (copyto!, sizes must match) and sets every other field (setfield!).

Aeolus.IO.checkpoint_state(c::MyCase) = fieldwise_checkpoint_state(c, (:nsteps, :flux, :acc))
Aeolus.IO.restore_checkpoint_state!(c::MyCase, s) = restore_fieldwise!(c, s)
Aeolus.IO.finish_checkpoints! — Method
finish_checkpoints!(ck) -> nothing

Delete the checkpoints (every prefix) and the FFTW wisdom of the folder of ck, and the folder if it is then empty: call it once the driver has stored the run's result, so a later run starts fresh. nothing is accepted (checkpointing off).

Aeolus.IO.finish_run! — Method
finish_run!(rf::RunFolder; status = :completed, error = nothing) -> RunFolder

End the session of rf: record ended, status (:completed, :failed, :interrupted, …), wall_seconds and, if given, the error message in run.toml; log the end (subsystem = :run, event = :finish; at Info when completed, else Error); close the run log. A second call does nothing.

Aeolus.IO.fnv1a64 — Method
fnv1a64(data) -> UInt64

The 64-bit FNV-1a hash of data (bytes or a string). Used for the Manifest hash in the provenance: a stable, dependency-free fingerprint (not a cryptographic hash). fnv1a64("") == 0xcbf29ce484222325.

Aeolus.IO.git_state — Function
git_state(repo = aeolus_source_dir(); exclude = String[]) -> NamedTuple

The state of the git checkout containing repo: available (git is installed and repo is in a work tree), toplevel, commit (full hash, "" if unavailable), branch, dirty and changes, the lines of git status --porcelain (staged, unstaged and untracked files; ignored files do not count). Paths under any of exclude (absolute) are left out, so a run folder inside the work tree does not make it dirty.

Aeolus.IO.guarded_step! — Method
guarded_step!(f, guard, sim; step) -> f()

Run one step f() under the guard: if it throws (anything but an InterruptException), the run is diagnosed, dumped and stopped with a BlowupError whose cause is the exception. Otherwise the regular check_blowup! follows, on its cadence: a non-finite value is caught at the next due check (step_adaptive! already rejects a non-finite step itself, and throws when its retries run out).

guard = BlowupGuard(sim; dir = "crash", sgs = closure, stepper = st)
for n in 1:nsteps
    guarded_step!(guard, sim; step = n) do
        step_adaptive!(sim, cfl; sgs = closure)
    end
end

The most recently created run folder of case under root (by the created_unix time of its run.toml, compared as a number; ties are broken by the run.toml modification time, then the folder name), or nothing.

Aeolus.IO.monitor! — Method

After step step (which took dt, limited by limiter, with retries rejected attempts): the blowup check (on its cadence; a blowup throws a BlowupError after the diagnosis and the crash checkpoint), a diagnostics row, and the progress line when due.

Aeolus.IO.monitored_step! — Method
monitored_step!(f, m::RunMonitor, sim; step, limiter = "") -> f()

with_run("cbl"; config = cfg) do rf
    with_monitor(sim; run = rf, t_end = 3600.0, components = (; sgs = closure)) do m
        dt = nothing
        for n in 1:nsteps
            _, dt, _ = monitored_step!(m, sim; step = n) do
                step_adaptive!(sim, cfl; dt_prev = dt, sgs = closure)
            end
        end
    end

Aeolus.IO.restart! — Method
restart!(sim, path; sgs = nothing, components = (;), stepper = nothing,
         rng = nothing, allow_mismatch = false) -> sim

Restore a run from a checkpoint written by checkpoint!: sim must be built exactly as the checkpointed one (same mesh — checked —, boundary conditions, physics), and sgs, components, stepper, rng must be the same kinds of objects the checkpoint was written with (the closure's type and the component names are checked). Copies the fields with their halos, the clock, the closure memory and every component's state back; the next step then equals the continuous run's bit for bit (given the same FFT plans: see fftw_policy).

Run parameters. The scalar parameters of sim (ν, θ₀, g_accel, f_coriolis, C_s, Pr_t, the surface fluxes, the sponge, the enable flags) are compared with the checkpoint's. A difference throws an ArgumentError listing every differing parameter with both values: a restart with other parameters is a different experiment, not a continuation. Pass allow_mismatch = true to restart anyway (a deliberate change, e.g. a new sponge); the differences are then logged with @warn.

Refuses unversioned snapshots (see read_checkpoint). To read the checkpoint's extra or provenance, use read_checkpoint.

Aeolus.IO.start_run — Method
start_run(case; root = "runs", config = Dict(), seeds = Dict(), resume = nothing,
          allow_uncommitted = ENV["AEOLUS_ALLOW_UNCOMMITTED"] == "1",
          repo = aeolus_source_dir(), console = stderr,
          console_level = AEOLUS_LOG or Info, file_level = Debug,
          flush_interval = 5.0, allow_changed_inputs = false,
          run_id = nothing) -> RunFolder

With config a RunConfig (Aeolus.Config, CFG-a #356), root, allow_uncommitted, the log levels and flush_interval default to its [run] and [logging] sections (keywords given explicitly win), and a restart refuses to start when an input file recorded under [inputs] changed, unless allow_changed_inputs = true.

Start a run that writes a run folder (epic #293, #334):

  1. Code check. If the git work tree containing repo (the Aeolus source tree by default) has uncommitted changes, staged, unstaged or untracked, throw UncommittedCodeError, unless allow_uncommitted = true: then git diff HEAD is saved as uncommitted-<session>.diff and the untracked files are listed in untracked-<session>.txt in the folder, and a warning is logged. Files under root are ignored, so the run folders do not count. If repo is not in a git work tree (an installed release), the run starts and the provenance records git.available = false.
  2. Folder. A new run creates root/<yyyy-mm-dd>_<case>_<runID>/ with a fresh 8-hex-digit run ID (from the OS entropy source; the global RNG is untouched). resume = folder (or resume = :latest, the newest folder of case under root, see latest_run) reuses an existing folder: same run ID, the log is appended and run.toml gets a new session.
  3. Provenance. run.toml holds run_id, case, created, the full config and seeds (any object; see toml_value; a RunConfig is stored in its canonical resolved form with config_schema_version, config_hash, config_sources, [inputs] and replayable, see config_record) and one [[session]] table per start or restart: kind ("start" or "restart"), started, ended, status, wall_seconds and everything provenance returns (git commit, Julia and package versions with the Manifest hash, host, threads, command line, FFTW planner, threads and wisdom, AEOLUS_* variables). A restart whose config, seeds or commit differ from the first session logs a warning and records the new values in its session.
  4. Run log. logger is open_run_log(run.log; console, console_level, file_level): info to the console, debug to run.log. The header is logged through it: one Info record (subsystem = :run, event = :start or :restart) with the run ID, folder, commit, versions, host, threads and FFTW policy, and one Debug record (only run.log keeps it) with the whole session record and the config.

Call finish_run! at the end, or use with_run, which does both and installs the logger.

Aeolus.IO.with_run — Method
with_run(f, case; kwargs...) -> f(rf)

start_run(case; kwargs...), then call f(rf) with the run log installed as the current logger, then finish_run!. If f throws, the error and its backtrace are logged, the session is recorded as failed (or interrupted) and the error is rethrown.

with_run("gabls1"; config = cfg, seeds = (; noise = 42)) do rf
    ck = run_checkpoints(rf; every_steps = 500)
    resume!(ck, sim)
    for n in ck.last_step+1:nsteps
        step_adaptive!(sim, cfl)
        maybe_checkpoint!(ck, sim; step = n)
    end
end

Aeolus.IO.write_snapshot — Method
write_snapshot(path, sim; extra = Dict())

Serialize the interior of sim.u, sim.v, sim.w, sim.p, sim.θ, sim.qv plus the scalar time / clock to path. The extra dict is copied into the snapshot for user-defined metadata (dt, step number, tags, …). Round-trips through read_snapshot.

A snapshot is output, not a restart file: it has no closure memory, halos or stepper state, and restart! refuses it. Use checkpoint! to continue a run.
