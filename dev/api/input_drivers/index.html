Input drivers

Aeolus.InputDrivers (CFG-f, #361) holds Aeolus's own input drivers: NetCDF-4 files with what a run reads from outside the model. The first is the static driver: terrain, buildings, surface classes and leaf area on the run's own horizontal grid, plus the building and patch polygons. The second is the dynamic driver (CFG-g, #362): the initial state, the boundary planes of the open faces over time, and the large-scale and surface forcing. There is no PALM (PIDS) compatibility goal: the names are Aeolus's own, with CF attributes.

Who writes a driver

Aeolus keeps the readers, the writers and the format schemas (this module). Everything that creates a driver from outside data is the separate package AeolusPrep.jl (ONE-h, #457; the single-model design, One model): OpenStreetMap and GeoJSON footprints, the nest parent's land-use classification, soundings, ERA5 (GRIB2 or NetCDF), and the downloads of those sources. It depends on Aeolus for the writers, so a file is written by the code that defines and checks its format, and the model itself never reads OpenStreetMap, GIS or reanalysis files (and does not depend on GRIBDatasets).

# in an AeolusPrep.jl checkout
julia --project -m AeolusPrep static <aeolus>/examples/urban/berlin_summer.toml \
      --source data/berlin/alexanderplatz_real.osm --min-height 8 --park-lai 2.5
julia --project -m AeolusPrep dynamic --from-sounding <aeolus>/examples/urban/berlin_summer.toml
julia --project -m AeolusPrep dynamic --from-era5 data/era5/era5_lindenberg_20190629_*.nc \
      --config <aeolus>/examples/lindenberg_era5/lindenberg_era5.toml --lat 52.2085 --lon 14.118
julia --project -m AeolusPrep regenerate <aeolus> --check     # every committed driver, reproduced?

aeolusprep static reads the run's grid and anchor from the Aeolus config and the source and its options (--source, --min-height, --park-lai) from the command line; for an urban site nested in a parent [[domain]] with a tiled surface it also writes that domain's static_driver from the land-use table --landuse (the site's own classes under its footprint, NEST-p3 #483), and for a tiled domain alone (the nest parent alone) its tiles from --landuse. Every driver committed to Aeolus (examples/**/input/, test/data/**/input/) is listed with its command and options in AeolusPrep's recipes.toml, and its tests regenerate each one: every data variable bit for bit, every global attribute but date_created and aeolus_commit equal. The exceptions are the case-table drivers of the SBL configs (examples/sbl/input/), written once by the former sbl run type's writer and committed here since ONE-g (#456) removed it; AeolusPrep lists them as not made by it, and test/input_dynamic.jl checks them against the case tables. A source recorded relative to its driver must exist (test/input_static.jl): check_driver skips the staleness check of a source it cannot find, which a moved driver would otherwise switch off silently (#487). The parent-made driver of an offline nest is model output, not a preprocessor (below).

An Aeolus change that AeolusPrep follows runs its tests. AeolusPrep calls the config (load_run_config, [run] legacy, [urban] enabled, the domain's static_driver and dynamic_driver), this module's writers and schemas, the urban site's options and writers (Urban.site_options, write_sounding_driver, the nest parent's tiles), the simulation's mesh and open faces, and the layout of examples/<case>/. A PR that changes any of these, or a committed driver, runs julia bin/test-against <this checkout> in an AeolusPrep.jl checkout and quotes the result (Contributing).

Conventions

Shared with the dynamic driver (CFG-g). Every driver carries the global attributes of DRIVER_ATTRIBUTES: aeolus_driver ("static"), aeolus_form, aeolus_schema_version (1), the anchor origin_lat, origin_lon and where it lies in the run's mesh coordinates (origin_x, origin_y), projection = "equirectangular" (latlon_to_meters, the one implementation; sub-metre over the ≤ 5 km of an LES domain), the grid spacing dx, dy, and the provenance: source (relative to the driver's directory when the source lies in the same package; in another package "<Package>:<path in it>", e.g. "AeolusPrep:data/berlin/alexanderplatz_real.osm", which does not depend on where the packages are checked out), source_fnv1a64, preprocessor (e.g. "aeolusprep static"), aeolus_commit and date_created. Variables have CF units, long_name and, where CF has one, standard_name.

No resampling. read_static_driver errors, naming both grids, if the file's x, y, dx, dy or anchor differ from the run's. The preprocessor is re-run for another grid (aeolusprep static).

Checks. A DriverSchema is a declarative table of variables (name, dims, type, units, required, valid range). check_driver returns every problem of a file against it: wrong kind or form, a schema version other than 1, a missing attribute or required variable, wrong dimensions, type or units, values out of range, and a source_fnv1a64 that no longer matches the source file (a stale driver). The tables below are generated from the schemas.

The static driver, resolved form

Dimensions x, y are the cell centres of the run's horizontal grid. The polygons are CF contiguous ragged arrays: building_nvertex counts each building's vertices in building_x, building_y; the rings of a polygon with holes (a courtyard, a multipolygon relation) are each closed and followed by a NaN vertex, the convention of point_in_polygon. The surface-class code table (SURFACE_CLASSES) is stored as the CF flag_values and flag_meanings of surface_class.

The rasters do not depend on the run's lateral boundaries: a run applies its building-free frame (the columns next to an open face take ground_class and no building) and its wall tagging (solid_and_classes), so one file serves a periodic and a nested run on the same grid. Terrain is written as zt = 0: no preprocessor reads elevation yet, and the Berlin case refuses a driver with terrain. There are no vegetation_type, soil_type or water_type rasters yet: no preprocessor has a source for them and no run reads them, so they would be written and never used. Schema version 2 adds them with the first reader that needs them. ground_class (the surface class with the buildings removed) is stored instead: the building-free frame of a nested run and the leaf area under a removed building need it.

Times. Every time coordinate is in seconds since the global attribute init_time (ISO-8601 UTC, the model start; "" for a case without a calendar date, the SBL configs), with CF units = "seconds since …".

Initial state. Profiles over init_z, or 3-D fields on the run grid (init_u3d, …: the interior cells in storage order, u at the cell's west face, v at its south face, w at its bottom face), and init_p_surface. An ERA5 driver (below) fills the init_* profiles and the surface series, and the simulation driver's [initial] dynamic reads the profiles; no case reads the surface series yet. A sounding driver has no init_* profiles: the Berlin case reads its ls_profile_* tables and init_p_surface and evaluates the tables at its start time itself (the bilinear (height, time) interpolation between the two launches that bracket the start), which is bitwise the CSV path (test/input_dynamic.jl).

Large-scale forcing. Each ls_<name> table has its own height and time coordinates (ls_<name>_z, ls_<name>_time, or the shared time_bc of a parent-made driver; the schema's * dimensions). No table is resampled onto a common grid, so a sounding's or a case's ForcingTable round-trips value for value. dynamic_forcing maps the tables onto LargeScaleForcing: ls_u_g/ls_v_g the geostrophic wind, ls_*_adv AdvectiveTendencies, ls_w_subs Subsidence (global attributes subsidence_fields, subsidence_form), ls_nudge_* ProfileNudging (global attribute nudging_tau). ls_profile_* are the large-scale mean profiles: a sounding's tables, or a nest parent's mean over the child (the sponge and θ-relaxation targets). The surface series are sfc_temperature and sfc_pressure over time_sfc.

Initial soil (#521). init_soil_t (K) and init_soil_m (m³ m⁻³) are PALM's PIDS variables, on the coordinate zsoil. That coordinate is the levels' centres in m below the surface: positive down and strictly increasing.

  • Shape. Each variable is a profile over zsoil, or a volume over (x, y, zsoil) on the run's horizontal grid. The schema's alt_dims lets a variable take either shape.
  • Fill values. NaN (the _FillValue) marks a level or a column without data.
  • The writer. AeolusPrep.jl's ERA5 soil writes them from ERA5's four layers (stl1–4, swvl1–4; centres 0.035, 0.175, 0.64 and 1.945 m), appended to the sounding driver. Columns that are not land are NaN.
  • What reads them. The urban site's ground starts from them ([ground] soil_init, GroundSoil), and so do the nest parent's soil tiles.

Boundary planes. For each open face and each field with data, bc_<face>_<var> over (…_i, …_j, …_k, time_bc) holds the child's buffer slab: the storage points of the OpenPlane, the face plane plus the H halo layers (attributes field, side, i0, j0, k0, halo_mode). Slabs, not 3-D fields: a record of the 16³ smoke child holds the five faces only. FileBoundaryData is the generic two-snapshot WindowedBoundaryData with a FileSnapshot, one time_bc record whose snapshot_values is a slab-backed 3-D view (SlabArray): the time blend is the existing blend_window!, the one kernel of the nest, with no second interpolation. The blend reads each plane from the one slab that holds its whole box, found once per plane (blend_source, #529), not point by point through the view. A FileBoundaryFeed holds two records and moves the window (feed_window!, advance_feed!), reading the one record it does not hold. Measured (test/input_dynamic.jl): over 1000 records Base.summarysize of the feed stays at two records plus the time axes; data linear in time, u = 1 + 0.01 t at time_bc = 0, 60, 120 s, is reproduced at t = 17, 60, 95 s to within 1 ulp; data quadratic in time has a blend error of exactly the bound Δt²/8 · max|u''| at the window midpoints. A face the run has open but the file lacks, a slab at other storage indices (another grid or halo), a run interval the records do not cover (check_coverage, both intervals printed) and a file on another grid are errors.

Sounding and case-table drivers

sounding_dynamic_inputs holds a radiosonde sounding's height-time tables (ls_profile_theta, _qv, _u, _v, _p, the union of the launches' level heights up to the table top) on the "seconds since inittime" axis and the ground pressure reduced from the launch site ([`surfacepressureat`](@ref Aeolus.InputDrivers.surfacepressureat)). [`forcingdynamicinputs`](@ref Aeolus.InputDrivers.forcingdynamicinputs) holds the ForcingTables of a case's forcing (GABLS, CASES-99); a number stays in the case's config. The committed drivers of the SBL configurations (`examples/sbl/input/*dynamic.nc: GABLS2 and CASES-99 the surface θ series and the subsidence, GABLS3 the geostrophic wind, the advective tendencies and the 0.25 m θ series, GABLS4 the surface θ series) were written from the case tables by the formersblrun type (ONE-g, #456). The model reads the large-scale tables generically: the[largescaleforcing]component (ug = "driver",advectivetendencies,subsidence,nudging; [dynamicforcing`](@ref Aeolus.InputDrivers.dynamicforcing)) and the [surface] model = "most" temperature = {kind = "driver"}, the times read at the model time minus [time] start; a driver with no initial profiles initialises nothing (the profiles stay in [initial]).

The parent-made driver

NestBoundaryRecorder is an in-run writer (model output: [output] child_boundaries): at every parent step it appends one record, the values every child plane reads from the prolongated parent state (exactly the points blend_window! reads online), the parent time, the step the parent took (time_bc_step) and the parent's mean profiles over the child; it also writes the child's 3-D initial wind. Recording every parent step, rather than extracting from 3-D output at output cadence, is what makes the offline child bitwise the online one: both blend the same Float64 snapshots over the same windows.

ERA5 drivers

AeolusPrep's ERA5 preprocessor (CFG-h #363, shared with #57) reads ERA5 as the CDS delivers it, GRIB2 or NetCDF, on pressure or model levels, and writes the init_* profiles and init_p_surface, the boundary planes of the run's open faces (one time_bc record per ERA5 time), the ls_profile_* tables, ls_u_g/ls_v_g (centred differences of Φ over ±box), ls_w_subs (from ω), ls_theta_adv/ls_qv_adv and the surface series; heights Φ/g₀ above the ERA5 orography, θ from MoistThermodynamics.potential_temperature, bilinear in lat/lon about the anchor (meters_to_latlon, the inverse of latlon_to_meters), linear in z. Every ERA5 file is listed with its FNV-1a hash in the global attribute era5_files. Its tests (analytic hydrostatic atmosphere, GRIB2 = NetCDF bit for bit, the Lindenberg sample against the Lindenberg sounding: θ RMSE 0.787 K, qv RMSE 0.718 g/kg over 200–3000 m) moved with it.

The simulation driver takes such a driver as [initial] dynamic: its profiles set the initial u, v, θ (and qv), and lateral faces set to boundaries.x/y = "open" take its boundary planes through a FileBoundaryFeed, blended linearly in time (boussinesq core, uniform grid, z walls). examples/lindenberg_era5/lindenberg_era5.toml is a 16³ open box over Lindenberg reading the committed input/lindenberg_era5_dynamic.nc (1.4 MB; ERA5 of 2019-06-29 00–12 UTC at 52.2085 N, 14.118 E); the file is hashed under [inputs] of run.toml, and 20 steps round-trip bit for bit (test/input_dynamic.jl).

The Berlin case

examples/urban/berlin_<s>.toml name their drivers in each domain's static_driver (the site's and its parent's, relative to the config, hashed under [inputs] of run.toml); the generated files are committed in examples/urban/input/ (all of them together 790 KB; each is under the 2 MB limit for committed drivers) with their source hashes. A missing file is a configuration error before any run folder is made, and it prints the aeolusprep static <config> command that makes it. There is no in-memory ground: a grid no file was made for needs its driver made first (aeolusprep static <config> --set grid.size=… --out …). The Mitte sample at the smoke size of its [test] overrides and the synthetic city of test/urban_run.jl have committed drivers of their own.

Reading the driver is bit for bit the OSM-direct path it replaced (test/input_static.jl, against digests captured before the switch: the smoke case's solid mask, surface classes, heightmap and view factors, the summer rasterisation, the nest parents' land use, and the 12-step smoke state in test/config_berlin.jl); the Mitte sample at 32 × 32 × 16 is its driver's polygons rasterised there. The two known defects of the OSM reader (the &&/|| precedence of the node parser, now in AeolusPrep; patches drawn over roofs, the rasterisation here) are kept and documented; fixing them is #141's.

The dynamic driver (CFG-g, #362): the domain's dynamic_driver names it ([initial] dynamic of the urban run type before ONE-e #454).

  • Sounding. berlin_summer.toml reads its initial state from input/berlin_20190629_dynamic.nc (aeolusprep dynamic --from-sounding, from the Lindenberg CSV, which stays as [urban] sounding, the driver's hashed source). The tables are the ones the CSV path builds, so the initial θ(z), qv(z), ground pressure (101841.78 Pa), reference state, the parent's geostrophic wind and zi are bitwise those of master's CSV path (digests captured before the switch). With `dynamicdriver = "none"the CSV is preprocessed in memory by the same functions. The driver holds the whole sounding series: a case starting at another time ([urban] starth) reads the same tables with the time axis moved and its ground pressure recomputed at its start, bitwise the CSV read in memory. The smoke and winter scenarios keep the idealised profile (sounding = dynamicdriver = "none"`).
  • Offline nest. An online run with [urban] child_boundaries = "<file>" writes the parent's windows, the child's boundary slabs, its initial wind and the parent's mean profiles. A child run with dynamic_driver = "<file>" and [nesting] parent_driver = "offline" replays them without the parent: the same windows (the child steps land on the parent times), the same face data and targets; its own initial θ, qv and reference state come from [urban] sounding as online. Measured on the smoke case: 12 steps, bitwise the online one-way child in every child field. The online nest stays the default; offline is for a parent run once and reused. Two-way and offline exclude each other.

Aeolus.InputDrivers — Module
InputDrivers

Aeolus's own input drivers (CFG-f, #361): NetCDF-4 files that hold what a run reads from outside the model. A run reads its geometry, initial state and forcing from them, never from OpenStreetMap, GIS or reanalysis files.

  • Conventions (input_drivers/conventions.jl, shared with the dynamic driver of CFG-g): the global attributes every driver carries (DRIVER_ATTRIBUTES), the one map projection (latlon_to_meters, equirectangular), and the declarative DriverSchema a file is checked against (check_driver) and the docs pages are generated from (schema_markdown, format_reference).
  • The static driver (input_drivers/static.jl): terrain, buildings and surface classes on the run's own horizontal grid plus the building and patch polygons (STATIC_SCHEMA, StaticInputs, write_static_driver, read_static_driver), and the tile form of an unresolved surface, class counts and building morphometry per column, for a coarse (nest parent) grid (STATIC_TILES_SCHEMA, StaticTiles).
  • The dynamic driver (input_drivers/dynamic.jl, CFG-g #362): the initial state, the boundary planes of the open faces over time and the large-scale and surface forcing (DYNAMIC_SCHEMA, DynamicInputs, read_dynamic_driver, write_dynamic_driver); the planes feed the open boundaries as FileBoundaryData, read two records at a time by a FileBoundaryFeed.
  • The city (input_drivers/city.jl): the footprints a static driver stores (UrbanCity, Building), the surface classes, and their rasterisation on a grid (rasterize_city, static_inputs, solid_and_classes), which a run uses as well as the writer.
  • A sounding or a case's tables as dynamic inputs (input_drivers/sounding.jl: sounding_dynamic_inputs, forcing_dynamic_inputs), what a run reading its CSV builds in memory and what a sounding driver holds, and the in-run writer of a parent's child boundaries (input_drivers/recorder.jl: NestBoundaryRecorder).

Everything that creates a driver from outside data (OpenStreetMap and GeoJSON, land-use classification, soundings, ERA5/GRIB, downloads) is the separate package AeolusPrep.jl (ONE-h, #457), which depends on Aeolus for these schemas and writers.

A file whose grid differs from the run's is an error naming both grids: there is no resampling inside the model; the preprocessor is re-run for another grid (aeolusprep static <config.toml>).

There is no PALM (PIDS) compatibility goal: the variable names are Aeolus's own, short snake_case with CF attributes.

Aeolus.InputDrivers.DRIVER_ATTRIBUTES — Constant
DRIVER_ATTRIBUTES

The global attributes every Aeolus input driver carries, with what each holds:

  • aeolus_driver — "static" or "dynamic";
  • aeolus_form — the layout within the kind ("resolved", "tiles");
  • aeolus_schema_version — DRIVER_SCHEMA_VERSION;
  • origin_lat, origin_lon (degrees) — the anchor of the projection;
  • projection — "equirectangular" (latlon_to_meters);
  • origin_x, origin_y (m) — where the anchor lies in the run's mesh coordinates (the x, y of the file);
  • dx, dy (m) — the horizontal spacing of the run's grid;
  • source — the file the driver was made from: relative to the driver's own directory when both lie in the same Julia package (a source in Aeolus, such as a sounding CSV); "<Package>:<path in it>" when the source lies in another package (an OpenStreetMap file of AeolusPrep.jl: "AeolusPrep:data/berlin/alexanderplatz_real.osm"), so the attribute does not depend on where the packages are checked out; else absolute;
  • source_fnv1a64 — the FNV-1a hash of that file (16 hex digits): a driver whose source has since changed is reported as stale;
  • preprocessor — what wrote it (e.g. "aeolusprep static");
  • aeolus_commit — the git commit of the writing Aeolus ("" outside a checkout).

A file also carries the CF Conventions attribute and date_created.

Aeolus.InputDrivers.DRIVER_SCHEMA_VERSION — Constant

The version of the driver conventions and schemas below; a file of another version is refused.

Aeolus.InputDrivers.DYNAMIC_SCHEMA — Constant
DYNAMIC_SCHEMA :: DriverSchema

The dynamic driver (aeolus_driver = "dynamic", aeolus_form = "standard"). Every group is optional; read_dynamic_driver checks that what is present is consistent:

  • initial state — profiles over init_z (init_theta, init_qv, init_u, init_v; schema only: written and read back, but no preprocessor fills them and no case reads them yet), or 3-D fields on the run grid (init_u3d, …, over the run's x, y, z, interior cells in storage order: u at the cell's west face, v at its south face, w at its bottom face), and init_p_surface. A sounding driver has no profiles: its consumer evaluates the large-scale profile tables (ls_profile_*) at its start. Global attribute init_time: the model start, ISO-8601 UTC ("": a case without a calendar date); every time coordinate is in seconds since it.
  • boundary planes — for each open face (west, east, south, north, top) and each field with data, bc_<face>_<var> over (bc_<face>_<var>_i, _j, _k, time_bc): the child's buffer slab (the face plane plus the H halo layers, the storage points of the OpenPlane), with attributes field (the field's name), side, i0, j0, k0 (the slab's first storage index) and halo_mode. time_bc_step is the window length the writer asked for ending at each record (NaN: none).
  • large-scale forcing — ls_<name> tables (see LS_TABLES), each over its own height and time coordinate (ls_<name>_z, ls_<name>_time, or a shared time_bc), so a table round-trips without resampling; and the surface series sfc_temperature, sfc_pressure over time_sfc (schema only, like the init_* profiles).
  • initial soil (#521, PALM's PIDS init_soil_t, init_soil_m) — init_soil_t (K) and init_soil_m (m³ m⁻³) on the coordinate zsoil (m below the surface, positive down, strictly increasing: the levels' centres), each a profile over zsoil or a volume over (x, y, zsoil) on the run's horizontal grid; NaN (the _FillValue) marks a level or a column without data (AeolusPrep.jl's ERA5 soil marks the columns that are not land). What the urban site's soil starts from ([ground] soil_init).

Global attribute dynamic_source: "sounding", "case_table" or "parent" (an Aeolus nest parent, NestBoundaryRecorder).

Aeolus.InputDrivers.STATIC_SCHEMA — Constant
STATIC_SCHEMA :: DriverSchema

The static driver of a building-resolving run (aeolus_driver = "static", aeolus_form = "resolved"): rasters on dimensions x, y (the cell centres of the run's horizontal grid) and the building and patch polygons as CF contiguous ragged arrays (a count variable per polygon over the vertex dimension; rings of a polygon with holes are NaN-separated). The polygon variables are absent when there are no buildings (no patches).

Aeolus.InputDrivers.STATIC_TILES_SCHEMA — Constant
STATIC_TILES_SCHEMA :: DriverSchema

The static driver of a run that does not resolve buildings (aeolus_form = "tiles", the nest parent): per column, the count of fine cells of each surface class (out of refinement², the variable's attribute; the tile fractions are class_count / refinement²) and the building morphometry. Global attributes tile_x0, tile_y0: the south-west corner of the grid, m from the anchor.

Aeolus.InputDrivers.SURFACE_CLASSES — Constant
SURFACE_CLASSES

The surface-class code table, code => name: 1 street, 2 roof, 3 park, 4 water, 5 wall. A static driver stores it as the CF flag_values and flag_meanings of surface_class.

Surface class: park (vegetated ground).

Aeolus.InputDrivers.SURFACE_ROOF — Constant

Surface class: roof (the top of a building).

Aeolus.InputDrivers.SURFACE_STREET — Constant

Surface class: street (paved ground, the default).

Aeolus.InputDrivers.SURFACE_WALL — Constant

Surface class: a street cell next to a building, carrying the wall heat load of the 2-D surface (set by tag_building_adjacent!).

Aeolus.InputDrivers.SURFACE_WATER — Constant

Surface class: water.

Aeolus.InputDrivers.VOLATILE_ATTRIBUTES — Constant

The attributes that change on every write (a reproduced file differs only in these).

Aeolus.InputDrivers.Building — Type
Building(polygon, height, class = SURFACE_ROOF; levels = NaN, min_height = 0.0,
         material = "", roof = "")

A single footprint. polygon is a vector of (x, y) vertices in the mesh coordinate system (metres from the mesh origin); a polygon with holes (a multipolygon) is several closed rings, each followed by a (NaN, NaN) vertex. height (m) is the top of the building, class the surface class of its roof (default SURFACE_ROOF). The attributes levels (NaN: untagged), min_height (m, the bottom of a part that does not reach the ground), material and roof (the roof shape) are what the source says (OSM building:levels, min_height, building:material, roof:shape); they are kept through a static driver but do not enter the rasterisation.

Aeolus.InputDrivers.DriverSchema — Type
DriverSchema(kind, form, doc, variables; attributes = [])

A declarative table of the variables of one kind of input driver: kind is the aeolus_driver attribute ("static"), form the aeolus_form attribute that tells two layouts of one kind apart ("resolved", "tiles"). attributes are the global attributes of this form on top of DRIVER_ATTRIBUTES, name => meaning pairs. check_driver checks a file against it; schema_markdown and format_reference render it for the docs.

Aeolus.InputDrivers.DriverVariable — Type
DriverVariable(name, dims, type; units = "", long_name, standard_name = "",
               required = true, range = nothing, doc = "", alt_dims = ())

One variable of a DriverSchema: its name, its dimensions dims (Julia index order: ("x", "y") is an (Nx, Ny) array; "*" matches any dimension name, () is a scalar) and the other dimensions it may have instead, alt_dims (a tuple of such tuples: PALM's init_soil_t is a profile over zsoil or a volume over x, y, zsoil), its element type, its CF units, long_name and standard_name ("" where CF has none), whether a file must have it, and the closed range (lo, hi) its values must lie in (nothing: unchecked; NaN values, the ring separators of the polygons, are skipped).

Aeolus.InputDrivers.DynamicInputs — Type
DynamicInputs

What a run reads from a dynamic driver (read_dynamic_driver) or a preprocessor makes in memory (sounding_dynamic_inputs):

  • init_time — the model start (ISO-8601 UTC, "": none); every time below is in seconds since it;
  • profiles — the initial profiles (z, theta, qv, u, v) (each a vector, or nothing), or nothing;
  • p_surface — the initial pressure at the ground (Pa), or nothing;
  • fields — 3-D initial fields by name (:u, :v, :w, :θ, :qv), interior cells of the run grid;
  • tables — the large-scale ForcingTables by name (:profile_theta, :u_g, :theta_adv, …, see LS_TABLES);
  • surface — (t, temperature, pressure) series (a vector or nothing each), or nothing;
  • soil — the initial soil (z, t, m): the depths zsoil (m, positive down) and the temperature (K) and water content (m³ m⁻³), each a vector over z (a profile), an (Nx, Ny, Nz) array (a volume) or nothing; or nothing;
  • boundary — the FileBoundaryFeed of the boundary planes, or nothing;
  • attributes — the file's global attributes (in memory: what a writer records, e.g. dynamic_source, nudging_tau).
Aeolus.InputDrivers.FileBoundaryData — Type
FileBoundaryData = WindowedBoundaryData{FileSnapshot}

The boundary planes of a dynamic driver as open-boundary data: two time_bc records (a at t0, b at t0 + Δt) blended linearly in time by the generic WindowedBoundaryData (blend_window!). Held and advanced by a FileBoundaryFeed.

Aeolus.InputDrivers.FileBoundaryFeed — Type
FileBoundaryFeed

The boundary planes of a dynamic driver, read lazily: the record times time (s since init_time), the window lengths step the writer took (time_bc_step), the slab layout, and the FileBoundaryData data holding two records (data.a = record k, data.b = record k + 1). feed_window! moves the window (reading only the record it does not hold yet) and advance_feed! moves it to the window holding a time. The file is opened for each read, so the feed holds no file handle. reads counts the records read.

Aeolus.InputDrivers.FileSnapshot — Type
FileSnapshot

One time_bc record of a dynamic driver's boundary planes: per field, the buffer slabs of its open faces at their storage-index ranges. The snapshot type of FileBoundaryData: snapshot_values(s, name) is a SlabArray, a storage-indexed 3-D view backed by the slabs, so the time blend is blend_window! reading the plane points, as for the nest.

Aeolus.InputDrivers.NestBoundaryRecorder — Type
NestBoundaryRecorder(path, planes, mesh; init_time = "", fields = Dict(), profiles = (;),
                     attributes = Dict(), inputs = nothing, source = "", preprocessor, anchor…)

The in-run writer of a dynamic driver's boundary planes (an Aeolus parent writing its child's driver, CFG-g #362; AeolusPrep.jl uses it for the steady planes of a sounding driver and the ERA5 planes): it defines a bc_<face>_<var> variable for every non-mirror plane of planes (the OpenPlanes of the child's open boundary set) over the unlimited time_bc, writes the 3-D initial fields (:u, :v, :w, …: interior arrays), and on each record_boundary! appends one record: every plane's values read from a snapshot (snapshot_values(s, name) at the plane's storage points, exactly what blend_window! reads online), the record time, the window length, and the mean profiles (name => vector over the run's level centres: ls_profile_<name> over (ls_profile_<name>_z, time_bc)). inputs (a DynamicInputs) writes its profiles, tables, series and attributes into the same file (a sounding driver with the steady planes of an open case). The file is opened for each record, so a run that stops leaves a readable driver.

Aeolus.InputDrivers.SlabArray — Type
SlabArray <: AbstractArray{Float64,3}

The storage-indexed values of one field held by a FileSnapshot: A[i, j, k] is the value of the slab whose storage ranges hold (i, j, k); a point no slab holds is a BoundsError (only the open-face buffers exist). Where two faces' slabs overlap (the corners) they hold the same value, written from one field.

Aeolus.InputDrivers.StaticInputs — Type
StaticInputs

What a building-resolving run reads from its static driver (read_static_driver) or makes in memory (static_inputs): the grid (x, y cell centres, dx, dy), the anchor (origin_lat, origin_lon at origin_x, origin_y in mesh coordinates), the rasters zt, building_height, building_id, surface_class, ground_class, lai, the city (its polygons) and the file's global attributes (empty in memory).

Aeolus.InputDrivers.StaticTiles — Type
StaticTiles

The unresolved surface of a coarse grid (STATIC_TILES_SCHEMA): the grid (x, y, dx, dy) and anchor, the south-west corner x0, y0 (m from the anchor), class_count[I, J, c] (fine cells of class c out of refinement²), lambda_f, h_mean, h_max, the source's provenance lines notes, and the file's attributes.

Aeolus.InputDrivers.UrbanCity — Type
UrbanCity(buildings = Building[], patches = Building[])

Container for a set of Buildings plus patch labels for non-built surfaces (parks, water) as polygons (height 0, the class the patch's surface class).

Aeolus.InputDrivers.check_driver — Method
check_driver(path, schema; source = true) -> Vector{String}

Every problem of the driver file path against schema, as messages (empty: the file is good):

  • not a NetCDF file, another aeolus_driver kind or aeolus_form;
  • an aeolus_schema_version other than DRIVER_SCHEMA_VERSION;
  • a missing global attribute of DRIVER_ATTRIBUTES;
  • a missing required variable, a variable over the wrong dimensions, of the wrong element type or units, or with values outside its range;
  • with source = true, a source_fnv1a64 that does not match the source file (when that file is present: a driver can be used without its source).
Aeolus.InputDrivers.check_grid — Method
check_grid(path, ds, mesh; origin_lat, origin_lon, origin_x, origin_y)

Error, naming both grids, unless the driver ds (at path) is on the horizontal grid of mesh (its x, y cell centres, dx, dy) with the anchor at the same place.

Aeolus.InputDrivers.check_planes — Method
check_planes(feed, planes) -> nothing

Error unless the driver has a slab for every non-mirror open-boundary plane of the run (OpenPlanes, e.g. st.planes of the run's open boundary state) at that plane's storage ranges: a face missing for a configured open side, or a slab of another size or place (another grid), names the plane.

Aeolus.InputDrivers.driver_attributes — Method
driver_attributes(kind, form; origin_lat, origin_lon, origin_x, origin_y, dx, dy,
                  source = "", out = "", preprocessor) -> Dict{String,Any}

The global attributes of a driver (DRIVER_ATTRIBUTES) about to be written to out: source is recorded relative to out's directory when both lie in the same package, as "<Package>:<path in it>" when it lies in another one, else absolute, with its hash; the commit is the writing checkout's.

Aeolus.InputDrivers.dynamic_forcing — Method
dynamic_forcing(inputs; t0 = 0) -> NamedTuple

The large-scale forcing of the driver as LargeScaleForcing objects (times: seconds since init_time, plus t0, shift_table: the run's model time at the start): U_g, V_g (ForcingTables or nothing) and extra, a tuple of AdvectiveTendencies (from ls_*_adv), Subsidence (ls_w_subs, global attributes subsidence_fields, subsidence_form) and ProfileNudging (ls_nudge_*, global attribute nudging_tau), in that order, each only when the driver has it.

Aeolus.InputDrivers.feed_coverage — Method
feed_coverage(feed) -> (t_first, t_last)

The time interval the boundary records cover (s since init_time). A one-record file is steady and covers every time ((-Inf, Inf)).

Aeolus.InputDrivers.feed_steady! — Method
feed_steady!(feed, k) -> feed

Hold record k as steady data (b = a, Δt = 0, t0 = time[k]): the data a nest child is started from before its first window.

Aeolus.InputDrivers.feed_window! — Method
feed_window!(feed, k) -> feed

Point the feed's data at the window from record k to record k + 1 (t0 = time[k], Δt = time[k+1] − time[k]); for the last record (or a one-record, steady file) b = a and Δt = 0. Moving to the next window reads one record into the buffers of the one dropped, so at most two records are resident.

Aeolus.InputDrivers.file_fnv1a64 — Method

fnv1a64 of the bytes of the file path, as 16 hex digits.

Aeolus.InputDrivers.forcing_dynamic_inputs — Method
forcing_dynamic_inputs(; U_g = nothing, V_g = nothing, extra = (), surface = nothing,
                       t_start = 0.0, init_time = "", attributes = Dict()) -> DynamicInputs

The dynamic-driver form of a case's large-scale forcing (the case-table preprocessor: GABLS, CASES-99): the inverse of dynamic_forcing. U_g, V_g and the quantities of the extra forcings (AdvectiveTendencies, Subsidence, ProfileNudging) that are ForcingTables become ls_* tables; a number or a function stays with the case (it is not a table). surface is a (t, temperature, pressure) series. Times move from the case's model time to seconds since init_time, the run start t_start.

Aeolus.InputDrivers.format_reference — Method
format_reference(schema; example = nothing, title = nothing) -> String

The input-format specification of one DriverSchema, as Markdown, generated from the schema (the docs build writes docs/src/reference/input_static.md and input_dynamic.md from it): the identifying attributes (aeolus_driver, aeolus_form, aeolus_schema_version = DRIVER_SCHEMA_VERSION), one table row per variable (dimensions, element type, units, required or optional, valid range, meaning; schema_markdown), the global attributes (the common DRIVER_ATTRIBUTES and the schema's own), and, with example a driver file of this schema, its header as ncdump -h prints it (ncdump_header).

Aeolus.InputDrivers.init_day_seconds — Method
init_day_seconds(init_time) -> s

Seconds from 00 UTC of the date of init_time (ISO-8601 UTC) to init_time: the offset that puts a driver's "seconds since init_time" tables on a day-based axis (a sounding whose epoch is the start date).

Aeolus.InputDrivers.init_time_string — Method
init_time_string(y, m, d, hour_utc) -> String

The ISO-8601 UTC time ("yyyy-mm-ddTHH:MM:SSZ") of fractional hour hour_utc of the date (y, m, d): the init_time attribute of a dynamic driver.

Aeolus.InputDrivers.latlon_to_meters — Method
latlon_to_meters(lat, lon, lat0, lon0) -> (x, y)

Project geographic (lat, lon) in degrees to local (x, y) metres about the anchor (lat0, lon0): the equirectangular (plate carrée) projection with the anchor's parallel as the standard parallel, $x = R\,Δλ\cos φ_0$, $y = R\,Δφ$, $R = 6371$ km. Sub-metre accurate over the ≤ 5 km of an LES domain. The one projection of the input drivers (projection = "equirectangular").

Aeolus.InputDrivers.meters_to_latlon — Method
meters_to_latlon(x, y, lat0, lon0) -> (lat, lon)

The inverse of latlon_to_meters: local (x, y) metres about the anchor (lat0, lon0) back to degrees, $φ = φ_0 + y/R$, $λ = λ_0 + x/(R\cos φ_0)$.

Aeolus.InputDrivers.ncdump_header — Method
ncdump_header(path; max_attr = nothing) -> String

The header of the NetCDF file path in CDL, as ncdump -h prints it (dimensions, variables with their attributes, global attributes; no data), written in Julia so that the docs need no NetCDF binaries. Dimensions are listed in C order, as ncdump does. max_attr shortens an attribute value longer than that many characters (with …; ncdump does not).

Aeolus.InputDrivers.plane_snapshot — Method
plane_snapshot(planes, mesh) -> FileSnapshot

The current buffers of planes (the non-mirror OpenPlanes of an open boundary set) as a boundary snapshot: what record_boundary! writes for boundary data evaluated on the planes themselves (the steady planes of an open case, boundary_values! of its analytic data).

Aeolus.InputDrivers.point_in_polygon — Method
point_in_polygon(x, y, poly) -> Bool

The even–odd (crossing-number) test of the point (x, y) against poly. An edge that touches a NaN vertex never counts, so for a multipolygon (closed rings, each followed by (NaN, NaN)) the test over all rings is exactly the polygon with its holes.

Aeolus.InputDrivers.polygon_bbox — Method
polygon_bbox(poly) -> (xmin, xmax, ymin, ymax)

Bounding box of a footprint polygon, skipping the NaN ring separators of a multipolygon.

Aeolus.InputDrivers.rasterize_city — Method
rasterize_city(city, mesh; default = SURFACE_STREET)
    -> (building_id, building_height, surface_class, ground_class)

The footprints of city on the horizontal cell centres of mesh, cell by cell (a cell belongs to a polygon when its centre does, point_in_polygon):

  • building_id::Matrix{Int32} — the last building (index into city.buildings, list order) whose footprint holds the cell, -1 where none does;
  • building_height (m) — the largest height of the buildings holding the cell, 0 where none does;
  • surface_class::Matrix{UInt8} — default, then each building's class, then each patch's class, in list order (a patch drawn over a roof relabels it: a documented defect of the Berlin case, kept bit for bit until #141);
  • ground_class — the same without the buildings: what a column shows when its building is removed (the building-free frame of an open case, solid_and_classes).
Aeolus.InputDrivers.read_dynamic_driver — Method
read_dynamic_driver(path; mesh = nothing, origin_lat, origin_lon, origin_x, origin_y,
                    check_source = true) -> DynamicInputs

Read the dynamic driver at path. It is checked against DYNAMIC_SCHEMA (check_driver: kind, schema version, attributes, units, ranges, a stale source) and for consistency: an initial profile needs init_z; 3-D fields and boundary planes need the run mesh and the x, y, z of the file must be the run's (an error naming both grids; with the anchor keywords, the anchor too); time_bc must increase strictly. The boundary planes become a FileBoundaryFeed positioned on its first window (two records read). planes = false reads only the profiles, tables and series (no mesh needed): what a consumer of a sounding uses.

Aeolus.InputDrivers.read_static_driver — Method
read_static_driver(path; mesh, origin_lat, origin_lon, origin_x, origin_y) -> StaticInputs

Read the static driver at path. It is first checked against STATIC_SCHEMA (check_driver: kind, schema version, attributes, required variables, ranges, a stale source), then against the run: an error naming both grids unless its x, y, dx, dy and anchor are the run's (mesh, and the anchor origin_lat/origin_lon expected at origin_x/origin_y in mesh coordinates). There is no resampling.

Aeolus.InputDrivers.read_static_tiles — Method
read_static_tiles(path; mesh, origin_lat, origin_lon, origin_x, origin_y) -> StaticTiles

Read the tile form of the static driver at path, checked as read_static_driver checks the resolved form.

Aeolus.InputDrivers.record_boundary! — Method
record_boundary!(rec, t, step, snapshot; profiles = (;)) -> rec

Append one time_bc record to the driver of rec: time t, window length step (NaN for the first record), the values of every plane from snapshot (snapshot_values(snapshot, name) at the plane's storage ranges) and the mean profiles (name => vector, the names given to the recorder).

Aeolus.InputDrivers.schema_markdown — Method
schema_markdown(schema) -> String

A Markdown table of schema's variables (name, dimensions, type, units, required, range, meaning), for the docs page.

Aeolus.InputDrivers.shift_table — Method
shift_table(tab, Δt) -> ForcingTable

tab with its time coordinate moved by Δt (s): a table on the "seconds since init_time" axis of a driver onto another time axis (a sounding's epoch, a case's model time). Exact for times and shifts that are whole seconds below 2⁵³.

Aeolus.InputDrivers.solid_and_classes — Method
solid_and_classes(st, mesh; frame = (0, 0), tag_walls = true,
                  bcs = FieldBoundaryConditions(:periodic, :periodic, :noflux)) -> (sm, sfc)

The IBM SolidMask and the (Nx, Ny) surface-class map of a run, from the rasters st of rasterize_city or a StaticInputs: a column with a building is solid in every cell whose centre is at or below building_height, and takes surface_class.

frame = (fx, fy) (cells) keeps the columns within fx cells of the west and east faces and fy cells of the south and north faces free of buildings (the boundary_frame of an open case, N-open-d #262, so the boundary data is not imposed on a building cut by the box edge): there a column is fluid and takes ground_class. With tag_walls, street cells next to a building become SURFACE_WALL (tag_building_adjacent!, neighbours read through bcs).

Bit for bit what rasterising the city with the frame did before the static driver (the union over buildings of z ≤ h_b is z ≤ max h_b).

Aeolus.InputDrivers.sounding_dynamic_inputs — Method
sounding_dynamic_inputs(snd::Sounding; t0, init_time, z_top = 3000.0, p_surface = nothing)
    -> DynamicInputs

The dynamic-driver form of a radiosonde sounding: its height-time tables (sounding_profiles up to z_top) as ls_profile_theta, _qv, _u, _v, _p on the axis "seconds since inittime" (t0 is the run start on the sounding's axis, [`soundingtime](@ref Aeolus.LargeScaleForcing.sounding_time)), andpsurface(Pa) asinitpsurface. There are noinit*profiles: a consumer evaluates the tables at its start time (t = 0` on this axis), the time interpolation between the two launches that bracket the start.

Aeolus.InputDrivers.surface_pressure_at — Method
surface_pressure_at(profiles, t, z_launch, z_site; c = MoistThermodynamics.DEFAULT_CONSTANTS) -> Pa

The pressure at a site of elevation z_site (m above sea level) from the sounding profiles (sounding_profiles) at time t (on the tables' axis), launched at z_launch: the launch-site surface pressure reduced hypsometrically with the surface virtual temperature, $p = p_L \exp\bigl(g_0 (z_L - z)/(R_d T_v)\bigr)$.

Reference: Wallace & Hobbs (2006), Atmospheric Science, 2nd ed., §3.2.2.

Aeolus.InputDrivers.tag_building_adjacent! — Method
tag_building_adjacent!(sfc, sm, mesh; class = SURFACE_WALL,
                       bcs = FieldBoundaryConditions(:periodic, :periodic, :noflux))

Overwrite any SURFACE_STREET cell that shares an edge with a building footprint (in the horizontal plane) with class. This lets an otherwise 2-D surface energy balance carry the effective heat load of the building's vertical walls, since real walls dominate solar absorption in dense urban geometry. The four neighbours are read with neighbor_index on bcs (#262): across a periodic side they wrap, across an open one the cell has no neighbour beyond the face.
