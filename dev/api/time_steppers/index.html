TimeSteppers

Generic time-integration schemes. Currently only Shu-Osher SSP-RK3 is provided; a projected-RK3 variant is planned in Phase 2. The step! function is a generic function shared with Simulations — the Boussinesq driver adds its own method to it.

Aeolus.TimeSteppers.RK3 — Type
RK3(state)

Shu–Osher strong-stability-preserving RK3 stepper.

Given a state::NamedTuple{names, NTuple{N,Field}}, RK3(state) allocates scratch fields for the two intermediate stages plus a tendency buffer.

Advance one step with

step!(stepper, state, tendency!, dt, t)

where tendency!(k, state, t) fills the tendency k::NamedTuple (matching state) with ∂/∂t contributions. The caller is responsible for filling halos of state — usually inside tendency! before it computes stencils.

Aeolus.TimeSteppers.step! — Function
step!(stepper, state, tendency!, dt, t = 0)
step!(sim::BoussinesqSimulation, dt)

Advance one time step. The first method is the generic Shu–Osher SSP-RK3 driver (see RK3); the second is the fractional-step / pressure- projection driver for BoussinesqSimulation. Both add methods to the same generic function.

step!(sim::MassWeightedSimulation, dt; kwargs...)

Generic entry point — dispatches to step_anelastic! or step_pseudo_incompressible! according to the weighting, so step! / run! work uniformly across all three dynamical cores.

step!(col) -> col

Advance the column by col.set.dt: radiation (every dt_rad), radiative heating, surface fluxes and T_s, implicit turbulent mixing of s = h + g z, q_v, q_l and momentum, Coriolis turning toward the geostrophic wind, droplet settling, and finally fog saturation adjustment with fog_condensation. Diagnostics are recorded every dt_out.

step!(sim::BoussinesqSimulation, dt; body_force! = nothing, post_predictor! = nothing,
      momentum_advection = momentum_advect!, sgs = nothing,
      sgs_stress = :laplacian)

Advance sim by dt. Two optional callbacks are supported:

  • body_force!(sim, Δt) — invoked after the built-in tendencies are assembled and before the predictor step. Explicit source terms (Coriolis-like body forces, weak IBM penalty, geostrophic nudging) belong here.

  • post_predictor!(sim, Δt) — invoked after the predictor u* = u + Δt F and before the divergence + Poisson solve. This is the correct place for stiff / implicit-style corrections: implicit IBM velocity-damping, mask enforcement, anything that would blow up if added as an explicit tendency. The pressure projection then makes the resulting field divergence-free.

Two keywords swap numerical operators without changing the algorithm:

  • momentum_advection = momentum_advect! — the operator f(tu, tv, tw, u, v, w) that adds -∂(uⱼuᵢ)/∂xⱼ to the momentum tendencies (halos of u, v, w are filled). The default is the 2nd-order centred flux form; e.g. (tu, tv, tw, u, v, w) -> momentum_advect_weno_z!(tu, tv, tw, u, v, w) (AdvectionSchemes) selects the WENO-Z form.

  • sgs = nothing — the subgrid-scale closure, any AbstractSGSClosure (StaticSmagorinsky, DynamicSmagorinsky, ML.MLSGS, …) or a plain function f(νt, u, v, w). When given it replaces the built-in Smagorinsky closure and switches the SGS terms on even if C_s = 0. The closure's coefficients are computed from the current state (halos filled) into sim.νt/sim.κt, its momentum and scalar tendencies are added where the built-in closure adds them (the scalar flux to θ and, with moisture = true, to qv, which also gets ν∇²qv), and advance_sgs! commits its memory once, after the projection. StaticSmagorinsky(sim.C_s) reproduces the built-in run bit for bit.

  • eddy_viscosity! = nothing — the pre-contract name of sgs for a function f(νt, u, v, w); still accepted (it is wrapped in a FunctionSGS, κt = νt/Prₜ). Pass one of sgs, eddy_viscosity!.

  • sgs_stress = :laplacian — the form of the SGS momentum divergence, passed to add_sgs_momentum!: :laplacian is ∂ⱼ(νₜ∂ⱼuᵢ) (the default; the pre-Era-VI runs bit for bit), :symmetric the stress form ∂ⱼ(2νᵢⱼSᵢⱼ) with the closure's horizontal and vertical viscosities (add_sgs_stress_divergence!, P55-b). step_rk3!, step_imex!, step_adaptive! and the sound-proof cores take the same keyword.
