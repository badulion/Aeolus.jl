3-D Monte-Carlo radiative transfer (Phase 34)

Aeolus.MonteCarloRT.MCDomain — Type
MCDomain{T}

Uniform Cartesian voxel grid the photons travel through: nx × ny × nz voxels of size dx × dy × dz with lower corner (x0, y0, z0).

Boundary conventions, fixed here and assumed everywhere below:

  • x, y — periodic. A photon leaving the east face re-enters at the west face. This matches the LES lateral boundary conditions and makes the domain a statistically infinite, horizontally heterogeneous slab.
  • z = z0 — the ground. A reflecting Lambertian surface with a per-cell albedo; what is not reflected is absorbed there.
  • z = z0 + nz·dz — the top. Photons that cross it have escaped to space and are scored as top-of-domain upwelling flux.

Voxel (i,j,k) spans [x0+(i-1)dx, x0+i·dx] × … × [z0+(k-1)dz, z0+k·dz], so k = 1 is the layer touching the ground — the same bottom-up ordering as OpticalProperties and RadiativeFluxes.

Aeolus.MonteCarloRT.MCMedium — Type
MCMedium{T}

The optical state of the domain at one wavelength (one g-point):

  • kext — extinction coefficient per voxel, m⁻¹. The optical depth of a chord of length s through the voxel is kext·s.
  • ssa — single-scattering albedo per voxel, ω₀ ∈ [0,1].
  • g — Henyey-Greenstein asymmetry parameter per voxel.
  • phase — :henyey_greenstein or :rayleigh. Rayleigh ignores g.
  • solid — true marks a building voxel: it does not transmit.
  • solid_albedo — Lambertian albedo of each solid voxel's surface.
  • sfc_albedo — Lambertian albedo of the ground, per (i,j) cell.

kext is stored rather than a per-voxel optical depth because the chord through a voxel is not dz for a slanted ray; storing an extinction coefficient is what lets the traversal integrate the slant path exactly.

Aeolus.MonteCarloRT.MCResult — Type
MCResult{T}

Everything a Monte-Carlo solve produces, with a standard error on every statistical quantity.

Normalisation: all fluxes are absolute (W m⁻²), and incident is the horizontal irradiance at the top of the domain, F₀μ₀. Dimensionless fractions (albedo, transmittance, absorptance_*) are relative to incident, so albedo + absorptance_atm + absorptance_sfc + absorptance_solid equals one up to the Russian-roulette imbalance.

Fields:

  • absorbed, absorbed_err — volumetric absorption rate, W m⁻³, per voxel (zero inside buildings).
  • sfc_direct, sfc_diffuse (+ _err) — downward surface irradiance maps, W m⁻², split into the unscattered beam and everything else.
  • sfc_absorbed — what the ground keeps, W m⁻².
  • solid_incident, solid_absorbed — power on and into each building voxel, W.
  • flux_up, flux_dn, flux_dn_dir — level fluxes, (nx, ny, nz+1), W m⁻², bottom-up, matching the RadiativeFluxes convention.
  • albedo, transmittance, absorptance_atm, absorptance_sfc, absorptance_solid (+ _err) — the broadband budget.
  • albedo_analogue, transmittance_analogue (+ _err) — the same two quantities from the pure analogue estimator. Comparing them against the local estimates is a direct measurement of the variance reduction and a cross-check that the local estimator is unbiased.
  • radiance_up, radiance_up_err — top-of-domain diffuse radiance (W m⁻² sr⁻¹) in each of view_dirs. The unscattered solar beam is not included; it is a delta function in angle.
  • rr_loss, rr_gain, lost — weight bookkeeping, as fractions of the incident flux.
Aeolus.MonteCarloRT.MonteCarloSolver — Type
MonteCarloSolver{T} <: AbstractRTSolver

3-D Monte-Carlo shortwave solver.

  • nphoton — photons per solve. Rounded up to a multiple of nbatch so that all batches are the same size and the batch variance is an unbiased variance estimate.
  • nbatch — number of independent batches used for the standard-error estimate. Eight is the practical minimum for a stable variance; the default of 16 costs nothing.
  • weight_min, rr_survival — Russian-roulette threshold and survival probability. A photon whose weight falls below weight_min survives with probability rr_survival and has its weight divided by that probability, which leaves the expected weight unchanged.
  • max_scatter — hard cap on scattering events per photon.
  • local_estimation — enable the next-event estimators. Turning it off leaves a pure analogue solver; the difference in standard error at fixed cost is the measure of what the variance reduction buys.
  • stratify — launch photons on a jittered stratified grid over the domain top instead of independent uniform points. Removes the clustering noise from the surface irradiance maps at no cost.
  • tau_cutoff — abandon a local-estimation ray once e^{-τ} is beyond negligible (default τ = 30, i.e. 10⁻¹³).
  • max_steps — voxel-traversal step cap, a guard against a pathological near-horizontal ray in an optically empty domain.
  • view_dirs — viewing directions for the top-of-domain radiance estimator. Empty by default because each direction costs one extra ray per scattering event.
Aeolus.MonteCarloRT._dda! — Method
_dda!(tal, med, px, py, pz, ux, uy, uz, τ_target, τ_stop, w, scattered,
      score, max_steps)

March a ray through the voxel grid, exactly.

The ray starts at (px,py,pz) — wrapped into the domain laterally — and travels along the unit vector u. At each step the parametric distance to the next x, y and z voxel face is compared and the smallest taken, so every segment lies inside exactly one voxel and the optical-depth integral ∫ k_ext ds is exact.

Two things happen along the way:

  • Collision. The first point at which the accumulated optical depth reaches τ_target is recorded. The march does not stop there: it continues so that the optical depth all the way to the domain boundary is known, which is what the local estimators need.
  • Level-crossing local estimate. Whenever the ray crosses a horizontal level, w·e^{-τ} is scored into the up- or downward flux at that level — the energy that reaches the level without colliding. This is an expected-value estimator of the analogue "count the photons that cross" tally; it has the same mean and far less variance, and it makes the unscattered direct beam exact.

Returns a NamedTuple describing the collision (if any) and the ray's terminus. Lateral indices wrap, so a ray can circulate many times before exiting through the top or the ground.

Aeolus.MonteCarloRT.henyey_greenstein_phase — Method
henyey_greenstein_phase(g, μ) -> P

The Henyey-Greenstein phase function at μ = cos Θ, normalised so that ∫ P dΩ / 4π = 1 (isotropic scattering gives P ≡ 1):

\[P(μ) = \frac{1-g^2}{(1+g^2-2gμ)^{3/2}}\]

Aeolus.MonteCarloRT.mc_closure_residual — Method
mc_closure_residual(res) -> T

1 - total from mc_energy_budget. Every unit of launched weight is deposited into exactly one accumulator, so this is zero to floating-point round-off for every realisation — not merely in expectation. A non-zero value means weight is being created or destroyed somewhere in the transport loop, which is the first thing to check when a Monte-Carlo solver misbehaves.

Build a voxel grid. size is (nx, ny, nz) and spacing is (dx, dy, dz) in metres. The RegularGrid form takes the interior of an Aeolus mesh, so the radiation grid and the flow grid coincide cell for cell.

Aeolus.MonteCarloRT.mc_energy_budget — Method
mc_energy_budget(res) -> NamedTuple

The complete weight ledger as fractions of the incident flux: (albedo, atmosphere, surface, buildings, rr_loss, rr_gain, lost, total). total is the sum of every sink minus the roulette gain and must equal one to machine precision — see mc_closure_residual.

Aeolus.MonteCarloRT.mc_solve — Method
mc_solve(medium, solver; seed | rng, stream = 0, sun_dir, solar_flux = 1.0,
         backend = default_backend()) -> MCResult

Run the Monte-Carlo solve. sun_dir points toward the sun in the east-north-up frame (anything mc_sun_direction accepts, including a SolarPosition or a bare μ₀); solar_flux is the beam-normal irradiance F₀, so the horizontal irradiance at the top of the domain is F₀μ₀.

Random streams (KA-n, #305). Every photon draws from its own counter-based stream (Aeolus.Backends.counter_rng) keyed by (seed, stream, photon index): seed directly, or one UInt64 drawn from rng (so a seeded MersenneTwister still makes the solve reproducible; one of the two is required). The batches are the work items of a launch on backend, each tallying into its own buffer, merged in batch order: the result is bit-identical at every thread count. stream separates solves that share a seed (the g-points of solve_rt!). The solver can use at most nbatch threads.

Photons are launched from the top face, one per stratum of a jittered grid when solver.stratify is set. Each carries unit weight; the physical energy a unit of weight represents is F₀μ₀·A/N, which is how the tallies become absolute fluxes at the end.

Aeolus.MonteCarloRT.mc_sun_direction — Method
mc_sun_direction(x; azimuth = 0.0) -> (east, north, up)

Unit vector pointing toward the sun in the local east-north-up frame — the same convention as SolarGeometry.sun_direction_enu. Accepts

  • a 3-tuple, which is simply normalised;
  • a SolarPosition (or any object carrying elevation and azimuth fields in degrees), from which the ENU vector is built;
  • a cosine of the solar zenith angle μ₀ ∈ (0,1], with the azimuth given separately in degrees — the form the 1-D validation cases use.

Accepting SolarPosition structurally rather than by type avoids a module-load-order dependency on Phase 38 while remaining fully compatible with it.

Aeolus.MonteCarloRT.medium_from_optics — Method
medium_from_optics(domain, optics, gpt; kwargs...) -> MCMedium

Build a medium from the shared OpticalProperties contract at g-point gpt. optics may be column-shaped (nz, ngpt) — the profile is then replicated across every column — or 3-D (nx, ny, nz, ngpt).

Aeolus.MonteCarloRT.rayleigh_phase — Method
rayleigh_phase(μ) -> P

Rayleigh (molecular) phase function, P(μ) = ¾(1+μ²), with the same ∫ P dΩ / 4π = 1 normalisation. Its first moment is zero (forward and backward scattering are equally likely) and its second moment is 2/5.

Aeolus.MonteCarloRT.rotate_scatter — Method
rotate_scatter(ux, uy, uz, μ, φ) -> (vx, vy, vz)

Rotate a unit direction by a scattering angle Θ (μ = cos Θ) and an azimuth φ about the incident direction, into the laboratory frame (Cashwell & Everett 1959):

\[\begin{aligned} v_x &= \frac{\sinΘ}{\sqrt{1-u_z^2}}(u_xu_z\cosφ - u_y\sinφ) + u_xμ\\ v_y &= \frac{\sinΘ}{\sqrt{1-u_z^2}}(u_yu_z\cosφ + u_x\sinφ) + u_yμ\\ v_z &= -\sinΘ\cosφ\sqrt{1-u_z^2} + u_zμ \end{aligned}\]

The |u_z| → 1 special case matters. The formula divides by √(1-u_z²), which vanishes for a vertically travelling photon — precisely the direction every solar photon starts in when the sun is overhead, and the direction half the photons in a thick cloud end up near. The limit is simply v = (sinΘ cosφ, sinΘ sinφ, sign(u_z)·μ), applied below whenever 1-u_z² < 10⁻¹². Omitting it produces NaN or, worse, silently biased directions when the division is merely ill-conditioned.

Aeolus.MonteCarloRT.sample_free_path — Method
sample_free_path(rng, T = Float64) -> τ

Optical depth to the next collision, τ = -ln ξ with ξ uniform on (0,1]. This is the inverse CDF of the Beer-Lambert survival probability e^{-τ}, so the sample is exact for any extinction field: the heterogeneity is handled later, by marching until the accumulated optical depth reaches τ, not by re-sampling per voxel.

-log1p(-ξ) is used rather than -log(ξ) because Julia's rand returns ξ ∈ [0,1); 1-ξ ∈ (0,1] can never be zero, so the result can never be Inf.

Aeolus.MonteCarloRT.sample_henyey_greenstein — Method
sample_henyey_greenstein(rng, g) -> μ

Sample cos Θ from the Henyey-Greenstein phase function by its closed-form inverse CDF (Witt 1977):

\[μ = \frac{1}{2g}\left[1+g^2-\left(\frac{1-g^2}{1-g+2gξ}\right)^2\right]\]

The expression is 0/0 at g = 0; the |g| < 1e-6 branch uses the isotropic limit μ = 2ξ-1 instead. Forgetting that branch is the classic way to get NaN directions out of an otherwise correct solver.

Aeolus.MonteCarloRT.sample_lambertian — Method
sample_lambertian(rng, nx, ny, nz) -> (vx, vy, vz)

Sample a direction from the cosine (Lambertian) distribution about the unit normal n. The polar angle satisfies cos θ = √ξ, which is the inverse CDF of p(θ) ∝ cos θ sin θ — the distribution whose radiance is isotropic, i.e. a perfectly diffuse reflector. Sampling cos θ = ξ instead (a common slip) makes the surface too bright at grazing angles.

Aeolus.MonteCarloRT.sample_rayleigh — Method
sample_rayleigh(rng, T = Float64) -> μ

Sample cos Θ from the Rayleigh phase function. The CDF is a cubic,

\[F(μ) = \tfrac{1}{2} + \tfrac{3}{8}\left(μ + \tfrac{μ^3}{3}\right),\]

so inverting F(μ) = ξ means solving μ³ + 3μ - (8ξ-4) = 0. The discriminant is strictly positive, so Cardano's formula gives the single real root directly — no rejection sampling and no iteration:

\[a = 4ξ-2,\quad D=\sqrt{a^2+1},\quad μ = \sqrt[3]{a+D}+\sqrt[3]{a-D}\]

Aeolus.MonteCarloRT.scatter_direction — Method
scatter_direction(rng, u, g, phase) -> (vx, vy, vz)

Sample a new propagation direction: draw cos Θ from the phase function (:henyey_greenstein or :rayleigh), draw the azimuth uniformly on [0, 2π) — both phase functions are azimuthally symmetric about the incident direction — and rotate into the laboratory frame.

Aeolus.MonteCarloRT.set_solid! — Method
set_solid!(medium, predicate) -> medium

Flag every voxel whose centre (x, y, z) satisfies predicate(x, y, z) as a solid building voxel.

Aeolus.MonteCarloRT.solid_from_mask! — Method
solid_from_mask!(medium, sm::SolidMask) -> medium

Aeolus.RadiationCore.solve_rt! — Method
solve_rt!(fluxes, solver::MonteCarloSolver, optics, col::AtmosphericColumn;
          seed | rng, μ₀ = 1.0, sun_dir = nothing, sfc_albedo = 0.0,
          backend = default_backend(), kwargs...)

AbstractRTSolver interface, column form. The column's layer thicknesses col.dz must be uniform — the photon grid is a Cartesian voxel mesh — and the resulting domain is a single column with periodic lateral boundaries, which is exactly the plane-parallel problem the two-stream solver treats.

The solve is run once per g-point with a non-zero solar source and the broadband level fluxes are accumulated into fluxes, so the output is directly comparable with TwoStream.solve_sw! on the same optics. The g-point g traces the photon streams (key, g, photon) of mc_solve; the key is seed, one draw from rng, or 0 when neither is given, so every call is reproducible (KA-n, #305: there is no global random stream).

solve_rt!(fluxes, solver, optics, domain::MCDomain; seed | rng, kwargs...)

3-D form: optics is (nx, ny, nz, ngpt) (or a column profile replicated across the domain) and fluxes has shape (nx, ny, nz+1).
