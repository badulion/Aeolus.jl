Simulations

The high-level model driver. BoussinesqSimulation owns the mesh, boundary conditions, pressure solver, all prognostic fields, and all scratch buffers. One step!(sim, dt) executes the Euler-projection fractional step described in Fractional-step projection.

Aeolus.Simulations.BoussinesqSimulation — Type
BoussinesqSimulation(mesh; kwargs...)

Dry incompressible Boussinesq LES on a staggered Arakawa-C mesh with a fractional-step / pressure-projection driver.

mesh is a uniform RegularGrid or a vertically stretched StretchedGrid (#151): on the latter every operator of the core (momentum and scalar advection, molecular and SGS diffusion, the Smagorinsky length scale, buoyancy, the projection) uses the local cell thickness cell_thickness(mesh)[k] and centre spacing center_spacing(mesh)[k], and the default pressure solver is the direct stretched-z solver (see the Stretched vertical grid theory page). A :uniform StretchedGrid reproduces the RegularGrid run.

Prognostic state:

  • u @ FaceX, v @ FaceY, w @ FaceZ — velocity components.
  • p @ CellCenter — pressure.
  • θ @ CellCenter — potential temperature.

Constructor keyword arguments (each optional physics is disabled when its parameter is 0):

KeywordDefaultEffect
ν0Molecular viscosity.
θ₀0Buoyancy reference (0 → off).
g_accel9.81Gravitational acceleration.
f_coriolis0Coriolis parameter.
C_s0Smagorinsky coefficient (0 → off).
Pr_t1/3Turbulent Prandtl number.

The SGS coefficients of the last tendency evaluation are kept in sim.νt (eddy viscosity) and sim.κt (eddy diffusivity of θ and, with moisture = true, of qv), both cell-centred: with C_s ≠ 0 and no sgs keyword the built-in closure is StaticSmagorinsky(C_s), κt = νt/Prₜ; any AbstractSGSClosure passed as sgs replaces it. | sponge_α_max, sponge_z_start | 0, top | Rayleigh sponge on u, v, w above z_start. | | sponge_target | nothing (zero) | What the sponge relaxes toward (N-open-d, #262; see sponge_target). Required with an open top. | | bcs | FieldBoundaryConditions(:periodic) | Velocity BCs. | | θ_bcs | bcs | Scalar BCs (may differ from velocity). | | solver | FFTPoissonSolver(mesh) | Any AbstractPressureSolver. |

Advance with step!(sim, dt) — see step!. All buffers are allocated at construction; step! does no heap allocation.

Diagnostics: kinetic_energy, max_divergence, max_νt, mean_θ_profile.

See the Fractional-step projection theory page for the algorithm and the Quick start for a worked example.

Aeolus.Simulations.kinetic_energy — Function
kinetic_energy(sim::MassWeightedSimulation) -> Real

Density-weighted kinetic energy ½∫ρ̄(u²+v²+w²)dV over the interior. u, v use the cell density ρ̄[k], w the face density ρ̄_f[k] — each component weighted by the density at its own location. This is the energy that the anelastic system conserves in the absence of forcing; the unweighted Boussinesq kinetic_energy is not comparable in absolute terms across systems, which is why system_comparison_diagnostics also reports max_w and the θ variance.

kinetic_energy(sim) -> Float64

Volume-integrated kinetic energy ½ ∫(u² + v² + w²) dV over the interior cells. u, v, w are used as stored on their respective faces — no interpolation to a common location. This is a slight bias but the standard diagnostic for staggered LES.

Aeolus.Simulations.max_divergence — Function
max_divergence(sim::MassWeightedSimulation) -> Real

max |∇·u| — the Boussinesq constraint evaluated on a sound-proof solution. Non-zero by design; its size relative to max_anelastic_divergence is a direct measure of how far the run is from the Boussinesq limit.

max_divergence(sim) -> Float64

Maximum |∇·u| over the interior cells. Should sit at floating-point epsilon after the pressure projection (Chorin's method is exact on the discrete Laplacian).

Aeolus.Simulations.fill_state_halos! — Function
fill_state_halos!(sim, qv_bcs = passive_scalar_bcs(sim.θ_bcs)) -> sim

Fill the halos of the prognostic state of a BoussinesqSimulation — u, v, w with sim.bcs, θ with sim.θ_bcs and, with moisture, qv with qv_bcs — as one set (fill_halos!(fields::Tuple, …)): two threaded launches for the whole state (SC-b, #402), the same bits as filling the fields one after the other.

Aeolus.Simulations.max_νt — Function
max_νt(sim) -> Float64

Maximum SGS eddy viscosity νₜ over the interior. Zero when C_s = 0; otherwise responds to local strain and gives a sense of where the SGS model is most active.

Aeolus.Simulations.mean_θ_profile — Function
mean_θ_profile(sim::MassWeightedSimulation) -> Vector

Horizontal-mean potential-temperature profile ⟨θ⟩(k) over the interior, one entry per interior z-level. sim.θ stores the full θ, so this is directly comparable with sim.ref.θ̄.

mean_θ_profile(sim) -> Vector

Horizontal-mean potential-temperature profile ⟨θ⟩(k) over the interior, one entry per interior z-level. Useful for diagnosing stratification.

The sponge target (N-open-d, #262)

The Rayleigh sponge of every core relaxes u, v, w toward sim.sponge_target: zero below a lid (the Phase-7 default), the boundary data's state below an open top (required there). Theory: Near the open faces.

data = ProfileBoundaryData(u = 5.0, v = -1.5, θ = 300.0)
sim  = BoussinesqSimulation(mesh; bcs = open_boundary_conditions(mesh, data),
                            sponge_α_max = 0.05, sponge_z_start = 300.0,
                            sponge_target = sponge_target(data, mesh))
Aeolus.Simulations.sponge_target — Function
sponge_target(data, mesh) -> NamedTuple{(:u, :v, :w)}
sponge_target(; u = 0, v = 0, w = 0) -> NamedTuple{(:u, :v, :w)}

The relaxation targets of the core's Rayleigh sponge, one per velocity component, in a form the one damping kernel (_add_damping!, through add_sponge!) takes: a number, a level vector (length Nz, the interior levels of that component's own location) or a Field.

The first form evaluates boundary data on the levels of each component: a ProfileBoundaryData profile that is a number stays a number, a function of height z -> value becomes the level vector at the heights of u, v (cell centres) and w (faces), and a storage-indexed vector (length Nz + 2Hz) gives its interior levels. w defaults to zero. This is the target of an open top (N-open-d, #262): the sponge layer then relaxes the flow toward the state the boundary data imposes on the top face (the parent's, in a nest), not toward rest. A sponge that relaxes toward zero below an open top is a momentum sink against the inflow: with a free-atmosphere wind U it removes α(z)·U everywhere in the layer, and nothing imposes the wind there.

Pass the result as sponge_target to BoussinesqSimulation or a sound-proof core.

Aeolus.Simulations.add_velocity_sponge! — Function
add_velocity_sponge!(sim) -> sim

Add the core's Rayleigh sponge −α(z)(u − u_target) to the momentum tendencies sim.tu, sim.tv, sim.tw, with the profile sim.sponge_α_max, sim.sponge_z_start and the targets sim.sponge_target (sponge_target). The one sponge call of every core (step!, step_rk3!, step_imex!, step_adaptive! and the sound-proof cores): the zero target of a closed top is add_sponge!'s own default, so a closed run is unchanged bit for bit.

add_velocity_sponge!(sim, α_max, z_start, target) -> sim

The same sponge with the profile and targets given: the one implementation behind the core's built-in sponge and the Sponge component of the stage pipeline (Aeolus.Components.Sponge, ONE-a #450).

Swapping operators in step!

Two keywords of step!(sim, dt; …) replace a numerical operator without changing the algorithm (both default to the built-in one):

  • momentum_advection = f(tu, tv, tw, u, v, w) — the momentum-advection operator, e.g. (tu, tv, tw, u, v, w) -> momentum_advect_weno_z!(tu, tv, tw, u, v, w) from AdvectionSchemes;
  • sgs = closure — the subgrid-scale closure, any AbstractSGSClosure of the Era VI contract (StaticSmagorinsky, DynamicSmagorinsky, an ML.MLSGS, …) or a plain function f(νt, u, v, w) that fills νt (wrapped in a FunctionSGS, κt = νt/Prₜ). It switches the SGS terms on even with C_s = 0, and they are added where the built-in closure adds them, so StaticSmagorinsky(C_s) — or an MLSGS wrapping the Smagorinsky closure — reproduces the built-in run bit for bit. The pre-contract keyword name eddy_viscosity! = f(νt, u, v, w) is still accepted. step_rk3!, step_imex!, step_adaptive! and the sound-proof cores take the same keyword; see Era VI.

The pressure solver is chosen at construction (solver = …, any AbstractPressureSolver, e.g. MultigridPoissonSolver or MGPreconditionedCG).

Low-level stepping

Aeolus.Simulations.step_rk3! — Function
step_rk3!(sim::MassWeightedSimulation, dt; sgs = nothing, eddy_viscosity! = nothing,
          body_force! = nothing, post_predictor! = nothing, sgs_stress = :laplacian)

One Shu-Osher SSP-RK3 step of a sound-proof core, as step_rk3! of the Boussinesq core: three forward-Euler substages of dt (each the fractional step of step_anelastic! with its W-weighted projection), combined as

u⁽¹⁾ = E(uⁿ),  u⁽²⁾ = ¾ uⁿ + ¼ E(u⁽¹⁾),  uⁿ⁺¹ = ⅓ uⁿ + ⅔ E(u⁽²⁾)

for u, v, w, θ. Each combination is of fields that satisfy ∇·(W u) = 0, so the step does too, to the projection's tolerance; it is third-order accurate in time. The hooks run inside every substage, the SGS coefficients are formed from every substage state and the closure's memory is committed once, after the third substage. The pressure p is that of the last substage. Closed boundaries only: open faces (whose boundary buffers would have to be combined with the fields) are refused.

step_rk3!(sim::BoussinesqSimulation, dt; sgs = nothing, eddy_viscosity! = nothing,
          body_force! = nothing, post_predictor! = nothing,
          sgs_stress = :laplacian, workspace = rk3_workspace(sim))

Advance one Shu-Osher SSP-RK3 step with a pressure projection at each of the three substages. Third-order-accurate in time for divergence-free motion. Costs three Poisson solves per step (vs. one for step!), so use only when the extra accuracy is needed.

sgs is the SGS closure, as for step!: its coefficients are recomputed at each substage from the substage state, and its memory is committed (advance_sgs!) once, with dt, after the third substage — not three times. With moisture = true qv is combined over the substages like θ (before #177 it was not, so qv advanced by three Euler steps per call).

body_force!(sim, Δt) and post_predictor!(sim, Δt) are step!'s hooks (added for the Era VI wall-bounded cases, P54-d #174): each SSP-RK3 substage is one forward-Euler predictor + projection of length dt, and the hooks run inside every substage exactly where step! runs them (a tendency before the predictor; an implicit correction such as WallModels.apply_wall_stress! after it, before the projection). The step's net effect of a hook is the SSP-RK3 combination of its three substage effects, with weights 1/6, 1/6, 2/3.

In P56-e (#192) the same hooks carry the advection of a uniform background gradient, $-w\,∂_zΘ$, in a triply periodic box, and the immersed-boundary direct forcing of the surface-mounted cube.

Open boundaries (N-open-b, #255): each substage is a forward-Euler step projected with the boundary data of its own end time — t+Δt, t+2Δt and t+3Δt/2 for the three Shu–Osher substages — and the boundary buffers are combined with the fields' weights, so every stage's halos and boundary faces are exactly those of the combined state.

The step-start state lives in workspace (RK3Workspace, cached per simulation), so a step allocates nothing but the cache lookup (#295).

Aeolus.Simulations.RK3Workspace — Type
RK3Workspace(sim)

The step-start state uⁿ (u0, v0, w0, θ0, q0: storage-sized copies of sim.u, v, w, θ, qv) that step_rk3! combines with its later substages. Allocated once per simulation by rk3_workspace, so a step allocates nothing for it (before #295 every step copied 9 fields).

Aeolus.Simulations.rk3_workspace — Function
rk3_workspace(sim) -> RK3Workspace

The RK3Workspace of sim: allocated on first use and kept in the simulation's StepWorkspaces (KA-j, #306; before, a global weak cache).

Aeolus.Simulations.StepWorkspaces — Type
StepWorkspaces()

The per-simulation scratch of the step drivers: the step-start state of step_rk3! (RK3Workspace), the retry snapshot of step_adaptive! (TimeIntegration.StateSnapshot) and the IMEX stage state of step_imex! (TimeIntegration.IMEXWorkspace), and the StepRecord of the step cores (rec, #336). Each workspace slot is allocated on first use, on the simulation's backend (Backends.allocate), and lives as long as the simulation (rk3_workspace, state_snapshot, imex_workspace).

Before KA-j (#306) these lived in process-global WeakKeyDicts keyed by the simulation. A lookup there is not thread-safe, so stepping two domains concurrently could race on the cache; a field of the simulation cannot.

The step record and the diagnostics hook (#336)

Every step core fills the simulation's StepRecord and calls its hook at the end of each step; the run monitor attaches to it. See Per-step diagnostics.

Aeolus.Simulations.StepRecord — Type
StepRecord

What the step cores record about the steps of one simulation (#336): the cheap quantities of every step, for the diagnostics registry (RunLog.diagnostics) and the run monitor, and the diagnostics hook of the simulation. One per simulation, in its StepWorkspaces (step_record); a NestedRun has its own.

The last step (set at the end of every step):

fieldmeaning
stepssteps completed since construction
dtthe step taken (s)
limiterwhy it has this length: the binding limit of the dt pick (:advective, :diffusive, :buoyancy, :coriolis, :sgs; :growth, :dt_max, :dt_min when a clamp of adaptive_dt bound), :retry (shortened by rejected attempts), :prescribed (a dt pick was made but the step taken differs, e.g. shortened to land on an output time), :fixed (no dt pick: a fixed-step run)
retriesrejected attempts of the step

The interval since the last reset_interval! (the run monitor resets it after each diagnostics row, so a row covers the steps since the previous one, one or several):

fieldmeaning
nsteps
dt_sumthe simulated time they covered (s)
retries_sumrejected attempts
cfl_advlargest advective Courant number `dt · max_cell Σ
cfl_difflargest diffusive number dt · max(ν + νₜ, κₜ) · (Δx⁻² + Δy⁻² + Δz_min⁻²), comparable with C_diffusive (NaN likewise)
solvespressure solves
solver_iterstheir iterations, summed (solver_stats; 0 for a direct solver)
solver_residualthe largest final residual (NaN for a direct solver)
implicit_iters, implicit_residualthe implicit-diffusion CG of step_imex!: iterations summed, largest residual

Wall time (s, cumulative since construction): wall_step (inside the outermost step cores), wall_pressure (the pressure solves), wall_sgs (the SGS closure: coefficients and tendencies), wall_cfl (the CFL sweeps of cfl_diagnostics and the sound-proof adaptive_dt, also when a driver calls them between steps), wall_guard (step_adaptive!'s snapshot, post-step guard and rollbacks).

The hook (set_step_hook!) is called as hook(sim, record) at the end of every step, after the record is complete; the run monitor's attach mode installs one (Aeolus.IO.with_monitor).

Aeolus.Simulations.step_record — Function
step_record(sim) -> StepRecord or nothing

The StepRecord of sim: that of its StepWorkspaces for the dynamical cores, the run's own for a NestedRun, nothing for anything else.

step_record(run::NestedRun) -> StepRecord

The run's own StepRecord (#336), completed at the end of every parent step (a nest engine's window too): dt the parent step, limiter the parent's, retries the rejected parent steps and child substeps of the window, cfl_adv the largest advective CFL number of a child substep (at its start), the wall time of the whole window; its hook (set_step_hook!) is then called as hook(run, record). Each domain's own record is completed once per accepted step of that domain: the parent step with its retries, each child substep with the retries of its piece (a rejected attempt is not a step), and the domain's hook is called then.

Aeolus.Simulations.set_step_hook! — Function
set_step_hook!(sim, hook) -> sim

Install hook (a function hook(sim, record::StepRecord), or nothing to remove it) as the diagnostics hook of sim: every step core calls it at the end of each step of sim (#336). One hook per simulation; the run monitor installs one in attach mode. See StepRecord.

Aeolus.Simulations.step_hook — Function
step_hook(sim) -> hook or nothing

The diagnostics hook installed with set_step_hook! (nothing when none, or when sim has no StepRecord).

Aeolus.Simulations.reset_interval! — Function
reset_interval!(record::StepRecord) -> record

Start a new interval: zero the interval fields of record (n, retries_sum, solves, the iteration sums; NaN for the maxima). The run monitor calls it after each diagnostics row.

Field algebra of the step cores (KA-j, #306)

The drivers update their fields only through pointwise kernels, which give the bits of the broadcasts they replaced at every thread count (the kernel port).

Aeolus.Simulations.axpy! — Function
axpy!(y::Field, a, x::Field) -> y

y = y + a·x over the interior (interior_map!); halos untouched. The one axpy of the step cores (KA-j, #306: it replaces three copies of _axpy_interior!).

Aeolus.Simulations.pressure_from_potential! — Function
pressure_from_potential!(p::Field, φ::Field, Δt) -> p

p = φ/Δt over the interior: the pressure of a projection with potential φ (a pointwise kernel).

Aeolus.Simulations.copy_storage! — Function
copy_storage!(dst, src) -> dst

dst .= src over the whole storage (halos included); dst and src must have the same size. It is copyto! (a memcpy, which a GPU array also implements). A copy kernel measured no reliable gain (KA-j, #306; benchmarks/bench_ka_step.jl kernels): 1.01-1.07× the memcpy serially, and 1.09-1.30× at 64×64×32 and 0.82-1.58× at 128×128×64 on 4-24 threads.

Aeolus.Simulations.zero_storage! — Function
zero_storage!(f::Field) -> f

Zero every value of f, halos included: the reset of the tendencies at the start of a step. It is fill! (a memset, which a GPU array also implements). A pointwise kernel measured slower at every thread count that matters: 15.8 µs against 11.2 µs serially at 64×64×32, and 28 µs at 4 threads (KA-j, #306; benchmarks/bench_ka_step.jl kernels).
